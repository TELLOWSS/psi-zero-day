# 디펜스 전투 시청각 기획·구현

## 목표와 검증 기준

공개 디펜스에서 무엇이 발사됐고 어디에 맞았는지 연결이 약하다. 기존 단일/범위 효과음과 장비 주위 점멸을 보완해 발사 → 표적 도달 → 명중 → 위험 해소가 읽히게 한다. 사람 대신 비인간 산업 위험체에 대응한다. 원래 피해·공격 간격·장갑·슬로·탐지·경제·저장 규칙을 유지한다.

| 장비 | 발사/명중 시각 | 사운드 믹싱 | 진화 구분 |
|---|---|---|---|
| 펄스 | 황금색 꼬리와 백색 중심의 직선 펄스, 명중 파편 | 짧고 선명한 어택, 고역을 정돈한 타격 | A 다중 잔광 / B 좁고 긴 정밀광 |
| 분산 | 포물선 탄도와 중심 섬광, 실제 피격 지점마다 충격 고리 | 낮고 넓은 충격, 과한 저음 제한 | A 넓은 파동 / B 집중 코어 |
| 제어 | 청록 구속선과 앵커 모양 명중점 | 낮은 기계 체결음 | A 굵은 고정선 / B 복수 구속선 |
| 관측 | 보라색 정밀 광선과 조준 십자 | 밝고 짧은 스캔·타격 | A 넓은 스캔 링 / B 정밀 이중광 |

## 구현 계약

- 엔진이 실제 공격 표적·피격 위치·유효 피해·위험 해소 여부를 프레임 결과로 반환한다. UI에서 표적을 추측하거나 가짜 탄환 피해를 적용하지 않는다. 발사체는 즉시 판정 뒤 220~420ms 안에 보여주는 표현이며 추가 탄도 판정을 만들지 않는다.
- 2배속에서도 두 틱의 공격 결과를 모은다. 프레임 ID로 중복 재생을 막고 화면 효과를 최대 24개로 제한한다. 일시정지·재시작·탭 숨김 시 잔여 연출을 제거한다.
- 모바일에서 화면 전체 플래시·흔들림·중앙 팝업을 추가하지 않는다. 빛은 국소적으로, 최대 피해 범위는 실제 맞은 위치로 표현한다. 움직임 줄이기에서는 이동/팽창 대신 정적인 짧은 연결 표시를 쓴다.
- 기존 런타임 음원 control-resolve/area-resolve 등을 Web Audio로 디코딩해 재사용한다. 장비별 필터·피치·음량·좌우 위치를 적용하며 새 외부 음원이나 오실레이터를 최종 전투음으로 추가하지 않는다. 원본 생성 서비스/요금제 권리 검증은 기존 상업 출시 감사와 별개다.
- 사용자 입력 뒤 오디오를 활성화한다. 효과음 버스의 컴프레서, 최대 8보이스, 계열당 최소 재생 간격으로 중첩을 억제한다. 음소거·정지·탭 숨김은 예약된 음까지 끊는다. 파일 디코딩 실패 시 폭주/반복 요청 없이 조용히 종료하고 진단 이벤트를 남긴다.
- 이번 범위는 공개 `ramp-01` 전투 연출이다. G8A 현장 전용 아트·음악 계약을 임의로 교체하지 않는다. 새 래스터 자산 제작 대신 기존 최종 장비에 코드 기반 실시간 광학/입자 효과를 연결한다.

## 검증

엔진 프레임의 표적/피해/킬/범위피격과 기존 상태 결과 동일성, 일시정지/2배속, 중복 억제 및 음소거 정리를 검사한다. 실제 Chrome에서 4계열 발사/명중 표시·음원 디코딩·스케줄링·정지/음소거를 확인하고 PC/세로/가로 10웨이브 회귀를 진행한다. 자동 음향 검증은 청취 품질이나 실제 Android 성능 판정을 대체하지 않는다. 전체 테스트·typecheck·빌드 후 GitHub/Vercel에 반영한다.

## 구현 결과

- `src/domain/defense.ts`의 `DefenseCombatShot/Frame`, `src/engine/defense.ts`의 `advanceDefenseWithCombat`으로 실제 공격 결과를 반환한다. 기존 `advanceDefense/tickDefense` 호출 계약과 저장 상태는 유지한다. 프레임은 영구 이벤트 로그가 아니다.
- `src/ui/DefenseCombatFX.tsx`, `src/ui/defense-combat-fx.css`에 4계열 실시간 광선/탄도/접촉점/해소 체크 연출을 연결했다. L3A에는 추가 잔광, L3B에는 집중광을 적용했다. 실제 진화 단계에서 표시하며 공격 규칙은 원래 엔진 정의를 따른다.
- `src/app/defense-combat-mixer.ts`, `src/ui/useDefenseCombatAudio.ts`에 Web Audio 샘플 버스·필터·스테레오 패닝·컴프레서·발사/접촉 시간차를 구현했다. 총 8보이스에 예약된 접촉음도 포함한다. 계열별 75ms 최소 간격, 중복 엔진 ID 억제를 적용했다. 공개 기본판에서 기존 공통 공격음을 겹쳐 재생하지 않는다.
- 원음 3개는 기존 `public/assets/defense/audio/g8a/{control-resolve,area-resolve,control-barrier-clack}.ogg`다. 새 AI 음원 생성이나 권리 취득을 주장하지 않는다. 원음 생성/승인 이력은 기존 `content/defense/g8a-premium-audio-production.json`과 상업 출시 감사가 별도 기준이다.
- 전역 SOUND 설정을 사용한다. 동료 선택 클릭부터 음원을 준비해 첫 발사 직전에 로딩이 시작되는 것을 피한다. 무음으로 시작했더라도 다시 켤 때 사용자 클릭에서 오디오를 활성화한다. 일시정지·탭 숨김·화면 종료 시 예약 재생까지 정리한다.
- 검수 중 세로 화면에서 설정창이 원래 설정 버튼을 덮는 문제를 발견해 창 안에 명시적인 ‘현장으로 돌아가기’ 버튼을 추가했다.

## 완료 검증과 한계

전체 테스트 **2,089 통과 / 1 건너뜀**, TypeScript 및 빌드 통과. PC·세로·가로 각각 10웨이브를 정상 UI로 완주해 보호막 20·3별을 확인했다. 4계열의 실제 발사/피격/유효 피해, 브라우저 음원 디코딩/예약/정지, 모바일 음소거/다시 켜기, 레이아웃을 검증했다. 원음 첫 90ms·220ms의 RMS/피크를 분석해 무음 접두부나 클리핑이 없음을 확인했다. 증거는 [검증 기록](qa/defense-combat-av-20261015/verification.md)과 같은 폴더의 이미지/JSON/로그에 있다.

실제 휴대폰 스피커/이어폰으로 느끼는 밸런스·장시간 피로도, 저사양 Android GPU 성능, 최종 연출/청취 승인과 상업 출시 권리 확정은 남아 있다. 기존 BGM·G8A 현장 믹스 및 다른 모드의 사운드를 전부 새로 만든 작업으로 보고하지 않는다. 빌드의 기존 500kB 초과 청크 경고도 남아 있다.
