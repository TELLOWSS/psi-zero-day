## 2. 단계별 작업

### B0. 사실과 표현의 기준선

목적: 틀린 약속을 하지 않는 브랜드.

- 화면별 이름·문구·기능·준비 중 상태 목록 작성.
- 현재 프로덕션 화면을 PC·폰 세로·폰 가로·태블릿에서 동일 버전으로 기록.
- 모든 타이틀과 메뉴에서 현재 플레이 가능한 기능을 일치시킴.
- 잔액·수리·파손·피해·진화·보상·다음 맵의 실제 규칙과 문구를 매핑.
- 기존 저장 파일·음성 선택·폰트·아트·음원 출처와 승인 상태를 보존.
- 실제 완주와 다음 구역 준비 검수를 우선 해결. 강제 결과 fixture와 자연 플레이 증거를 분리.

완료 조건: 비교 가능한 기준 화면, 기능/문구 매핑, 실제 결과 흐름 증거. 브랜드 최종 승인을 의미하지 않는다.

### B1. 이름·용어·정보 위계

목적: 기존 제품의 정체성을 읽히게 만들기.

- NEW PSI / ZERO DAY / 오늘도 무사히 / 시그널 워치 계층 정리.
- 합의한 문장 사전과 현재 미지원 기능을 분리.
- 타이틀의 중심 행동과 준비 중 콘텐츠의 위계 조정.
- 장비실의 실제 효과·장착·내구도·잔액 표시 점검.
- 본문·제목·수치 폰트의 사용 위치와 긴 한글 표시 통일.
- 새로운 로고·원화 제작이 없어도 사실·위계 정리는 가능하나, 이를 Final Art 제작 완료로 계산하지 않음.

완료 조건: Director가 화면별 변경 전후를 확인, localization·기능 회귀 통과. 승인된 묶음만 PR/배포.

### B2. 공식 브랜드 자산 후보

목적: 이름을 기억되는 얼굴과 형태로 연결하기.

- 워드마크·심벌·단색 로고·작은 아이콘 후보.
- 실제 슬롯을 조사한 대표 원화와 화면별 크롭.
- 기존 주인공의 동일 얼굴·도구·직책 검수.
- 최종 후보의 원본·편집본·납품본·사용권·승인자·적용 슬롯 기록.
- 단순 화질 확대, 기존 파일 이름 변경, CSS 장식은 새 최종 자산으로 계산하지 않음.

완료 조건: 후보별 실크기·흑백·밝고 어두운 배경·모바일 검수와 Director의 파일 단위 승인. 런타임 교체는 그 다음.

### B3. 주인공·장비·소리의 연기

목적: 클릭한 기능이 아니라 장비를 사용하는 인물을 느끼게 하기.

- 발 교차 중간 동작, 실제 방향·피벗 일관성.
- 무전·보호 모듈·드론의 소켓·앞뒤 가림·독립 레이어.
- 발사/피격/흡수/소진/복구/통제 확인과 실제 상태의 동기화.
- 실제 완료 뒤의 짧은 안도 동작·음성 후보.
- 브랜드 사운드와 음악·대사·위험 경고의 우선순위.
- 혼잡·움직임 감소·음소거에서는 핵심 정보가 남는지 확인.

완료 조건: 실제 플레이에서 구분되며 손·도구·얼굴·예고를 가리지 않음. 스프라이트 한 장이나 음원 파일 존재만으로 완료 처리하지 않음.

### B4. 완성형 한 흐름

목적: 개별 화면보다 일관된 한 판을 완성하기.

- 타이틀 -> 준비 -> 장비실 -> 플레이 -> 성장 -> 대표 위험 -> 결과 -> 정비 -> 다음 준비.
- 최초 플레이, 재접속, 실패, 실제 클리어, 마지막 구역, 음성 변경, 수리 포인트 부족 경로 검수.
- 보상 한 번 지급, 내구도 마모, 수리 복구, 장착, 선택 맵, 새로고침 유지 확인.
- 실제 사용 기기에서 긴 플레이의 조작·발열·프레임·음향 피로 검수.
- 신규 사용자 소규모 검수 후 표현의 이해도와 기억되는 요소를 정리.

완료 조건: 기능·화면·소리·연출·사용자 이해도 검수 및 Director 승인. 그 전 '프리미엄 완성' 홍보 금지.

### B5. 본편과 외부 접점

- Master Design의 기존 제작 순서에 따라 본편 TBM -> FIELD와 Episode 01 완성형 샘플에 적용.
- 완성된 실제 플레이 기준으로 소개 영상·공유 이미지·크레딧 제작.
- 현재 모드/준비 중 콘텐츠를 동일하게 표시.
- 대규모 새 캠페인·계절·공법 시스템은 기존 Episode 01 게이트 전 확장하지 않음.

## 3. 제작 우선순위와 투자 방식

금액·일정은 실제 슬롯 수, 원본 보유 여부, 성우 조건, 리깅 계약을 조사한 뒤 산정한다. 아래는 금액 견적이 아니다.

| 우선순위 | 투자 대상 | 이유 | 먼저 확보할 자료 |
|---|---|---|---|
| 1 | 실제 완주·정산·정비·재시작 안정성 | 멋진 연출도 틀린 결과를 만회하지 못함 | 실제 입력 플레이 기록 |
| 2 | 대표 주인공의 작은 실크기 동작·도구 | 플레이 시간 대부분을 함께하는 얼굴 | 승인 원본, 방향/피벗/소켓 계약 |
| 3 | 작전 준비·장비실·결과의 일관성 | 한 판의 기대와 해소를 연결 | 화면/문구 기준선 |
| 4 | 실제 슬롯용 로고·대표 원화 | 기억과 외부 인지도를 연결 | 상위 브랜드·아트 방향 승인 |
| 5 | 장비별 독립 발동과 재질 음향 | 구매·성장·진화의 체감을 강화 | 실제 효과·이벤트·레이어 계약 |
| 6 | 본편 감정 연기와 외부 영상 | 완성형 경험을 확장 | Episode 01 관통 검수와 승인 자산 |

신규 배경 수량, 의상 수량, 빛 효과 수량을 프리미엄 지표로 사용하지 않는다. 같은 자산으로 더 정확하고 생생한 장면을 만드는 일이 먼저다.

## 4. 제안 검수 점수표

평가 점수는 아직 측정하지 않았다. 기술 검사 통과와 주관적 연출 평가는 분리한다.

| 평가 | 비중 제안 | 질문 |
|---|---|---|
| 인식과 일관성 | 20 | 작품명·주인공·현장·모드가 같은 게임으로 기억되는가? |
| 가독성과 조작 | 25 | 위험·잔액·수리·다음 행동이 바로 읽히는가? |
| 손맛과 인과 | 20 | 실제 발동/피해/통제와 소리·원화가 일치하는가? |
| 인물과 여운 | 15 | 주인공과 동료의 역할·감정이 남는가? |
| 정직성과 신뢰 | 20 | 광고·표시·저장 결과가 실제 기능과 일치하는가? |

권장 통과안: 가중 합계 80/100 이상, 각 항목 3/5 이상. 다만 저장·보상 오류, 조작 불가, 실제 위험 예고 가림, 승인되지 않은 인물 정체성 변경, 사용권 미확인 공개 배포는 총점과 무관하게 보류한다. 점수 임계치 자체도 Director 승인 대상이다.

## 5. 사용자 파일럿

가설 검증용 소규모 검수다. 시장 성공률이나 통계적 유효성을 주장하지 않는다.

- 제안 표본: 신규 사용자 4명, 기존 플레이어 4명. 가능하면 실제 현장 경험자와 비경험자를 함께 포함.
- 5초 첫 화면 뒤 작품명·주인공 역할·지금 가능한 행동을 확인.
- 설명 없이 시작·장비 비교·잔액 확인·수리 필요 이해·재시작을 관찰.
- 한 판 뒤 기억나는 인물·소리·장면과 불편했던 순간을 자유 응답으로 기록.
- 신호가 불명확해서 맞은 경우와 판단·조작 실패를 구분.
- 시안 선호 투표만으로 결정하지 않고 실제 행동 성공 여부를 함께 본다.
- 제안 초기 목표: 8명 중 6명 이상이 작품/역할/현재 행동을 혼동하지 않음. 최종 임계치는 파일럿 후 조정.
- 시간을 재는 항목은 기존 버전의 기준선을 먼저 기록한다. 아직 측정하지 않은 '전환율 향상'이나 '몰입도 상승'을 수치로 보고하지 않는다.

## 6. 릴리스 체크리스트

1. 승인 ID와 범위가 PR에 기록되어 있는가?
2. 실제 자산과 후보/준비 중 상태를 구분했는가?
3. 기존 코드·저장·장비 소유권·음성 선택·맵 해금을 보존했는가?
4. 전체 테스트·타입 검사·빌드가 통과했는가?
5. PC·모바일 가로/세로·태블릿, 키보드·터치, 긴 문장·움직임 감소·음소거를 검사했는가?
6. 실제 완주/실패/재준비/정비/새로고침과 fixture 검수를 구분했는가?
7. 위험 예고·주인공 손·도구·동선이 가려지지 않는가?
8. 신규 폰트·이미지·음원·음성의 출처와 공개 배포 조건이 기록됐는가?
9. Director가 실제 화면과 청취 결과를 승인했는가?
10. GitHub 검사 통과 후 운영 Vercel 커밋·파일·핵심 흐름을 확인했는가?

## 7. 다음 구현을 시작하기 위한 최소 확인

첫 확인은 아래 세 가지면 충분하다.

- 전체 방향: 현장의 온기가 있는 시네마틱 전술 게임.
- 이름/대표 인물: 기존 NEW PSI : ZERO DAY / 오늘도 무사히와 승인된 주인공 유지.
- 첫 묶음: B0+B1 사실·용어·화면 위계 정리. 새 로고·음원·캐릭터 원화는 후보 단위로 별도 검수.

이 확인 전에는 운영 타이틀·설정·캐릭터·사운드를 변경하지 않는다. 승인 후에도 로고나 문장 하나를 전체 제작 완료로 계산하지 않는다.
