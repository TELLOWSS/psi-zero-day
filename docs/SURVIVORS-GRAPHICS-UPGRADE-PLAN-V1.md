작성: 2026-10-09 / 상태: 검토·제작 제안 / 대상: 시그널 워치 중심, 장비실·메인·스토리·디펜스의 공통 표현 기준

후속 승인: 사용자가 전체 개선 진행을 요청하여 G0~G5 구현을 진행했다. 원래 제안의 제작 기준과 실제 구현·검증 결과는 구분하며, 현재 결과는 `SURVIVORS-GRAPHICS-UPGRADE-IMPLEMENTATION.md`에서 확인한다. 구현 완료가 감독의 최종 시각 Lock을 뜻하지 않는다.

## 1. 목표와 범위

목표는 **현장 사람이 자기 작업 환경을 알아보고, 주인공의 행동과 위험을 즉시 읽으며, 장비를 성장시킨 보람을 실제 화면에서 느끼는 그래픽**이다. 고해상도 이미지의 수량보다 한 화면의 시점·신체·재질·조명·움직임·UI 일관성을 우선한다.

이 문서는 신규 구현 승인이 아니라 검토 가능한 제작 계획이다. 기존 장면·캐릭터·장비·몬스터·행동을 고도화한다. 공정·계절·공법의 대규모 캠페인 확장은 기존 제작 순서 이후에 별도로 다룬다. 기존 게임 판정과 재화를 유지하며, 렌더링 품질을 이유로 사거리·공격속도·피격판정·충돌을 바꾸지 않는다. 최종 자산 후보를 제작하고 실제 플레이 시각 검수를 통과한 것만 최종 승인한다.

운영 기준선은 `6c2812df`다. 영상 피드백의 미리보기 발동·확대 및 후면 다리 보정은 로컬 수정이며 운영본과 구분하여 비교해야 한다.

## 3. 통합 아트 방향

방향은 **절제된 산업현장 사실감과 작은 화면에서 선명한 캐릭터 표현을 결합한 2.5D**로 제안한다.

- 작업복의 봉제·보호구·공구·장비는 실제 용도와 착용 위치가 읽히게 한다. 얼굴과 역할별 실루엣은 작은 화면에서도 유지한다.
- 배경은 콘크리트, 강재, 배관, 케이블, 목재, 안전 표식으로 장소를 설명한다. 바닥의 모든 얼룩을 똑같이 강조하지 않는다.
- 공통 카메라 기준과 기준 광원 1개, 보조광을 제작 계약에 기록한다. 방향 원화의 색과 명암이 회전할 때 갑자기 바뀌지 않는다.
- 안전모·조끼·바리케이드의 실제 색을 유지한다. 색 하나만으로 적·아군을 결정하지 않고 실루엣·방향·바닥 표식을 함께 사용한다.
- 유료·무료 모두 같은 제작 품질을 적용한다. 높은 등급은 부품 완성도·동작·발동 특성으로 구분한다. 화면을 많이 가리는 광량을 등급의 기준으로 삼지 않는다.

| 화면에서 전달할 의미 | 시각 언어 | 제한 |
|---|---|---|
| 즉시 회피해야 할 위험 | 경계가 선명한 주황/붉은 예고, 방향·패턴 | 장비 장식에 같은 경고 패턴을 사용하지 않는다. |
| 확보된 구역·안전한 동선 | 차분한 청록/녹색, 정돈된 바닥 선 | 소화·냉각 같은 실제 재질색과 구역 표식을 형태로 구분한다. |
| 주인공 | 작업복 고유색, 국소 밝기 차, 접촉 그림자 | 상시 큰 후광이나 전신 점멸로 주변 위험을 가리지 않는다. |
| 일반 공격·장비 발동 | 재질과 발사 방향이 있는 짧은 연출 | 공격 범위로 오해할 장식 원을 만들지 않는다. |
| 진화·희귀 성장 | 공구 구조와 작동부 변화, 짧은 강조 | 일반 장비의 기본 착용 가독성을 낮추지 않는다. |

## 4. 캐릭터와 애니메이션 제작

### 제작 방식 제안

| 방법 | 장점 | 비용·위험 | 이번 계획에서의 사용 |
|---|---|---|---|
| 방향별 마스터 원화 + 분리된 상체·팔·도구·하체·부츠 리그 | 현재 Canvas와 연결하기 쉽고, 고유 얼굴·작업복 유지 | 가려지는 부위와 방향별 팔 구조를 실제로 그려야 한다. 한 장을 과하게 늘리면 다시 왜곡된다. | 1차 기본안. 기존 원화와 실제 연속 동작을 우선 교정한다. |
| 제작용 3D 마스터 모델·리깅 후 2D 방향 렌더 | 시점·빛·신체·장비 위치를 일관되게 제작하기 좋음 | 모델·재질·리깅·렌더 제작 역량과 비용 필요. 스타일 맞춤이 중요 | 1차 샘플에서 2D 일관성이 확보되지 않으면 비교 제작하는 2차 옵션. 브라우저 전체 3D 전환과 구분한다. |

이미지 생성은 고정된 마스터의 최종 원화 후보 제작에 활용한다. 각 프레임을 독립적으로 새로 생성해 몸이 달라지는 방식은 제작 기준에서 제외한다. AI 생성 시트는 프레임 수·방향·발 접점·PPE·손가락·투명 경계·빈 셀을 사람이 실제로 검수한다.

### 캐릭터 자산 계약

캐릭터별로 신장 비율, 골반·어깨·무릎·손·발의 기준점, 주 도구, 소켓, 앞뒤 가림을 기록한다. 최종 출력의 모든 프레임은 같은 카메라와 같은 신체 기준을 사용한다. 상체와 골반은 이동을 전달하고, 무릎·발목은 접지/이탈/착지를 표현한다. 발 접지 때문에 다리를 늘리는 처리는 허용하지 않는다.

1차는 주인공 1명의 후면·후방 대각선 3방향을 선정한다. 방향당 정지 1 + 보행 8 + 달리기 4 + 회전 연결 2 + 발사/지시 3 + 피격 2 = **20개 프레임**을 목표 계약으로 한다. 총 60개이며 수치 통과가 아니라 연속 재생 검수가 필요하다. 피격은 통증을 과장하기보다 균형 회복·보호구 반응으로 표현한다. 신규 전투 능력은 추가하지 않는다.

3방향 샘플을 통과한 뒤 같은 계약을 8방향으로 확대하면 1명 160개, 6명 960개다. 이는 제작량 산정용 제안이며 즉시 전량 제작하지 않는다. 공유 가능한 자세는 재사용 여부와 실제 고유 원화 수를 따로 기록한다. 분사·궁극기·장비 점검의 별도 연기는 기본 샘플 승인 후 현재 행동에 한해 증설한다.

### 동작 검수

- 정지→걷기→달리기→멈춤→180도 회전→후면 보행→후진을 연속 확인한다.
- 앞을 보는 방향과 이동 방향이 다를 때 전진 보행을 억지로 늘리지 않고 후진/옆걸음 자세를 선택한다. 판정 방향과 시각 방향의 차이를 숨기지 않는다.
- 전 방향에서 머리·골반 높이, 양발 길이, 안전모·작업복 색, 주 도구가 유지된다.
- 접지 추적은 도달 가능한 범위에서만 적용한다. 원화 자체가 불일치하면 런타임 메시 변형으로 감추지 않고 원화를 교정한다.
- 이동·공격은 30/60/120Hz의 시간 기준으로 검증한다. 프레임 수를 시간으로 가정하지 않는다.

## 5. 착용 장비와 미리보기

장비를 가슴/어깨/허리/손목/등/발/손 소켓으로 정의하고, 각 방향의 손·도구 접촉점을 원화에 함께 표시한다. 유료 16종(통신 3종 포함), 일반 하드웨어 16종을 현재 제작 범위로 삼되 지원 아이템과 진화 슬롯의 매핑은 기존 정의를 따로 검수한다.

- 같은 몸에 여러 장비가 붙을 때 공간 충돌을 먼저 해결한다. 작업복은 남기고 보호대만 덧씌우며, 손목 장비는 손을 가리지 않는다.
- 손에 쥐는 도구는 엄지·손바닥 앞뒤 가림을 별도로 제공한다. 역할별 원래 도구와 새 장비가 경쟁하면 제작 계약에 착용 위치와 가림 순서를 명시한다.
- 등 장비는 끈·거치대·케이블로 부착 이유를 보여준다. 드론 출격·복귀의 접힌 상태/빈 거치대/연결 상태를 구분한다.
- 일반 Lv1~5는 작동부·노즐·보호 패널·부품 연결의 작은 변화로 표현한다. 진화는 실제 취득 상태에 맞춰 구조와 발사 특성이 변한다. 등급 표시를 위해 모든 단계에서 더 큰 광원을 붙이지 않는다.
- 미리보기는 정면/옆/뒤, 이동/회전, 발동, 한 순간 확인을 사용한다. 동일한 몸·장비·VFX를 실제 게임과 공유하고 검사 전용 그림으로 대체하지 않는다.
- 장비 이름, 착용 부위, 눈에 보이는 변화, 시너지 대상, 실제 효과 확인 동선을 가까이 배치한다. 자세 재생과 실제 시험장 효과를 명확하게 표시한다.

현재는 3개 제작 시점을 8개 방향에 배치한다. 1차에서는 **주인공 1명×시너지 장비 6종×뒤/옆**을 먼저 검수한다. 이 단계에서 실제 회전 품질이 부족한 장비만 8방향 전용 시점을 증설한다. 전 품목에 무조건 8방향을 만들기 전에 큰 수익이 있는 품목을 선정한다.

## 6. 산업현장 배경·빛·공간

기존 STAGE 42 전기공정 화면을 대표 샘플로 삼는다. 새로운 공정 맵을 대량 생성하는 대신 한 스테이지의 공간 완성도를 닫는다.

제작 레이어는 바닥/고정 자재/판정에 연결된 장애물/높은 구조물/동적 장비/인물/효과/정보로 나눈다. 배경 그림에 이미 들어 있는 구조물을 다시 개별 물체로 그리지 않도록 자산 목록을 정리한다.

- 바닥: 줄눈·마모·분진·바퀴 자국으로 산업현장을 설명한다. 이동·전투 구역은 대비를 낮추고 위험의 경계가 드러나게 한다.
- 구조물: 높이와 실제 가림을 구분한다. 플레이어가 큰 물체 뒤에 있을 때 주인공의 위치와 위험 예고는 식별되게 한다.
- 조명: 주 광원 방향과 접촉 그림자를 통일한다. 원화에 들어간 그림자와 런타임 그림자가 중복되지 않도록 그림자 레이어를 분리한다.
- 재질: 금속은 짧은 국소 반사, 콘크리트는 무광·미세 파편, 고무는 낮은 반사, 증기는 얇은 투명층으로 표현한다. 모든 재질에 같은 광택을 적용하지 않는다.
- 현장 피드백: 현재 정리/통제/정비 상태를 기존 데이터에서 읽어 바리케이드·표식·바닥 흔적으로 표시한다. 새 전투 보너스를 시각 기획에 섞지 않는다.
- 가림 규칙: 지면 위험 표식은 장소에 고정한다. 구조물의 높이와 투사 범위를 판정처럼 보이게 과장하지 않는다. 실제 충돌과 그림의 불일치는 별도 결함으로 기록한다.

## 7. 몬스터별 타격감과 해소 표현

기존 몬스터 유형을 대표 3종부터 재제작한다. 움직임은 무게·동력·정지 방식이 읽히게 한다. 처치의 의미는 현장 위험을 멈추고 통제하는 것으로 표현한다.

| 대표 위험·재질 | 공격 준비 | 타격 | 무력화·해소 | 남는 화면 정보 |
|---|---|---|---|---|
| 폭주 운반 카트/금속 | 바퀴 정렬, 경고등, 진행 방향 | 해당 접점의 짧은 금속 반응·하중 흔들림 | 제동·전원 차단·고정 | 작은 확보 표식, 즉시 제거되는 과잉 파편 |
| 가스 누출 장비 | 밸브 진동·누출 방향·위험 경계 | 압력 맥동, 국소 증기 변화 | 밸브 닫힘·누출 감쇠 | 통제 완료 표식, 잔류 증기 짧게 |
| 전기 설비 위험 | 점멸·접점 아크·절연 경고 | 짧은 전기 접점 반응 | 아크 소멸·차단 상태 전환 | 전원 상태와 확보 경계 |

종별 예고와 실제 공격의 시간은 엔진이 정한다. 연출이 강한 빛이나 입자로 공격 준비를 숨기지 않는다. 기존 피해/제동/사라짐의 의미를 변경해야 하는 경우는 그래픽 구현이 아니라 별도 게임 기획으로 분리한다.

## 8. 전투 VFX와 화면 가독성

표현 우선순위는 **위험 예고 → 주인공과 이동 경로 → 실제 공격 접점 → 적 상태 → 보상 정보 → 장비 장식 → 환경 장식**이다. 혼잡할수록 위험·주인공은 유지하고 장식 수·투명층·잔상의 비용을 줄인다.

| 이벤트 | 표현 제안 | 보호할 정보 |
|---|---|---|
| 발사 | 도구 끝에서 짧은 발광·분사 시작, 방향이 있는 궤적 | 손·장비 위치, 위험 범위 |
| 타격 | 금속/분진/증기/전기별 접점과 짧은 반응 | 피격 대상과 주인공 |
| 위험 무력화 | 한 번의 강한 정지 반응 뒤 빠른 정리 | 다음 위험과 이동 경로 |
| 궁극기 | 짧은 준비 신호→발동→잔향; 카메라 효과는 선택적 | 플레이어 조작과 보스 예고 |
| 진화 | 작동부 변화와 간결한 상단 안내 | 전투 중앙 |
| 보급/성장 선택 | 안전하게 정지된 화면의 정돈된 이미지 카드 | 아이템·시너지·복귀 상태 |

발사 강조 60~100ms, 접점 강조 100~180ms, 잔향 180~300ms를 첫 제작 실험값으로 제안한다. 실제 무기 특성과 엔진의 발사·피격 이벤트에 맞춰 조정하며 이 값을 피해 지연이나 공격속도로 사용하지 않는다. 일반 전투에서 전 화면 백색 섬광을 기본값으로 만들지 않는다. 광량·카메라 흔들림·모션 감소 설정을 모든 새 연출에 적용한다.

수치 텍스트는 근처의 반복 타격을 묶고 치명·방어·큰 피해의 정보 계층을 구분하는 방안을 검토한다. 합산 표시는 결과 정보의 표현이며 실제 계산을 바꾸지 않는다. 중요하지 않은 이름표는 혼잡 시 줄일 수 있지만 예고 시간·공격 방향·위험 경계는 유지한다.

## 9. 모바일·그래픽 옵션·성능

초보자가 결과를 예상할 수 있는 기존 ‘부드럽게/추천/선명하게’ 흐름을 유지한다. 메뉴 설명은 “움직임이 끊길 때”, “대부분의 기기”, “여유 있는 기기에서 세부 표현”처럼 선택 결과를 설명한다. 추천 설정은 실제 측정과 히스테리시스로 자동 보정하고, 순간적인 한 프레임으로 화질을 반복 변경하지 않는다. 변경 시 짧은 안내와 직접 설정 복구를 제공한다.

| 설정 | 유지할 것 | 단계적으로 줄일 것 |
|---|---|---|
| 부드럽게 | 캐릭터 실루엣·착용 위치·위험 경계·필수 UI | 먼 그림자, 장식 반사, 환경 입자, 장식 잔상, 내부 렌더 해상도 |
| 추천 | 핵심 움직임·재질 타격·국소 접촉 그림자 | 혼잡도에 따라 주변 효과만 조절 |
| 선명하게 | 같은 플레이 정보 + 풍부한 재질·연출 | 기기 예산을 넘으면 장식부터 자동 감쇠 |

가용 화면으로 검수하며 브라우저 주소창·기기 안전영역·손가락 가림을 고려한다. 모바일 세로의 주인공 표시 높이 56~72 CSS px를 시작 검토값으로 제안한다. 시야 확보와 충돌하면 가독성 시험으로 조정한다. 조이스틱과 버튼 때문에 생기는 화면 가장자리 사각 영역에는 필수 안내를 배치하지 않는다.

성능 목표는 측정 전의 제안이다: PC·여유 있는 모바일은 60fps 지향, 저사양은 안정적인 30fps 경로를 제공한다. 선택한 프레임 목표에서 95백분위 프레임 시간, 최대 정지 구간, 초기 준비 시간, 10분 플레이 열화, 메모리 증가 추세를 기록한다. 저사양 30fps를 달성했는데 60fps 최적화 완료라고 보고하지 않는다.

정적 바닥·조명·그림자는 변경 시에만 다시 생성하고, 동일 크기 자산을 캐시한다. 화면 밖 물체의 장식 효과를 생략하며 동시 투명 합성·큰 블러·넓은 섬광을 예산에 포함한다. 단순 PNG 파일 크기와 디코딩 후 메모리를 구분한다. 2048×2048 RGBA 이미지의 비압축 픽셀 데이터는 약 16MiB이며 캔버스 복사와 브라우저 내부 자원이 더해질 수 있다. 전체 캐릭터의 모든 방향을 미리 로드하는 대신 현재 캐릭터와 다음 필요한 자산을 단계적으로 준비한다. 이 변경은 자세 전환 시 재로딩 깜박임이 없다는 기존 검수도 함께 만족해야 한다.

Canvas 최적화의 캐싱·레이어 분리와 시간 기반 애니메이션은 [MDN Canvas 최적화](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas), [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)의 기본 원칙을 근거로 한다. 렌더러 교체는 측정된 병목과 동일 장면의 비교 결과가 확보된 경우에만 다음 단계로 검토한다.

## 10. 제작 순서와 완료 게이트

| 단계 | 제작 범위 | 산출물 | 통과 기준 |
|---|---|---|---|
| G0 기준선 | 현재 운영본·로컬 수정본 구분, 같은 스테이지/장비/입력 재현 | 기준 영상, 기기·설정·버전 기록, 결함 목록 | 어떤 개선이 어느 버전인지 비교 가능 |
| G1 신체·착용 | 주인공 1명 후방 3방향 + 대표 착용 6종 | 60프레임 목표 후보, 기준점·가림 메타데이터, 연속 동작 영상 | 다리 왜곡·얼굴 변화·도구 부유·앞뒤 오류가 없고 기존 접지 제한 유지 |
| G2 공간 | 기존 STAGE 42 배경 1개 | 분리된 공간·그림자·조명 레이어, 판정 대응표 | 캐릭터·장비가 같은 현장에 서 있고 장애물·위험 표식 구분 가능 |
| G3 전투 | 대표 위험 3종 + 무기/장비 효과 3계열 | 예고·타격·무력화 연속 컷, 혼잡도 비교 | 최대 혼잡에서도 위험·주인공·이동 경로 확인 가능 |
| G4 모바일 | 세로/가로, 세 그래픽 설정 | 실기기 10분 결과, 준비·열화·정지 시간 기록 | 필요한 정보 유지, 설정 변화 안정, 목표 프레임 경로 확인 |
| G5 확장 | 승인된 제작 계약을 나머지 5명·기존 장비·장면에 적용 | 최종 후보, 원본·프롬프트·슬롯 매핑, 회귀 영상 | 공통 기준 유지, 실제 플레이 최종 시각 검수 통과 |

1차 제작의 핵심 결과물은 **한 스테이지·한 캐릭터·세 위험 유형·대표 장비 조합이 들어간 실제 플레이 완성 샘플**이다. 이를 승인하기 전에 전 캐릭터·전 맵의 일괄 원화 제작에 들어가지 않는다. 기간·금액은 담당 인력과 샘플 제작 속도를 확인한 뒤 G1 결과를 기준으로 산정한다.

## 11. 검수표와 의사결정

다음 조건을 PC, 휴대폰 세로/가로, 태블릿에서 같은 장면으로 검수한다.

- 현재 6명·8방향·전진/후진의 비율 보호, 장비 소켓, 일시정지, 저장 데이터 불변 회귀를 유지한다.
- 정지 화면뿐 아니라 5~10초 연속 동작에서 얼굴·작업복·다리·장비가 유지되는지 확인한다.
- 기본 장비/유료 6슬롯/일반 Lv1·Lv5/실제 진화 장비를 확인한다. 미보유 진화를 취득 상태로 꾸미지 않는다.
- 몬스터와 투사체가 많은 장면, 캐릭터가 장애물 뒤에 있는 장면, 저사양 설정, 모션 감소에서 위험이 읽히는지 확인한다.
- 현장 경험자에게 같은 장면을 짧게 보여주고 주인공·큰 위험·탈출 방향·장비 용도를 설명하게 한다. 초기에는 소규모 관찰 검수로 결함을 수집하며 성공률을 일반 사용자 전체의 통계로 주장하지 않는다.
- 자산 유효성/자동 테스트/성능 목표/감독 시각 승인 상태를 별도로 기록한다. 생성 파일과 단위 테스트 통과를 최종 시각 승인으로 대체하지 않는다.

이번 제안의 기본 방향은 2.5D 원화·리그 일관성 개선이며, 대표 샘플은 현재 영상의 주인공과 STAGE 42다. 감독 검토 사항은 이 아트 방향과 샘플 범위의 적합성이다. 확정 전 신규 캠페인·능력·유료 혜택·대규모 엔진 교체를 구현하지 않는다.
