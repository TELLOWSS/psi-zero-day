# 순찰 사운드 고급화 제작 명세

## 기준과 현재 상태

배경음의 오케스트라 질감과 소장 샤우팅의 존재감을 기준으로 삼되, 모든 효과음을 같은 크기와 길이로 만들지 않는다. 반복 공격은 정보 전달, 궁극기는 감정적 정점, 환경음은 장소감을 담당한다.

현재 score-v1의 7곡은 CANDIDATE이며 청취 승인 전 최종 음원으로 표기하지 않는다. 소장 음성은 Director 승인 자산이다. 일반 효과음은 합성 PCM/오실레이터 기반이다. 이번 화면 개선은 새 녹음 음원을 생성하거나 교체하지 않는다. 여기에는 음악 생성 도구가 연결되어 있지 않으며 Gemini의 실제 오디오 출력 기능은 사용 환경에서 확인해야 한다. 텍스트 응답을 음원 납품으로 취급하지 않는다.

## Gemini/외부 제작용 공통 프롬프트

수정된 실사용 버전은 [Gemini 독립 프롬프트 24개](./gemini-audio-prompts/README.md)를 우선한다. 아래 공통 블록의 WAV/스템 조건은 외부 전문 제작의 목표 납품 규격이며 Gemini 앱의 지원 보장이 아니다. Gemini 음악 만들기와 순수 Foley/TTS를 구분해 번호별로 하나씩 요청한다.

아래 블록의 대괄호를 위 표의 개별 이벤트로 바꾸어 한 번에 한 이벤트씩 제작한다. Gemini에서 파일 생성이 불가능하면 동일 명세를 오디오 제작 도구나 사운드 디자이너에 전달한다.

```text
PSI: ZERO DAY의 한국 건설현장 안전 순찰 게임을 위한 최종 후보 사운드를 제작하라.
이벤트: [이벤트 이름], 길이: [표의 길이], 변형: [개수].
실제 제작 기능이 있다면 텍스트 설명이 아닌 개별 WAV 오디오 파일을 출력하라.
첨부한 foundation/pressure 배경음과 승인된 소장 샤우팅을 질감 참고로 사용하되 음성을 복제하거나 새 대사를 만들지 마라.
건설현장 재질과 장비의 사실적 Foley를 중심으로, 이벤트 중요도에 맞는 저현·호른·팀파니의 짧은 레이어를 사용하라.
반복 효과는 짧고 또렷하며 날카로운 고역, 지속적인 서브베이스, 긴 리버브를 피하라.
궁극기와 보스/클리어 효과만 충분한 깊이와 공간감을 허용하라. 음악 전체를 효과음에 포함하지 마라.
각 변형의 어택 시간과 체감 크기를 일관되게 유지하라. 무음 패딩, 클릭, 잘린 꼬리, 클리핑이 없어야 한다.
48kHz/24bit WAV 마스터를 제출하라. 위치 기반 효과는 mono dry로, 음악과 환경음은 stereo로 제출하라.
드라이 본체와 공간/오케스트라 꼬리를 별도 스템으로 제출하라. 실사용 권리와 생성/참고 출처를 함께 명시하라.
파일명: PSI_SFX_[EVENT]_[MATERIAL]_v01_[A-D].wav. 루프는 sample-accurate 경계와 루프 구간을 제공하라.
```

## 믹스와 모바일 청취

- 음악·효과·음성·환경의 기존 4개 버스를 유지한다. 반복 공격 < 피격/경보 < 궁극기 음성 순으로 우선순위를 둔다.
- BGM 후보 시작 목표는 -18 LUFS-I, 최종 출력 true peak -1 dBTP 이하. 짧은 효과에는 LUFS-I 수치를 강제로 맞추지 않고 반복 밀도와 피크/체감 크기를 함께 평가한다. 수치는 제작 시작점이며 청취 승인값이 아니다.
- 소장 음성/경보 중에는 음악을 잠시 낮추고, 종료 후 자연스럽게 회복한다. 기존 동시 보이스 제한 24개와 효과 반복 제한을 보존한다.
- 이어폰, PC 스피커, 휴대폰 mono 스피커에서 각각 낮은/보통 음량으로 확인한다. 저음이 사라져도 공격·피격·경보 구분이 남아야 한다.
- 무음 시작은 5ms 이내, 디코딩/로딩은 순찰 전 준비, 이벤트 중 네트워크 fetch는 금지한다. 여러 변형을 순환하되 같은 소리가 연속 반복되지 않도록 한다.

## 대입 절차와 승인

1. 원본을 public/assets/survivors/sfx-v1에 별도 버전명으로 입고한다. 기존 승인 파일을 덮어쓰지 않는다.
2. 무음·길이·클리핑·루프·권리·SHA256을 검사하고 CANDIDATE로 등록한다.
3. A/B 청취 승인 후 PRODUCTION_APPROVED로 승격한다. src/app/survivors-audio-manifest.ts와 src/ui/survivors-session-audio.ts의 승인 재생 경로를 이용한다.
4. 기존 playSound 및 projectileFeedback 이벤트에 연결한다. 위치 효과는 connectSfx의 공간 처리, 재사용 버퍼, 우선순위 및 반복 제한을 유지해야 한다. 범용 playApproved만 붙여 위치 정보를 잃지 않는다.
5. 3분 최고 난이도에서 반복 피로, 음성 가림, 오디오 동시수, 일시정지·음소거·브라우저 자동재생 정책·종료 후 잔향을 검증한다.

## 화면 변경

첫 화면은 겹치는 독립 패널 대신 배경 현장 이미지 위에 모드 선택과 브랜드를 정렬했다. 순찰 준비는 작전 준비/구역/요원/설정으로 나눴다. PC 1440×900, 모바일 세로 390×844, 가로 844×390에서 진입·선택·시작 버튼과 가로 넘침을 확인한다. 실제 아트는 기존 자산을 유지하며 CSS 변경을 새 최종 아트로 계산하지 않는다.
