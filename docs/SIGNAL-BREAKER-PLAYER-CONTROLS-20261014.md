# 플레이어 우선 개선: 조작과 재도전의 일관성

2026-10-14 / `0.55.0-player-controls` / 이전 배포 `f406371f`

플레이어에게 우선 필요한 사항을 **선택한 조작과 장비를 이해하고 유지하면서 다시 도전하는 것**으로 선정했다. 이미 실패 원인별 안내·특성 성장·튜닝 선택·그래픽 연출이 있으므로, 이를 실제로 사용할 때 발생하는 불편을 먼저 고쳤다. 이는 코드와 실행에서 확인한 판단이며 사람의 선호도 조사 결과는 아니다.

## 발견한 문제와 적용

1. 수동 장비 선택은 자동 전환을 끄는데, 집중 전투 화면에서 자동 전환 버튼이 숨겨져 있었다. 전투를 멈추고 설정을 찾아야 했다. **장비 자동/장비 수동 버튼을 항상 보이게** 하고 상태·접근성 이름을 동기화했다. 자동발사 AUTO와 별도 기능이며, 한 번 눌러 자동 장비 전환을 복구한다. 일시정지 설정에서 변경해도 버튼 상태가 함께 바뀐다.
2. 즉시 재도전은 일부 선택을 유지했지만 ‘재도전 준비’는 새 작전 기본값으로 돌아가 장비·프레임을 다시 골라야 했다. **동일한 재도전 계획을 두 경로에 적용**해 스테이지·시드·장비 구성·현재 선택 장비·장비 레벨/설정·EP02 프레임·튜닝 자동 여부를 유지한다. 준비 화면에서도 실제 선택된 값으로 표시한다. 이번 시도의 튜닝·아이템·진화·시간은 기존 재시작 규칙대로 초기화한다.
3. 일시정지에서 명시적으로 재시작해도 이전 구간 체크포인트가 저장소에 남을 수 있었다. **본편 재시작 시 이전 체크포인트와 복원 후보를 제거**한다. 작전 기록·획득 특성·장비 성장은 유지하며 훈련/실험의 재시작은 이 처리를 적용하지 않는다. 저장 오류는 기존 저장 경고를 사용한다.

재도전 계획과 적용은 순수 `session-flow.js`에서 검증된 엔진 명령을 호출한다. UI가 장비 수치·시간·물리 상태를 직접 변경하지 않는다. 난이도·보상·본편 콘텐츠를 새로 만들지 않았다.

## 검증

- standalone 테스트 268개 통과. 신규 3개: 정상 재도전 계획의 설정 복원, 배열 분리·다른 스테이지/시드/에피소드/활성 전투 적용 거부, 잘못된 프레임·튜닝 플래그·선택 장비 적용 거부.
- root 테스트 2,059개 통과·1개 기존 skip. 타입 검사·빌드 통과. 총 통과 2,327개.
- 320×568, 360×640, 844×390, 1440×900에서 실제 버튼 클릭으로 수동 상태·자동 복구·재도전 준비·설정 유지 검사. 새 버튼이 화면 안에 있고 터치 높이 44px 이상임을 확인. 320px 합성 스크린샷을 열어 배치 검토.
- 실제 입력으로 첫 구간을 완료하여 체크포인트 생성 → 후보 선택 → 일시정지 → 즉시 재시작 → 같은 시드·첫 구간·체크포인트 제거 검사.
- 별도 EP02 접근 기록 fixture에서 기본 레이저 대신 전격 선택 → 진단 피격 → 재도전 준비 → 엔진과 버튼 모두 전격 유지 확인. 접근 기록/피격 fixture는 전투 승률이나 인간 플레이 증거가 아니다.
- UI/UX 8개 viewport 회귀 검사, 세 방향의 실제 입력 10작전·엔딩·보상·강화·소켓·재접속 흐름 검사 통과.
- 릴리스·서비스워커 캐시와 99개 자산 해시 갱신. 결과는 `docs/qa/signal-breaker-player-controls-20261014.json`, 로컬 스크린샷·로그는 `artifacts/player-controls-*`에 보존한다.

실제 초보 플레이어가 장비 자동과 자동발사를 명확히 구분하는지, 작은 기기에서 버튼 간 손가락 간섭이 없는지는 사람과 실제 모바일 기기에서 확인해야 한다. 유료 구매 가치나 즐거움 증가를 자동 검증만으로 확정하지 않는다.
