# 캐릭터별 접지·회전 제작과 구현

요청 범위: 6명의 정지·회전 원화, 자연스럽게 이어지는 보행, 착용 원화의 캐릭터·방향별 부착 보정. 능력치·이동 판정은 변경하지 않는다.

## 원화 프레임 계약

목표 계약은 캐릭터별 8방향 × 정지·회전 연결·보행 4자세의 48개 표시 자세다. 열 순서는 동/남동/남/남서/서/북서/북/북동이다. 생성 결과가 항상 같은 격자를 지키지 않아 기본 시트는 실제 5행 또는 6행, 보완 시트는 4열×4행으로 제작·검수했다. 윤성호는 방향 일관성을 위해 기본 원화를 편집한 8열×5행 보완 v3을 사용한다. 실제 행 경계를 `survivors-contact-frame-layout-v1.json`에 기록하여 합성한다. 캐릭터별 좌우 방향 보정도 로드 시 적용하며 인접 행의 투구·발 조각은 주 캐릭터의 연결된 불투명 영역만 추출하여 제거한다. 플레이어의 기존 8방향 무전·장비 점검 원화는 별도 두 자세로 유지한다. 기존 원본을 덮어쓰지 않는다.

## 접지와 회전 원칙

- 입력이 아니라 실제 이동 거리로 보행 위상을 결정한다. 접지 중인 발의 월드 위치를 저장하고 다음 화면에서 몸의 실제 이동량을 빼 상대 위치를 구한다. 보행 원화의 다리와 접점 사이를 변형하여 접지 중 발이 바닥을 따라 끌리지 않게 한다.
- 공중에 있는 발은 접지·통과 키 사이를 연속 보간하고 발끝을 들어 올린다. 착지 경계에서 높이를 0으로 회복하며, 상체의 반동·압축은 역변환하여 지지 발에 전달하지 않는다. 관절이 과하게 늘어날 거리에서는 현재 발 위치를 다시 잡는다. 이 제한이 있으므로 모든 상황의 픽셀 단위 완전 접지를 보장한다고 표현하지 않는다.
- 정지·재출발은 접지 기준을 이어간다. 순간이동·시뮬레이션 시간 되감기·긴 공백은 접지 정보를 재설정한다. 같은 시간은 상태를 진행하지 않는다.
- 시각적 방향은 짧은 각도 경로를 따라 초당 제한 각속도로 회전한다. 이동·공격 판정은 즉시 반응하며 시각적 회전 때문에 플레이어 입력이 지연되지 않는다. 방향 경계에서는 22.5도 연결 원화를 사용한다. 회전 중심은 골반·지지 발이며 몸 전체를 스핀시키지 않는다.
- 새 캐릭터 방향 프레임의 불투명 영역에서 부착점과 부츠 위치를 읽는다. 등/가슴/허리/손목 소켓과 앞뒤 가림은 몸과 동일한 프레임을 사용한다. 정지·보행·장비 미리보기·실제 전투가 같은 자산을 공유한다.
- 팔을 펼친 캐릭터는 전체 이미지 폭으로 장비를 배치하면 손끝 밖으로 벗어난다. 골반 중심과 몸통 폭을 별도로 읽고, 6명의 가슴·허리 높이 및 8방향 손목 위치를 각각 보정한다. 강태식은 지시하는 팔, 윤성호는 결속 도구, 이재훈은 도면을 들지 않은 손, 임준호와 안전감시자는 무전 동작을 기준으로 삼는다.
- 감소된 모션 설정과 일시정지에서는 불필요한 흔들림을 진행하지 않는다. 최초 로드 시 분석·캐시하고 매 프레임 이미지 픽셀을 읽지 않는다.

## 검증

단위 테스트: 거리 기반 보행, 30/60/120Hz 회전, 180도 최단 회전, 정지 접점 유지, 접지 교대, 되감기/순간이동 재설정, 상태 불변. 브라우저: 6명 원화의 정지·보행·회전 및 전용 착용 장비를 PC/모바일 화면에서 확인한다. 접지 오차를 숫자로 기록하고 연속 동작 화면도 검토한다. 생성 파일이나 테스트 통과 자체를 최종 시각 승인으로 계산하지 않는다.

### 2026-10-09 구현 검증 결과

- 전체 테스트 1,852개 통과, 기존 1개 건너뜀. 마지막 손목 수치 보정 후 접지·착용 계획 테스트 12개 재검증 통과. 타입 검사와 배포 빌드 통과. 게임 번들은 503.03KB로 기존 500KB 경고 기준을 조금 넘으며 빌드 실패는 아니다.
- 실제 전투를 PC 1440×900, 모바일 390×844 및 844×390에서 확인했다. 화면별 78건, 총 234건의 장비 방향별 표시 검사와 점검 드론 출격 후 빈 거치대 표시가 통과했다. 6명 각각의 실제 전투에서도 새 원화 사용을 확인했다.
- PC·모바일 미리보기에서 6명의 보행·회전, 시험장의 일반 장비 측면·후면, 기존 플레이어 점검 자세, 일시정지 화면 유지, 저장 데이터 불변, 가로 넘침과 브라우저 오류 부재를 확인했다. 장비 상세 회귀 검사도 세 화면 크기에서 통과했다.
- 접지 투영 검사 결과는 논리 좌표에서 1e-6 미만이다. 이는 렌더링 변환과 소켓 좌표의 일치 검사이며, 실제 그림의 픽셀 단위 발 미끄러짐이 없다는 증명은 아니다. 이미지와 연속 동작 영상도 별도로 검토했다.
- 기록: `artifacts/contact-final-test.log`, `artifacts/contact-final-build.log`, `artifacts/contact-browser.log`, `artifacts/contact-combat-browser.json`, `artifacts/contact-equipment-regression.log`. 연속 동작 검토 영상: `artifacts/survivors-contact-turn-review.webm`.
- 요청한 기능 구현과 자동 검증은 완료했다. 새 원화 17장의 상태는 FINAL_CANDIDATE_REVIEW를 유지한다. 감독의 실제 플레이 시각 검수 후 최종 시각 승인을 구분하여 기록한다.

## 장비 원화와 확인 동선

통신 장비는 기존 정면·옆·뒤 전용 시트를 유지한다. 나머지 유료 13종과 일반·진화·지원 하드웨어 16종은 기존 정면 원화에 측면·후면 시트 4장을 추가했다. 이들은 3개 제작 시점을 8개 게임 방향에 배치하는 방식이며, 8방향 모두 별도 그림이라고 계산하지 않는다. 뒤를 볼 때 가슴 장비는 몸에 가리고 등 장비를 앞에 표시한다. 손목 장비는 손 복원 과정에 지워지지 않도록 마지막에 다시 표시한다. 부츠 보호대는 상체가 아니라 보정된 발 접점을 따른다.

점검 드론이 실제 억제 대상에게 출격하면 접힌 드론 대신 빈 거치대를 같은 등 부착점에 표시한다. 복귀하면 접힌 드론 원화로 돌아온다. 붉은 구조 드론 거치대 원화도 같은 시트에 제작되어 있으나 새로운 출격 능력이나 보너스를 임의로 추가하지 않는다.

착용 미리보기와 일반·진화 장비 시험장 모두 정지·이동·접지·회전 확인을 선택할 수 있다. 시험장의 공격·방어·한 순간 확인은 기존 독립 엔진을 계속 사용한다. 지갑·구매·실제 전투 상태를 변경하지 않는다. 원화 프롬프트와 선택 자산 경로는 `content/design/survivors-contact-art-v1.json`에 보관한다.

## 후속 개선: 미리보기 자세 전환

정지에서 보행·회전으로 바꿀 때 자산 로딩 효과가 다시 실행되어 로딩 문구와 동작 시간 초기화가 발생하던 경로를 수정했다. 캐릭터를 선택할 때 고해상도 정지 원화와 방향 원화를 함께 준비한다. 서로 다른 이미지 객체로 부착점 등록을 분리하여 정지 원화의 착용 보정을 유지하고, 동작을 바꿀 때는 준비된 이미지 객체만 교체한다. 캐릭터 변경 중 이전 원화가 준비 완료로 표시되지 않도록 자산의 캐릭터 ID도 검사한다. 무전·장비 점검의 의도된 동작 시작은 기존대로 유지한다.

브라우저 검사는 6명 모두 일시정지 상태에서 정지→보행→회전으로 전환하여 로딩 문구가 순간적으로라도 추가되는지, 동작 시간이 초기화되는지, 새 자세가 실제로 그려지는지를 확인한다. 이 검사는 장비실과 같은 공용 렌더러를 사용하는 시험장에도 적용되는 수정의 회귀 검증이다. 결과 기록은 `artifacts/contact-pose-switch-browser.log`, `artifacts/contact-pose-switch-lab.log`, `artifacts/contact-pose-switch-test.log`, `artifacts/contact-pose-switch-build.log`에 남긴다.

후속 검증: 전체 1,852개 테스트 통과(기존 1개 건너뜀), 타입 검사·빌드 통과. PC 1440×900와 모바일 390×844에서 6명씩 자세 전환 시 로딩 문구 추가 없음, 일시정지 시간 유지, 보행·회전 원화 표시, 저장 데이터 불변을 확인했다. 변경한 TSX 파일의 공백 오류 검사도 통과했다.
