# NEW-PSI : ZERO DAY — 스토리 시네마틱 통합 기획

작성일: 2026-10-17. 범위: 기존 Episode 01의 완성. 새 장편 캠페인을 늘리지 않는다.

이 문서는 **현재 구현에 대한 점검 + 제안 원고 + 구현 명세**다. 아래의 새로운 문장·연출·모드 연동은 제안이며, 출시된 기능으로 계산하지 않는다. 이번 작업에서 실제 반영한 것은 도감 19종 보수, 동료 아트 24개 슬롯의 NEW-PSI 안전모, 도입부의 잘못된 회상 시간 표기다.

## 1. 작품의 중심

**가제: 「돌아갈 자리」 — 아무 일도 없었던 하루를, 아무도 혼자 만들지는 않았다.**

첫 출근한 안전관리자는 위험을 발견하는 법보다 어려운 일을 배운다. 확신 없는 말을 꺼낸 사람 곁에 서는 일, 멈춘 시간의 값을 누군가에게 떠넘기지 않는 일, 그리고 “이제 괜찮다”는 말에 자기 이름을 남기는 일이다.

독자가 다음 장을 넘기는 이유는 더 큰 사고가 기다려서가 아니다. 임준호가 내일도 말할 수 있을지, 강태식이 끝내 누구의 편에 설지, 내가 남긴 기록에 오늘의 사람이 남아 있을지 궁금해서다. 공정 압박은 악인의 음모가 아니라 서로 다른 사람들이 동시에 지켜야 하는 약속에서 발생한다. 인간을 보스나 소모품으로 만들지 않는다.

NEW-PSI의 방패는 보상의 문장이 아니라 반복되는 행동이다. 작은 신호를 읽고, 확인하고, 사람을 보호하며 실행으로 번역한다. AI의 눈은 미래의 사고를 확정하는 마법이 아니다. 놓친 관계를 질문하게 만드는 보조 시선이다. 최종 판단과 책임은 사람에게 남는다.

## 2. 실제 확인한 현재 상태

점검 방법: `EpisodeSession.directed()`로 네 정책(first / last / listen / schedule)을 실행하고, 제공되는 엔진 명령으로만 대화·선택·현장 결과 확인을 진행했다. 상태를 강제로 바꾸지 않았다. 결과 원본은 `docs/qa/story-integration-20261017/current-audit.json`, 재현 스크립트는 `scripts/audit-story-current.mjs`다. 이 시뮬레이션은 분기 진행 검증이며 실제 독자의 감정·읽기 시간이나 음향 감상을 입증하지 않는다.

| 대상 | 확인 | 의미 |
|---|---|---|
| 운영 모드 | directed, 이벤트 26개 / 인물 8명 / 자산 등록 102개 | 이미 존재하는 본편을 다듬는 것이 우선 |
| 네 선택 정책 | 모두 complete, 각 26/26 이벤트 완료 | 엔진을 처음부터 다시 만들 이유가 없음 |
| 첫 정책의 입력 | 80개 대화·선택 단계, 선택 13개 / 읽기·결과 67개 | 선택 목표 9–12개에 비해 읽기 부담과 리듬을 재검토할 근거 |
| 실제 메인 진입 | `src/ui/GameHub.tsx` story 버튼은 `setModePreview('story')`, ‘준비중’ 표시 | 정상 본편 시작 버튼과 동일하게 설명하면 안 됨 |
| 회상 시간 | 10:24 뒤 ‘6시간 전’, 다음 버튼은 06:27 | 산술·연속성 오류. 이번에 ‘같은 날 아침’으로 수정 |
| 운영 번역 | `EpisodeSession`은 기본 ko 뒤 story-director-ko를 덮어씀 | 기본 JSON만 읽고 사건 시간을 고치면 실제 표시와 달라짐 |
| Guard 연계 | `defense-story-bridge.ts`: ramp_signal_known → 재구성 이벤트 해금 | 유효한 기존 연결을 보존 |
| Watch 연계 | `operation-handoff-store.ts` 기록, `operation-handoff-bridge.ts` 점검 행동 추천, `OperationHandoffDossier.tsx` 실행 버튼 | 연결이 전혀 없는 것은 아님. 다만 인물·사건의 극적 회수는 추가 설계 필요 |
| 공통 레이드 | `docs/TRI-MODE-RAID-INTEGRATION-20261016.md` 및 각 모드 기록 | 관측과 실제 승리 검증을 구분하는 기존 원칙 유지 |
| 음향 | 본편 registry audio 12개 모두 브라우저 decode 성공, 길이·peak·RMS 기록. 기존 Phase D 문서는 production-v1 8/8 잠금 | 등록 수와 품질 승인 수는 다른 수치. `audio-technical.json`은 청취/최종 믹스 승인이 아님 |
| 자동 읽기 | `episode01-story-director.ts` 수동 읽기 기준 | 음악 때문에 독자의 문장을 강제로 넘기지 않음 |

### 우선 해결할 문제

1. **P0 — 진입과 약속**: 준비중 화면에서 완성된 스토리를 암시하지 않는다. 아래 10분 slice의 통과 기준을 충족한 뒤 실제 시작/이어하기 경로를 연다. 기존 저장을 검사하고 충돌 시 새 시작을 강요하지 않는다.
2. **P0 — 연속성**: 운영 번역을 기준으로 06:27→06:40→07:10→08:05→09:10→09:24→09:45→10:20→10:24의 시간·장소·작업조건 표를 고정한다. 과거 기본 번역의 07:18/07:36은 다른 운영본처럼 섞이지 않게 관리한다.
3. **P1 — 사건이 설명으로 소모됨**: ‘확인·기록·재개’의 절차적 명사만 반복하면 인물이 같은 목소리가 된다. 누구의 손이 멈췄고 누구의 말이 끊겼는지 먼저 보여준 뒤 절차가 필요해지도록 쓴다. 문장 수를 늘려 해결하지 않는다.
4. **P1 — 세 모드의 의미 회수**: 기록함의 숫자만으로는 공동 세계가 체감되지 않는다. 같은 통로·무전·시간표를 재사용하고, 전투 전후 15–30초의 인물 반응으로 내가 왜 플레이했는지 회수한다.
5. **P1 — 시네마틱과 독서 UI**: 현장을 가리는 큰 검정 패널, 한 문장마다 컷 전환, 의미 없는 얼굴 확대를 배제한다. 기존 Phase D의 TBM→FIELD 현장 맥락 기준을 따른다.
6. **P1 — 음향의 서사 기능**: 소리를 늘리기보다 신호를 들을 수 있는 공간을 만든다. 무전과 문장이 겹치는 곳의 덕킹, 장면 전환의 잔향, 중지 직후 남는 소리를 점검한다. 현재 파일을 기술적으로 읽었다는 사실만으로 좋은 소리라고 판정하지 않는다.

## 3. 세 모드와 본편을 한 세계로 묶는 규칙

본편의 현실 장면과 위험 패턴의 재구성을 구분한다. Guard/Watch/Breaker의 전투를 현장에서 사람에게 무기를 쏘는 현실 사건으로 설명하지 않는다. 기존 명칭·보스 설정·승리 조건을 존중하며, 아래 해석은 연결 연출의 제안이다.

| 모드 | 서사에서 묻는 질문 | 실제 플레이와 연결할 증거 | 본편에서 돌아오는 반응 |
|---|---|---|---|
| Watch | 무엇을 보고도 지나쳤는가? | 통제 구역, 통로 정리, 돌진 제동 등 기존 인계 기록 | 임준호가 지목한 위치를 다시 묻는 대사, 현장 점검의 우선순위 |
| Guard | 누구에게 시간을 벌어 주었는가? | 실제 방어·통제 결과와 경로 기록 | 최민석이 닫힌 동선을 보고 무전을 되풀이해 확인, 작업반의 대기 위치 변화 |
| Breaker | 어떤 연결이 압박을 증폭시켰는가? | 검증된 모드 결과·관측 정보 | 이재훈이 작업 순서를 다시 그리는 대사, 원인 연결을 묻는 보고 선택 |
| Story | 그 시간을 어떤 말과 행동으로 책임질 것인가? | 본편에서 직접 확인한 사실·관계·재개 조건 | 사람의 반응, 현장 변화, 저녁 기록, 다음 날 첫 문장 |

연결의 기본 단위는 ‘보상 점수’가 아니라 **같은 사건의 흔적**이다. 예: 램프의 밀린 자갈 → Watch의 관측 인계 → Guard에서 확보한 교차 동선 → Breaker에서 읽은 압박 연결 → 본편에서 실제 재확인. 다른 모드의 승리가 난간 복구 완료나 법적 안전 판정을 자동 확정하지 않는다.

읽기 중심 플레이어는 전투를 생략하고 본편의 점검 행동으로 같은 핵심 사실에 접근할 수 있다. 전투를 선택하면 다른 사람의 관점과 추가 반응이 열린다. 미숙한 조작 때문에 소설의 다음 장을 못 읽게 하지 않는다. 실패는 ‘재구성 미완료’로 남고, 검증된 승리로 둔갑하지 않는다.

### 데이터 계약 제안 — 아직 구현하지 않음

앱 경계의 작은 변환 함수로 기존 기록을 읽는다. engine끼리 직접 import하거나 새 백엔드를 만들지 않는다.

```ts
type StoryEvidenceReceipt = {
  schemaVersion: 1;
  sourceMode: 'watch' | 'guard' | 'breaker';
  sourceRunId: string;
  incidentId: 'ep01.ramp' | 'ep01.edge';
  observationIds: readonly string[];
  outcome: 'observed' | 'verified-clear' | 'incomplete';
  contentVersion: string;
};
```

생성은 해당 모드가 확정한 실제 결과에서만 한다. `sourceRunId + sourceMode + incidentId`로 중복 적용을 막는다. 누락·손상·미지원 버전은 빈 증거로 취급하고 본편을 막지 않는다. 저장소 실패 시 현재 세션은 유지하되 저장 실패를 정직하게 알린다. 모드 결과가 본편의 사실로 반영되려면 독자가 해당 현장 점검 명령을 수행해야 한다. 본편 상태 변경은 CoreEngine의 승인된 명령으로만 처리한다. UI는 조건 평가·보너스 지급·사실 확정을 소유하지 않는다.

기존 저장의 이벤트 ID, choice ID, effect bundle은 1차 연출 개선에서 유지한다. 새 receipt는 별도 버전 데이터로 보관한다. 임의 PSI 수식·Dark Path 임계치·사고 확률을 만들지 않는다. 나중에 본편 분기를 추가할 경우 콘텐츠 버전과 저장 migration을 별도 검증한다.

## 4. 인물의 욕망과 목소리

역할과 이름은 기존 cast를 유지한다. 숨겨진 과거·가족·사고 경력은 확정 설정으로 추가하지 않는다. 아래 내면 축은 이번 에피소드에서 말과 행동으로 검토할 제안이다.

| 인물 | 오늘 지키려는 것 | 말을 어렵게 만드는 것 | 문장과 행동의 규칙 |
|---|---|---|---|
| 플레이어 / 안전관리자 | 첫 판단에 자기 이름을 남길 자격 | 확신이 없을 때 권한부터 내세우고 싶은 마음 | 처음엔 완전한 문장, 위기에는 대상·행동·재확인 순서의 짧은 무전 |
| 강태식 / 형틀반장 | 자기 반 사람들이 기다린 시간을 헛되게 하지 않기 | 작업을 모른다는 평가와 부하의 노출 사이 | 설명보다 손으로 위치를 짚는다. 반대하더라도 인신공격하지 않는다 |
| 윤성호 / 철근반장 | 옮긴 자재가 다시 일을 방해하지 않는 흐름 | 자기 구역 밖 문제에 책임이 번지는 부담 | 수량·위치·차례로 말한다. 동의는 통로를 실제 비우는 행동으로 표현 |
| 이재훈 / 공사대리 | 오늘의 약속들이 연쇄적으로 무너지지 않기 | 늦어진 시간의 이유를 설명해야 하는 책임 | 시각과 다음 작업을 먼저 말한다. 후반에는 시간표의 빈칸을 스스로 만든다 |
| 임준호 / 신입근로자 | 틀릴 수도 있는 말을 끝까지 꺼내기 | 한마디가 모두의 일을 세웠다는 시선 | 앞말을 고치고 구체적인 물체를 지목한다. 귀여운 조수나 예언자로 소비하지 않음 |
| 최민석 / 크레인 신호수 | 말이 작업자에게 같은 뜻으로 도착하기 | 소음과 서로 다른 지시 | 무전은 짧고 반복 확인한다. 조용한 장면에서는 침묵으로 재확인을 기다림 |
| 서정민 / 감리 | ‘완료’라는 말의 근거 | 문서와 실제 상태의 틈 | 대상을 먼저 말하고 근거를 묻는다. 냉정한 판정기처럼 전 장면을 독점하지 않음 |
| 오승재 / 현장 공사팀장 | 현장 전체가 다시 돌아갈 수 있는 결정 | 책임을 개인 탓으로 정리하고 싶은 조직의 관성 | 결론을 서두르다가 멈춘다. 재개 승인에서 조건과 담당자를 다시 말하게 함 |

모든 인물을 매 장면 부르지 않는다. 장면당 주화자 2명, 관찰자 1명 이내가 기본이다. 표정·안전모 색·소품·말투로 이름 없이도 구별되게 한다. 안전모 NEW-PSI 로고는 머리 각도에 종속시키고 인물을 광고 모델처럼 정면 배치하지 않는다.

## 5. Episode 01의 장면 구성

완주 목표는 우선 **본편 읽기 25–40분**, 선택 재구성 포함 45–60분이다. 이는 제작 목표이며 실측값이 아니다. 기존 26개 이벤트는 보존하고 아래 막 단위로 연출 묶음을 만든다.

| 막 / 기존 구간 | 장면의 질문 | 시청각 장치 | 독자의 행동과 회수 |
|---|---|---|---|
| 프롤로그 10:24 | 왜 이 사람은 모두를 멈췄는가? | 정지 손, 이어지지 않은 난간, 무전 송신 해제음. 사고 장면 선소비 금지 | 정지 문장을 읽고 직접 진행. 같은 날 아침으로 |
| 1 / arrival·meet | 누구의 말을 먼저 들을까? | 발밑 자갈→게이트→TBM 보드. 소음은 시점 거리로 변화 | 현장의 첫 우선순위 선택. 선택한 사람의 짧은 반응 |
| 2 / plan·junho | 틀릴지 모르는 말을 어떻게 다룰까? | 철판 끝, 밀린 자갈, 무전 버튼 위 엄지. 선택 Watch 인계 | 관찰·위임·질문을 선택. 확인한 사실과 미확인 사항을 분리 |
| 3 / command·pump·pour | 제한된 시간에 무엇을 닫을까? | 게이트와 램프의 같은 지형, 방향지시등과 끊기는 말 | 선택 Guard 재구성 후 실제 동선 확인. 성공 숫자보다 이동 경로 변화 |
| 4 / inspection·pushback | 어디까지 멈추고 무엇을 지킬까? | 프롤로그 컷을 같은 축으로 회수. 음악은 절정 대신 감산 | 범위·노출·담당자 확정. 전면정지가 언제나 우월한 정답인 UI 금지 |
| 5 / reinspection·responsibility | 어떤 근거로 다시 시작할까? | 사진 속 난간과 현재 난간의 차이, 비어 있는 서명란 | 직접 재확인. 선택 Breaker 해석 후 원인·순서를 본편 사실과 대조 |

| 다음 날 / tease | 내일에도 같은 방식으로 들을 수 있을까? | 같은 게이트, 다른 빛과 비 예보. 어제의 작은 행동이 첫 대사로 | 새 캠페인 강제 예고 대신 다음 날의 확인 질문 하나 |

## 6. 시네마틱 문법과 모바일 독서

기본 16:9에서 현장의 통로·공정·사람을 한 화면에 읽을 수 있게 하고, 세로 화면은 같은 원화의 별도 focal crop으로 대응한다. 얼굴만 확대해 장소를 잃지 않는다. 원화 확대율·패럴랙스로 품질을 속이지 않으며, 장비·발·손신호가 잘리면 별도 크롭을 제작한다.

- 한 비트는 **현장 전체 → 구체적 물체 → 사람의 반응** 중 필요한 두 컷만 사용한다. 컷을 늘리는 대신 인물 시선의 목적을 만든다.
- 대화는 2–4행의 읽기 단위. 긴 내레이션은 독자가 숨 쉴 지점에서 나누고 자동 넘김하지 않는다. 글자 크게/읽기 속도/즉시 표시/대화 기록/재독 스킵을 제공한다.
- 선택지는 문학적인 말장난 대신 실제 행동과 당장 비워 두는 대상을 함께 적는다. 도덕 점수·정답 색상 대신 선택 후 현장과 인물의 반응을 보여준다.
- 최소 44px 터치 영역, 320px 세로 및 568px 가로에서 대사·선택지 동시 접근. 대화창과 OS safe area가 손신호·위험 대상을 가리지 않아야 한다.
- 중요한 사실은 화면 흔들림·반짝임·소리만으로 전달하지 않는다. `prefers-reduced-motion`에서는 카메라 이동과 충격을 정지 컷/짧은 디졸브로 바꾼다. 텍스트와 입력 시점은 동일하게 유지한다.
- 문장 진행·선택·일시정지를 키보드와 스크린리더로 사용 가능하게 한다. 대사 기록을 닫으면 원래 버튼에 포커스를 돌려준다.
- 로딩은 현재 장면과 다음 한 장면만 예열한다. 전 인물·전 CG·전 음원을 첫 진입에 일괄 다운로드하지 않는다. 오프라인 팩 누락 시 준비 상태를 알리고 저장을 잃지 않게 한다.

## 7. 음향 설계 — 더 크게가 아니라 더 가까이

기존 production-v1을 먼저 재사용해 장면별로 실제 청취한다. 신규 음원은 기존 production slot의 명백한 결손을 채우는 최종 후보만 제작한다. 새 임시음원이나 저품질 TTS로 전체 보이스를 덮지 않는다.

| 레이어 | 역할 | 제안 믹스 / 동작 |
|---|---|---|
| 현장 room tone | 장소와 거리를 유지 | 게이트→TBM→작업면마다 멀리 있는 장비의 거리감. 전환 때 0.4–1.2초 겹침을 청취 조정 |
| 작업 소리 | 공정 상태를 들리게 함 | 펌프·차량은 실제 장면 상태와 동기화. 작업중지 때 모든 소리를 갑자기 삭제하지 않음 |
| 무전 | 사람의 의도가 전달되는 통로 | 대사/중요 신호 중 배경을 4–8dB 감산하는 출발점. 무전 시작·해제음을 남발하지 않음 |
| 음악 | 독자가 말하지 못한 감정 | 첫 인사에 영웅 테마 금지. 10:24는 저역을 키우기보다 리듬층을 걷고 멈춘 시간을 들려줌 |
| 침묵 | 결정의 여백 | 완전 무음 대신 호흡·먼 장비·옷 마찰. 타이머로 독자에게 대답을 재촉하지 않음 |
| UI | 입력 확인 | 선택 확정음은 정답/오답 음정 차별 없이 짧게. 반복 재생과 과도한 저역 금지 |

4–8dB 등 수치는 시작값이며 실측·청취 후 확정한다. 음성/음악/효과 개별 볼륨과 전체 음소거, 자막, 중요 무전의 화자 표시를 제공한다. 첫 사용자 입력에서 오디오 컨텍스트를 해제하고 차단되면 소리 켜기 안내를 표시한다. 탭 숨김·메뉴·전투 이동 때 잔류 루프와 중복 재생을 막는다. 음소거/저장 복귀/오프라인에서도 동일한 이야기와 선택에 접근할 수 있어야 한다.

기술 게이트: 모든 참조 파일 decode 성공, 누락 0, 반복 경계 클릭 없음, 음원별 peak/무음 구간 기록, 장면 전환 중 중복 루프 없음. **품질 게이트는 이어폰·휴대폰 스피커로 실제 듣고** 대사의 가독성과 경고의 피로를 평가한다. 자동 RMS나 파일 존재 검사로 감상 승인을 대신하지 않는다.

## 8. 원고 시연 — 「버튼 위의 손」

아래는 08:05 임준호 신호 장면의 **제안 원고**다. 기존 choice ID와 효과를 보존하는 첫 개작의 톤 샘플이며 실제 콘텐츠에 아직 삽입하지 않았다. 전투는 이 장면의 말을 대신하지 않는다.

**컷 A / 경사로 쪽 현장 전경.** 먼 엔진음. 카메라는 사람보다 먼저 철판의 끝을 본다. 자갈 두어 개가 바퀴 자국 바깥으로 밀려 있다.

무전기는 아무 말도 하지 않는데, 준호의 손에서 작은 소리가 났다. 엄지가 송신 버튼의 모서리를 문지르고 있었다.

“저, 아까하고 조금 달라서요.”

나는 그가 가리킨 쪽을 봤다. 경사로에는 철판이 있었고, 철판 아래에는 어제부터 있었을 법한 흙이 있었다. 처음 온 사람에게는 무엇이나 원래 그런 것처럼 보였다.

“어디가 달라졌어요?”

준호는 곧바로 대답하지 않았다. 게이트 쪽에서 차가 짧게 경적을 울렸다. 이재훈 대리가 손목을 들어 시계를 봤다. 그 짧은 동작에 준호의 손이 조금 내려갔다.

“끝이요. 밟으면 소리가 달랐는데…… 제가 잘못 들었을 수도 있습니다.”

나는 ‘확인하겠습니다’라는 말을 떠올렸다. 무슨 일이든 맡을 수 있을 것처럼 들리는 편리한 말이었다. 그러나 지금 필요한 것은 넓은 약속이 아니었다.

**컷 B / 무전기를 쥔 손.** 배경의 엔진층을 조금 낮춘다. 버튼 클릭이나 심장박동 효과를 덧붙이지 않는다.

### 선택 — 무엇부터 함께 확인할까?

| 선택 문장 제안 | 의도 / 당장 비는 곳 | 기존 명령에 연결할 방법 |
|---|---|---|
| “준호 씨가 본 자리부터 같이 봅시다.” | 직접 관찰. 진입 순서 조정은 동료에게 맡겨야 함 | 기존 follow_junho 계열 ID·효과 보존 |
| “차량은 대기시키고, 신호수와 위치를 맞추겠습니다.” | 노출을 먼저 제한. 기다리는 작업의 압박이 커짐 | 현재 이벤트의 실제 허용 선택과 효과 확인 후 대응. 없는 선택 ID를 임의 추가하지 않음 |
| “지금 순서를 조정하고 돌아오겠습니다. 위치를 짚어 주세요.” | 즉시 공정 조정. 미확인 상태가 남는 동안 임시 통제와 담당 필요 | 기존 일정 조정 경로를 검토. 사실 확인 완료로 기록하지 않음 |

**첫 선택의 후속 문장 예시.**

준호가 한 걸음 먼저 걸었다가 멈췄다. 내게 길을 내주려는 것 같았다.

“앞에서 짚어 주세요. 저는 아직 원래 모습을 모르니까.”

그는 이번에는 손을 내리지 않았다.

철판 끝에 닿기 전, 나는 최민석에게 무전을 보냈다. 아직 원인은 말하지 않았다. 확인하지 않은 말이 무전을 타면, 듣는 쪽에서는 벌써 사실이 되기도 했다.

“경사로 확인 중입니다. 확인 끝날 때까지 차량 대기 부탁합니다. 대기 위치 다시 말씀해 주세요.”

잠깐의 잡음 뒤에 장소가 돌아왔다. 나는 같은 장소를 되풀이했다. 이제 기다리는 차가 어디 있는지 두 사람이 같은 말을 알고 있었다.

게이트 앞의 차는 그대로였다. 멈췄다고 해서 눈앞의 풍경이 크게 달라지지는 않았다. 다만 준호는 다음 말을 할 때, 내 얼굴을 먼저 살피지 않았다.

**분기 회수:** 후반 작업중지 뒤 누군가 “신입이 말해서 일이 커졌다”고 말할 때 이 장면을 떠올리게 한다. 초기 선택별로 준호가 직접 보고하는지, 신호수를 통해 말하는지, 아직 말을 망설이는지를 다르게 표현한다. 영구 낙인·호감 점수 팝업으로 단순화하지 않는다. 대사 조건은 엔진의 실제 사실과 관계 데이터에만 연결한다.

**저녁의 짧은 회수 제안:** “오늘은 아무 일도 없었네요.” 보고서 앞에서 그 말을 쓰려다 지운다. 아무 일도 없었다는 문장에는 대기한 차량의 위치도, 다시 한 번 온 무전도, 준호가 끝까지 내리지 않은 손도 들어갈 자리가 없었다.

## 9. 첫 10분 제작 패키지

## 10. 검증과 개방 기준

자동 검증: 기존 전체 테스트·타입·프로덕션 빌드, 네 directed 완주, 초기/분기/중지/재개/저녁/다음날 save-load, 오래된 저장, receipt 없음·손상·미지원·중복, 모드 간 왕복, 오프라인 자산 누락 복귀. 진입 테스트는 실제 메인 버튼에서 시작하며 내부 화면만 주입해 성공 처리하지 않는다.

브라우저 검증: 320×568, 390×844, 568×320, 844×390, 1440×900. 각 프로필에서 대사 마지막 행·모든 선택·로그·음량·일시정지·포커스·뒤로가기 확인. 감소 모션과 키보드, 음소거 및 오디오 차단 상태를 별도 확인한다. 실제 Android 장치 검수는 브라우저 에뮬레이션과 구분해 남긴다.
