# NEW PSI : ZERO DAY — SIGNAL BREAK 재설계 기준 v1

작성: 2026-10-11 / 사용자 요청에 따른 새 액션 제작선
상태: 기존 브레이커 첫 웨이브의 발생원 관찰·통제·재발 확인 연결. 모드 테스트 62개 통과. 재검증 수정본 브라우저 4화면 검수 통과. 운영 배포·최종 아트·상업 출시 검수 전.

## 1. 이번 결정과 원전의 관계

2026-09-24 COMPLETE MASTER BIBLE과 같은 날짜 ZIP의 문서 구성을 확인했다. GitHub 기본 브랜치의 AGENTS.md, MASTER-DESIGN-PRINCIPLES.md, GAMEPLAY_DOCTRINE.md, package.json 및 DefenseGame 첫 부분도 확인했다. 이는 전체 저장소와 최신 플레이를 검수했다는 뜻이 아니다.

사용자가 팡을 모티브로 한 재설계를 명시적으로 허용했다. 따라서 예전 바이블의 ‘디펜스가 본편의 중심’, ‘엔진 전체 재작성 금지’, ‘새 게임 제작 금지’는 새 액션 제작선을 막는 조건으로 적용하지 않는다. 기존 플레이를 곧바로 삭제하는 지시는 아니므로 기존 저장과 에피소드를 보존하면서 별도 브랜치에서 새 경험을 검증한다.

유지: 사고 전 위험신호, 사람 중심의 현장, 관계와 제보, 판단의 다음 날 결과, 가상 사건, 현장 성장, 오늘도 무사히라는 감정. 변경: 직접 플레이의 중심을 현장 신호 액션으로 전환. 보류: 타워디펜스의 보드·패드·웨이브 수를 새 액션의 강제 규격으로 사용하는 것.

## 2. 작품의 한 문장

**쏟아지는 위험을 막아내면서, 그 위험이 계속 생기는 원인을 읽고 끊는 현장 액션 게임.**

상위 브랜드: NEW PSI. 작품명: NEW PSI : ZERO DAY — 오늘도 무사히. SIGNAL BREAK는 액션 제작선의 가칭이며 상표 확인 전 확정 상품명으로 사용하지 않는다.

PSI = Proactive Safety Intelligence.
뜻: **사고 전 신호를 모아 다음 위험을 먼저 읽는 안전지능.**
NEW에 임의의 영문 약자를 새로 붙이지 않는다. NEW PSI는 브랜드이고 PSI의 영문 풀이는 그대로 유지한다. 가상 현장의 자체 예방 프로젝트로 표현하며 실제 제품과 가상 조직은 설명에서 구분한다.

## 3. 팡에서 출발하되 우리 규칙으로 완성한다

향수를 부르는 핵심은 한눈에 읽히는 무대, 좌우 이동, 발사 타이밍, 머리 위 위험, 작은 위험이 늘어나는 긴장, 짧은 라운드와 즉시 재도전이다. 원작의 캐릭터·풍선 세트·작살줄·세계여행 배경·음악·UI·분열 순서를 재현하지 않는다.

우리 작품의 핵심 차이는 세 가지가 동시에 작동하는 것이다.

1. **관찰:** 센서 스캔이나 동료 제보로 숨겨진 원인 연결을 드러낸다. 보고는 실시간 전투 중에 받아도 되고, 짧은 안전한 틈에 확인할 수도 있다.
2. **대응:** 현장 위험을 추상화한 파편·전류·압력·먼지 신호를 대응 장치로 제어한다. 유형마다 이동과 해결법이 다르다. 모든 적을 동일한 원형 분열체로 만들지 않는다.
3. **예방:** 원인 노드를 확인하고 적합한 조치를 취하면 재발이 멈춘다. 조치 뒤 남아 있는 신호까지 정리하고 안정 구간을 확인해야 완료된다.

원인 통제는 중간 라운드의 승리조건으로 넣는다. 모든 전투에 같은 순서를 강요하면 새 지루함이 생기므로, 단순 처리 라운드·관찰 라운드·경로 방어·복합 원인 라운드를 섞는다. 아래 독립 코드가 검증하는 범위는 ‘원인 통제형 라운드’다.

## 4. 화면과 조작

캐릭터는 현장 대응 담당자이며, 발사는 실제 근로자나 설비를 총으로 쏘는 행동이 아니다. 게임에서 위험 패턴을 표현한 신호 공간에 대응하는 장치다. 실제 분전함·가시설을 쏴서 고칠 수 있다는 인상을 주지 않도록, 현실 원인 조치 장면은 절차와 인력 대응으로 연결한다.

모바일 기본 입력: 좌우 이동 / 대응 / 관찰. 대응은 누르고 있는 동안 반복 가능. 관찰은 짧게 눌러 제한된 범위를 드러낸다. 역할 배치는 라운드 전 또는 소수의 중간 휴식 때만 실행한다. 전투 중 카드·설명 팝업·상점이 화면을 덮지 않는다.

가로: 넓은 교차 위험과 위치 선택. 세로: 더 좁은 안전 레인과 순차 위험; 가로 화면 전체를 축소해 넣지 않는다. 서로 다른 시야가 난이도 우위를 만들지 않도록 같은 위협 도달시간을 기준으로 조정한다. 휴대폰 UI·태블릿·PC는 실제 실행 후 확정한다.

기본 피격 판정과 경고 실루엣은 모든 품질 모드에서 동일하다. 낮은 품질은 입자·블룸·배경 인원·그림자만 줄인다. 충돌과 스폰은 고정 스텝, 보간은 화면 표현에만 사용한다. 숨김/복귀 때는 자동 일시정지하며 프레임 지연을 대량 스폰으로 보상하지 않는다.

## 6. 첫 3개 라운드 — 완성형 샘플의 구성

### 01 작은 소리 / 자재 통로 / 60~90초 목표

머리 위에 비대칭 금속 파편 신호가 나타난다. 큰 신호를 처리하면 가벼운 작은 파편이 남는다. 파편 질량 총합은 원래보다 늘지 않는다. 화면을 비워도 적치 원인이 열려 있으면 다시 나온다. 관찰하면 원인과 신호 사이 연결이 잠깐 보인다. 통제 조치 후 작은 파편을 모두 처리하면 다음 파동이 오지 않는다.

동료: “치운 줄 알았는데, 위에서 또 내려와요.”
주인공: “밑에서 막는 것만으론 끝나지 않네.”
첫 성공 후 작은 기록: “PSI — 사고 전 신호를 모아 다음 위험을 먼저 읽는 안전지능.” 타이틀 설명보다 먼저 플레이로 의미를 경험한다.

### 02 끊긴 응답 / 임시 전력 구역 / 75~110초 목표

전류 신호는 튀는 구체가 아니라 고정 단자를 따라 점멸하며 이동한다. 박자가 경고다. 관찰 담당자의 제보로 실제 차단 대상이 드러난다. 원인 차단과 신호 정리를 연결한다. 현실 장면에서는 자격 있는 담당자의 확인과 차단으로 표현한다. 장비를 쏴서 수리하는 연출은 사용하지 않는다.

### 03 서로 다른 길 / 양중 동선 / 100~140초 목표

바람에 흔들리는 하중 그림자와 지상 이동 신호가 서로 다른 시간에 겹친다. 플레이어가 안전 레인을 확보하며 CONTROL 역할을 배치한다. 원인 두 개 중 하나만 닫으면 다른 흐름은 계속된다. BOSS는 생명체가 아니라 복합 공정의 상태다. 첫 번째 라운드의 분열 몹 수치만 올린 스테이지로 만들지 않는다.

## 7. 확장 시 지루함을 막는 규격

매 3~4 라운드마다 새 이동 규칙 또는 해결 규칙 한 개를 소개한다. 체력·색상만 달라지면 신규 위험 유형으로 세지 않는다.

| 공정 구간 | 신호 형태 | 행동 차이 | 원인 해결 차이 |
|---|---|---|---|
| 기초·토공 | 균열편 / 이동 그림자 | 경사 방향·시간차 접근 | 레인 분리·접근 통제 |

## 8. 성장, 타격감, 상품성

장치 업그레이드는 성능만이 아니라 실루엣·가동부·작동음·명중 재질·위험 정리 반응이 달라져야 한다. 발사→명중→잔재→소멸이 하나의 연출이다. 원인 통제 성공은 잠깐의 정적 뒤 장비 감속·통제선·작업자 이동과 함께 현장이 안정되는 변화로 보상한다.

최대 성장에서도 원인 확인·회피·통제 선택이 필요하다. 무적·화면 전체 영구 정리·재발 무시 효과를 허용하지 않는다. 유료 아이템은 외형·연출·음색·추가 이야기 중심으로 설계하고, 기존 유료 장비의 성능이 있다면 별도 마이그레이션과 비교 검증 없이 제거하거나 바꾸지 않는다. 난이도 해법을 결제로 판매하는 방향은 채택하지 않는다.

짧은 재시도, 첫 성공의 선명한 손맛, 다른 역할 조합으로 원인 해결, 다음 날의 새로운 제보가 재방문 동기다. 반복 스폰 자체를 경험치·점수 무한 농장으로 보상하지 않는다.

구체적 기준:

- 원작 화면을 따라 그리거나 원작 파일·추출 코드·효과음·패턴표를 사용하지 않는다.
- ‘이름과 색만 다르다’는 변형은 납품 불가. 조작 이후의 목표·원인 해결·관계 결과·현장 성장까지 작품 전체를 비교한다.
- 원형 위험 하나가 동일 규칙으로 반복 분열하는 로스터를 작품 전체의 정체성으로 삼지 않는다.
- 외부 자산마다 제작자·원본 경로·사용 조건·상업 이용·수정·재배포 범위를 기록한다. 라이선스를 확인하지 못한 자산은 출시 목록에서 제외한다.
- AI 이미지도 유명 게임 고유 캐릭터·로고·화면을 재현하는 프롬프트로 만들지 않는다. 생성 후 유사성 검토와 사람의 편집 기록을 남긴다.
- 출시 이름·로고의 상표 조사, 관련 특허 및 부정경쟁 쟁점, 게임 등급·플랫폼·유료 판매·개인정보 관련 검토는 미완료다. 이번 저작권 조사만으로 모든 법규 적합성을 선언하지 않는다.
- 상업 출시 전 실제 완성 빌드·아트·음악·홍보 문구를 묶어서 전문가 검토한다. ‘팡 리메이크’나 제휴·공식 후속작처럼 오해시키는 표현은 쓰지 않는다.

## 10. 새 코드의 범위와 다음 작업

독립 TypeScript 규칙 파일은 관찰 전 원인 차단 금지, 대응 유형 일치, 재발 스폰 상한, 질량 보존 분열, 안정 시간 확인, 입력 상태 불변성을 검증한다. 실제 피격·이동·조작·미술·사운드·저장 연결은 포함하지 않는다. 단위 검증 통과는 재미나 모바일 성능 통과와 다르다.

구현 순서:
1. 기존 액션/신호 모드의 실제 진입점과 저장 형식을 최신 코드에서 확인.
2. 새 규칙을 기존 엔진에 어댑터로 연결하고 첫 라운드 직접 플레이 구현.
3. 기존 UI에 이동·대응·관찰과 원인 통제 피드백 결합.
4. 원인 해결 전후 현장 변화, 독창적인 위험 3종, 장치 성장 1단계 완성.
5. 모바일 세로·가로·태블릿 실제 플레이와 저장 복구·성능 검증.
6. 재미 검증을 통과하면 3라운드 샘플 완성, 이후 캠페인 확장.

품질 통과 조건: 설명 없이 30초 안에 조작 이해; 첫 라운드에서 화면만 비우는 것과 원인 해결의 차이를 인지; 안전 레인과 피격 위치가 낮은 품질에서도 동일; 재도전 때 바꾸고 싶은 판단이 한 개 이상; 원작과 전체 화면·위험 로스터·진행·사운드 조합이 구별됨.

권장 작업 모델 수준: 일반 코드 연결과 회귀는 기본 모델의 중간 추론, 세계관·상업화 유사성·장르 통합 검토만 높은 추론. 별도 외부 모델이나 병렬 에이전트로 넘기지 않는다.


## 11. 첫 웨이브 구현 업데이트

초기 파일 검색이 브레이커 경로를 찾지 못했다. 재귀 경로 확인으로 public/signal-breaker-dev/index.html 및 src/engine.js, src/app.js가 이미 메인 메뉴에 연결된 기존 독립 모드임을 확인했다. 새 게임을 별도로 양산하지 않고 이 구현을 사용한다.

적용 범위는 캠페인 CH-01의 첫 웨이브다. 화면의 Ψ 관찰 버튼을 누르면 반복 신호의 발생원이 드러나고, 같은 버튼이 구역 통제 요청으로 바뀐다. 키보드 C도 지원하며 기존 키 설정이 C를 사용하는 경우 버튼으로 조작한다. 요청 후 잔여 신호를 회수하고 2초 동안 재발이 없어야 장비 선택과 다음 웨이브로 이어진다. 소스 상태와 연결선은 장식 품질과 관계없이 렌더링한다.

발생원을 방치하면 8초 뒤 첫 재발, 이후 6초 간격으로 신호가 나타난다. 재발 신호는 최대 2개다. 이를 처리해도 점수·처리량·포획량·콤보·반사 성장 보너스를 늘리지 않는다. 기존 계획 신호의 질량과 보상 계약은 유지한다. 원인 통제 후 남은 신호가 자동 삭제되지는 않는다.

기존 5웨이브·6장비·LAB·구형 체크포인트는 유지한다. 새 체크포인트는 causal 플래그를 보존하며 구형 저장에서 해당 필드가 없으면 기존 규칙으로 복구한다. 체크포인트는 기존과 같이 웨이브 사이에 저장하므로 첫 웨이브 도중 복구는 이번 범위에 포함하지 않는다.
