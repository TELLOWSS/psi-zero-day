# STAGE 02 전경 실제 게임 연결 · 2026-10-19

사용자가 새 전경 적용 질문에 ‘현재 후보를 게임에 적용’이라고 명시적으로 답했다. 해당 범위의 승인 기록은 `docs/art-source/watch-foreground-20261019/approval.json`에 보존했다. 원화 색과 가림 보호를 추가 수정하지 않고, 검토한 바로 그 알파 PNG를 등록했다.

## 연결

- `content/design/survivors-stage-foreground-v1.json`에 STAGE 02 하단 흙막이 1종의 원화·알파 경로, 월드 좌표와 승인 ID를 기록했다.
- `survivors-stage-mattes.ts`의 승인 목록에서 해당 파일을 읽는다. 정상 게임의 기존 스테이지 선택 → 원화·알파 비동기 로드 → 원화 색/조명에 맞춘 텍스처 준비 → Y 정렬 → 인물/위험 경고 가림 보호 경로에 연결했다.
- 캔버스에 승인·로딩·그리기 전경 수를 구분해 남겨, 등록만 된 경우와 실제 그려진 경우를 혼동하지 않도록 했다.
- 나머지 49개 스테이지에는 마스크를 만들거나 임의로 배정하지 않았다. 기존 해금, 충돌, 이동, 대미지, 보상과 저장 규칙은 변경하지 않았다.
- 비교 검수 화면도 후보 사본 대신 실제 게임의 승인 목록을 읽도록 바꾸고 ‘사용자 승인 적용’ 상태를 표시한다.

승인된 이미지의 바이트는 그대로다. 생성된 RGB는 사용하지 않으며 알파만 기존 원화에 적용한다. 앞 단계에서 확인한 원화 색 오차 최대 1/255, 인물 보호 55%와 경고 보호 25% 정책을 유지한다.

## 검증

승인 범위와 실제 등록 자산 일치, PNG RGBA 형식·크기·월드 경계, 다른 49개 미등록, 잘못된 원화·좌표·승인·외부 경로 거부, 인물·경고 보호를 검사한다. 관련 5검사는 통과했다. 전체 검사·빌드·브라우저 결과는 종료 후 아래에 기록한다.

첫 타입 검사 시 시스템 메모리 부족으로 네이티브 컴파일러가 중단됐다. 이전 작업의 개발 서버와 검수 탭을 닫고, 검증 프로세스에 한해 `GOMAXPROCS=2`를 사용해 타입 검사를 통과했다. 전체 테스트는 워커 2개 실행 중 자식 프로세스 메모리 오류가 있어 성공으로 계산하지 않았으며, 개발 서버를 중지하고 워커 1개로 다시 실행했다. 재실행 종료 코드 0, 2,355개 통과·실패 0·기존 건너뛰기 1개를 확인했다. 검사를 제외하거나 제품의 제한을 낮추지 않았다. 메모리 부족 중 브라우저의 본 게임 페이지도 중단되어, 이후 검증 결과와 구별해 기록한다.

최종 `npm run build`도 종료 코드 0으로 통과했다. 전체 테스트와 빌드의 필수 사전 검사를 유지한 상태에서 워커 수만 1개로 조정했다. 활성화 후 새 브라우저 검수 탭은 webview 연결 시간 초과로 열리지 않았다. 이전 후보의 실제 원화/인물/경고 렌더 검수 증거와 이번 등록 검사 결과를 구별하며 STAGE 02 전체 실전 플레이를 완료했다고 주장하지 않는다.

보존 증거: `docs/qa/watch-graphics-20261019/verification.json`, 전체 빌드·타입 로그, 이전 50단계 렌더 검사와 원화 접점/가림 보호 화면. 로컬 전체 테스트 원본은 `artifacts/watch-foreground-activation-20261019/verified-tests.json`이다.
