## A. 한 줄 제작 선언

> **현장의 소리는 끊기지 않는다. 음악은 위험의 의미를 바꾸고, 사람의 말은 내 선택 때문에 달라지며, 마지막에는 ‘오늘도 무사히’가 점수보다 긴 감정으로 남는다.**

목표는 무조건 웅장한 음악이나 모든 대사를 영화화하는 것이 아니다. **한 번의 클릭이 현장·인물·음악에 남는 흔적**을 만들고, 26개 사건을 “다음 버튼 26개”가 아닌 **원인–발견–압박–결정–파장–기억**의 연속으로 느끼게 한다. 중요한 순간만 강조하고 나머지는 여백을 둔다. 영화 감상성과 플레이어의 선택 주권을 동시에 지킨다.

### B-1. 현재 자산: 버릴 것이 아니라 재편집할 것

현 저장소의 생산 규격은 **12개 코어 음향(환경/효과 8 + 감독 검수 성우 4)**이며, 26개 이벤트에 소리의 연결점을 정의하고 있다. 이미 확보된 `gate_queue`, `workface_pressure`, `concrete_pour`, `office_report_roomtone`, `home_night`는 **연속 환경음 레이어**로, `radio_burst`, `pump_engine_boom`, `stopwork_silence_drop`은 **상황별 단발/이벤트 레이어**로 용도를 재분류한다. 네 음성 마스터(`강태식`, `임준호`, `이재훈`, `오승재`)는 재녹음 없이 우선 보존한다. 음질과 완성도는 실청 및 모바일 디바이스 기준으로 별도 승인한다.

## C. 연출 철학 — 관객을 설명으로 설득하지 않는다

1. **감정의 주인공은 건물이 아니라 사람**: 장비 작동을 먼저 들려주되, 결국 그 소리가 누군가의 손·목소리·귀가에 미치는 의미로 돌아온다.
2. **반복의 의미를 뒤집는다**: 06:40에 들린 TBM의 짧은 금속 타격음이 14:20에는 바뀐 작업조건의 불편한 기억으로, 마지막에는 다음 보고를 가능케 한 신뢰의 신호로 들리게 한다.
3. **압박은 악역 음악이 아니다**: 이재훈의 공정 일정 압박은 실제 업무의 리듬과 시계로 표현한다. 악당용 저음·공포 장치로 사람이 악역화되지 않도록 한다.
4. **침묵도 연주한다**: STOP WORK 순간 150–300ms의 **의도적인 사운드 다운**을 사용하되, 오류로 생긴 무음은 연출로 미화하지 않는다.
5. **정보는 소리에서도 들리지만 소리에만 있지 않다**: 필수 위험정보는 자막·시각 신호로도 제공한다.
6. **일방적 영상이 아니라 선택의 영화**: 중요한 분기마다 음악·무전·인물 반응이 달라진다. 선택은 자동으로 진행시키지 않는다.
7. **눈물 강요 금지**: 과장된 사망 예고·신파 대신 퇴근 후의 작은 안도, 다음 날 먼저 입을 여는 동료 등 현실적인 감동을 목표로 한다.

## D. 극 구조 재편집 — 26개 이벤트를 6막처럼 느끼게 하기

스토리 사건의 ID/순서는 유지하되 **컷의 길이와 강도를 재편성**한다. 아래 체험 시간은 *제작 목표 범위*이며 실제 플레이 계측값이 아니다. 음성 재생·자막 읽기·선택 숙고 시간에 따라 달라진다.

| 막 | 게임 내 시간·대표 이벤트 | 관객이 느껴야 할 것 | 장면 편집/사운드 원칙 |
|---|---|---|---|
| 프롤로그 | 10:24 STOP WORK 순간을 선공개 후 06:27로 되감기 | “왜 멈췄지?” | 위험음의 순간 감소 → 짧은 무전 → 미완성 단서 → **현장 소리로 J-cut** |
| I. 사람의 소리 | 06:27–07:10 도착·TBM·첫 배치 | 낯선 현장, 서로 다른 리듬 | 시계/금속/신발·무전, 절제된 피아노 2~3음 모티프, 설명 문구 최소화 |
| II. 작은 어긋남 | 08:05–09:24 임준호 제보·7분 압박·펌프 도착 | 놓치면 안 될 조각들 | 익숙한 현장 리듬에서 미세한 박자 누락, 임준호 말 전 음악 후퇴, 펌프 음으로 **L-cut** |
| III. 멈추는 선택 | 09:45–11:15 타설·이상·10:20 점검·재확인 | 행동의 무게와 후폭풍 | 호스·바퀴·발소리의 접근, 결단 순간 150–300ms 정적, 재개 시 정상 상태 변화가 들림 |
| IV. 보이지 않는 비용 | 13:30–15:38 책임·기록·TBM 불일치·재개·작업중지 이후 | 기술적 조치 뒤에도 남는 사람 | 실내 공조/종이/전화 무음, 감정 선율 간소화, **전에 들었던 동일 무전의 의미 변화** |
| V. 남겨야 하는 말 | 16:05–17:08 지시 전파·기록 압박·사실 검증 | 무엇을 남길지 책임지는 과정 | 문장을 넘길수록 소리의 대역이 조금 좁아지는 연출, 최종 보고에서는 또렷한 목소리/키보드 소리만 |
| 에필로그/브리지 | 17:18 저녁 → DAY02 06:52 | 살아 돌아온 하루, 내일 먼저 누군가 말할 가능성 | 현장 소음이 집의 작은 잔향으로 이어짐 → 최초 피아노 모티프가 **장조/개방된 화성**으로 귀환 → DAY02 다음 신호 |

**스토리 진행 리듬 권고:** 도입 30~50초 안에 인물·현장·미해결 질문을 제시. 평상시 컷은 2~6초, 짧은 인물 비트는 8~20초, 핵심 장면은 30~60초 규모로 설계하되 실제 음성 길이와 사용자의 읽기 속도·행동에 맞춰 조절한다. 설명만 있는 장면은 두 컷 연속으로 반복하지 않는다. 중요한 선택 전에는 0.7~1.5초 숨을 둘 수 있으나 **사용자 조작을 억지로 막는 대기 애니메이션**은 금지한다.

### D-1. 짧은 예시 시나리오: 08:05 임준호의 말

- **전 장면의 끝:** 펌프와 차량의 먼 엔진음이 남아 있고, 카메라가 경사로 쪽을 바라보기 *0.6초 전* 작은 철판 덜컹임이 먼저 들어온다(J-cut).
- **실제 화면:** 임준호가 무전을 들었다 놓는다. 1초 동안 음악의 저음을 빼고 현장음만 유지한다.
- **음성:** “저… 말씀드릴 게 있는데, 아닐 수도 있습니다.” 기존 승인 음성 사용. 배경음은 **120–180ms에 걸쳐 -6~-10dB 후보 범위로 완만하게 낮춘다**(실청 검증 전제).
- **선택 전:** 근로자의 손, 차량 바퀴 자국, 경사로 연결부를 각 1.5초 안팎으로 보여준다. 위험을 확정적인 미래 사고로 단정하지 않는다.
- **결정:** 사용자는 확인 방법을 고른다. 탭 입력은 즉시 반응하되 화면 전환의 현장음은 0.8~1.5초 잇는다.
- **후폭풍:** 나중에 같은 철판 소리가 나올 때 ‘그때 그냥 지나갔던 말’이 떠오른다. 선택 결과에 따라 인물의 짧은 반응과 SFX 잔향이 변한다.

### E-2. 필수 기술 규칙

- **오디오 객체 생명주기는 EP01 플레이 전체에 유지**: 장면 React 하위 UI가 재마운트돼도 Mixer, AudioContext, 프리로드 버퍼를 즉시 폐기하지 않는다. 게임에서 홈으로 완전히 이탈할 때만 명시적인 fade-out 후 정리한다.
- **Web Audio 우선, HTMLAudio fallback**: 디코드된 짧은 cue/loop는 Web Audio `AudioBufferSourceNode`+`GainNode`로 예약. 긴 BGM 스트림은 `HTMLAudioElement`+`MediaElementAudioSourceNode`를 사용할 수 있으나 단일 요소/컨텍스트 재사용, CORS 및 모바일 리소스 한계 고려. `AudioBufferSourceNode`는 재생 후 재사용 불가하므로 새 source만 만들고 버퍼는 캐시한다.
- **자산 사전 로딩:** 현재 장면 종료 예상 전에 *다음 1~2 장면*의 score/bed/voice/SFX를 요청하고 decode readiness를 확인한다. 디코드 대기 시 현재 환경음을 재생하며, 로딩 오류를 오류 코드로 수집한다.
- **동일 배경 자산이면 재시작 금지:** `gate_queue → gate_queue`, `workface_pressure → workface_pressure`이면 `currentTime`과 음장을 유지한다. `asset_id`가 달라져도 공통 WORLD 레이어는 남는다.
- **전환 시간 목표(제안값):** 장소 bed 800~1800ms, BGM 1500~3500ms, 1회 효과음 tail 200~800ms, 음성 duck attack 120~180ms / release 750~1400ms. 클립 길이·리듬·기기 별 실청 QA로 조절한다.
- **클릭과 오디오 분리:** 다음 클릭은 **텍스트/카메라 이동**을 일으키지만 환경음의 끊김 명령이 되지 않는다. VO가 다음 클릭에 겹치는 정책은 `allow_tail / fade_tail / hard_stop_on_skip` 등 명시적 Cue Policy로 결정한다.
- **음성 우선:** Voice가 겹치면 다른 음성은 큐잉하거나 명시적 fade-out. BGM/환경음 duck은 *즉시 값 변경이 아닌 오토메이션*으로 설정한다. 대사 끝에 툭 튀어나오는 볼륨 복원 금지.
- **무음의 화이트리스트:** `STOP_WORK` 중 지정된 150~300ms, 프롤로그 의도된 절단 등의 `authored_silence=true` 항목만 예외. **무음인 배경이 아니라 드라마적 공백**이어야 한다.
- **Autoplay:** 처음 터치에서 AudioContext를 resume/unlock하고 실패 시 사용자에게 사운드 활성화 안내(작고 비차단적인 토스트). background/foreground, 이어폰 연결 변화, 음소거, 페이지 이동 시 `pause / resume / rehydrate` 절차를 단일 상태기계로 제어.
- **빠른 클릭/뒤로/이전 문장:** 동일 cue가 중복 발화되지 않고, 새 선택 이전의 무전·성우가 겹치지 않으며, 재생을 건너뛴 경우 음향과 게임 상태가 뒤처지지 않게 한다. 음성 Skip은 플레이어에 의한 즉시 선택이며 강제 자동 진행은 금지.
- **버퍼 압박 대응:** 48kHz PCM 전체 상주시 메모리 급증 가능. 환경음은 재사용 캐시 + LRU, 긴 score는 스트림 고려, 3~4종 동시 디코드 상한과 메모리 계측을 모바일 기준으로 정한다.
- **인터페이스:** `AudioDirector.transition({fromEvent,toEvent,reason,beat,decisionId})`, `AudioDirector.playVoice({cueId,duck,subtitleTimes})`, `AudioDirector.onVisibilityChange(state)` 등 *게임 규칙과 독립된* 표현 API.

### E-3. 전환 의사코드 (제작 기준, 그대로 실행되는 완성 코드 아님)

```ts
async function transitionAudio(from: SceneAudio, to: SceneAudio) {
  const next = await prepareAssets(to, { deadlineMs: 500 });
  if (!next.ready) {
    retainCurrentWorldBed();
    reportAudioRecovery('asset-not-ready', to.eventId);
  }
  const at = audioContext.currentTime + 0.035;
  if (from.bedId !== to.bedId && next.bed) {
    playBed(next.bed, { gain: 0, at });
    automateGain(from.bed, 0, at, at + 1.2);
    automateGain(next.bed, to.bedGain, at, at + 1.2);
  }
  if (from.scoreState !== to.scoreState) crossfadeScore(to.scoreState, { seconds: 2.2 });
  // Non-scene-bound FOLEY continues to its authored tail naturally.
}
```

이 코드는 제안 인터페이스이며, 기존 저장 게임/음성 재생 계약을 깨지 않고 별도 구현·테스트가 필요하다.

## H. 지루함을 줄이는 구체적 편집 수칙

- **정보를 반복하지 않는다.** 26번에 걸쳐 같은 “위험을 확인하세요” 메시지를 변주하지 말고, **첫째는 징후, 둘째는 의견, 셋째는 비용, 넷째는 관계, 다섯째는 기록**처럼 질문 자체를 변경한다.
- **버튼 수와 비트 수를 혼동하지 않는다.** `다음` 버튼은 엔진 진행을 보존하지만, 화면상 여러 동일 문장을 1개 자막 비트로 묶고 **같은 장면 재진입 시 음악은 재시작하지 않는다**.
- **3종 리듬 도입:** `현장 탐색(보며 듣기)` ↔ `사람 대화(목소리 듣기)` ↔ `판단(플레이어 개입)`. 같은 형식 두 회 이상 연속되지 않도록 감독 QA로 점검.
- **샷 역학:** wide=어디인가, detail=무엇이 달라졌나, human=누가 영향을 받나, choice=내가 무엇을 할 것인가. 컷의 존재 이유가 없다면 축소한다.
- **정보 공개:** 모든 사건 첫 문장에 답을 쓰지 않는다. 인물이 왜 말을 망설이는지 직접 들어야 이야기가 굴러간다.
- **사용자 속도 존중:** 읽기 모드, 자막 켜기, 배경음 분리, “장면 감상”, 음성 Skip 제공. 이야기 전환은 수동이지만 **시각/음향 전환은 자연스럽게**.
- **최종 감정:** 큰 축하 화면 대신 퇴근 장면에서 앞선 위험 소리의 재해석을 들려준다. 낮에 겪은 일이 누군가에게 남았다는 사실이 보상이다.

### I-1. 측정할 QA 신호와 목표치 (초기 제안치)

- `audio_event_timeline.json`: `eventId`, `nodeId`, `cueId`, `assetId`, `requestedAt`, `readyAt`, `scheduledAt`, `audibleAt`, `endedAt`, `reason`, `voiceDuck`, `device`, `error` 기록(개인 정보 저장 금지).
- **의도되지 않은 무음:** 유효 world/bed가 존재하는 정상 장면 전환에서 **100ms 초과 비계획 무음 0건** 목표. Android 실제 오디오 캡처 또는 앱 오디오 루프백 측정 필요(단순 DOM 검사만으로는 판정 불가).
- **오디오 시작:** 캐시된 효과음은 사용자 조작 후 120ms 이내의 체감 응답을 초기 기준으로, 대사 및 긴 파일은 디코드 준비 정책과 함께 실제 기기 측정.
- **더블재생:** 동일 `cueId + storyRevision` 중복 시작 0건.
- **음성 가청성:** 음악의 체감 음량이 대사를 가리지 않고, 휴대폰 스피커에서 모든 주요 문장을 추가 반복 없이 이해할 수 있어야 함.
- **복원:** 일시중지→복귀, 화면 전환→뒤로, 전화 통화/앱 백그라운드→복귀 시 무한 무음·동시 반복 0건.

## J. 상업 출시에 앞선 원칙

- 다른 영화/드라마/게임의 **원음원·멜로디·명대사·효과음 라이브러리를 무단 복제하지 않는다**. 추출하는 것은 “모티프의 재등장”, “음악적 결말”, “대사 우선 믹스”, “장면 사이 J/L-cut” 같은 일반적인 제작 문법이다.
- 성우/AI 성우·AI 생성음·현장 음향은 생성·라이선스·초상/음성 권리·상업 사용 조건·소스와 버전을 manifest에 기록한다. 실제 특정 인물의 목소리를 무단 복제하지 않는다.
- 안전사고를 자극적인 충격 영상으로 소비하지 않는다. 압박을 받는 관리자·현장 반장을 일방적 악역으로 묘사하지 않는다.
- 기술적 품질 게이트 통과와 **감동의 객관적 보장**은 다른 문제다. 감정 몰입도는 블라인드 플레이테스트(일시정지 횟수, 전환 재감상율, 서사 이해, 재방문 의향 등)로 실제 측정한다.
