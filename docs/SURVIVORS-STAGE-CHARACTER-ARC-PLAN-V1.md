# 오늘도 무사히 - 50개 구역·6명 성장 서사 연결 v1

작성: 2026-10-09. 사용자 요청에 따라 기존 스테이지 변화·인물 성장 기획을 통합한 제안. 실제 구역 이름과 규칙은 기존 데이터가 기준이다. 아래 새 사건·대사·진로·해금 조건은 검토안이며 운영 콘텐츠가 아니다.

## 기존 계약을 먼저 연결한다

`survivors-campaign50-ko.json`에는 현장 적응/공정 연결/복합 지하/상부 교차작업/통합 인계의 5개 장과 요원별 완수 기록이 이미 있다. 이를 새 성장 저장소로 중복하지 않는다. `survivors-operation-brief-ko.json`의 6개 플레이 역할을 유지한다. 본편 `episode01/character-growth.json`에는 identity_locked, age_visual_change=false와 initial/focused/skilled 단계가 존재한다. 본편의 추가 등장인물을 플레이 가능한 신규 캐릭터로 자동 편입하지 않는다.

앞선 성장 기획의 네 장면은 이야기 구성이지 새 원화 상태 enum이 아니다. 현재의 나=initial, 나만의 방식=focused 후보, 책임의 확장=skilled 후보, 선택한 길=진로 후일담 CG로 제안한다. 단계 해금은 본편과 시그널 워치 사이에 자동 공유하지 않는다. 실제 연결 필드·승인·마이그레이션 검증 후 결정한다.

## 스테이지 변화의 세 층

공정 변화는 기존 구역·지도·위험 계약을 따른다. 같은 장소에서 통로·차폐·잔여 확인이 달라지는 변화는 실제 엔진 기록으로만 표현한다. 인물의 태도와 동료 반응은 승인된 이야기 사건으로 표현한다. 과거에 길을 비웠다고 실제 맵의 통로가 다음 판에 유지된다는 거짓 안내를 하지 않는다. 연결 기능이 없으면 결과 기록만 남긴다.

| 기존 구역 범위 | 현장 변화 | 인물에게 던질 질문 | 결과 장면 제안 |
|---|---|---|---|
| 01-10 현장 적응 | 눈앞의 예고·이동·기초 대응 | 나는 무엇을 먼저 보고 말하는가? | 처음 남긴 구체적인 확인 기록 |
| 11-20 공정 연결 | 다음 작업팀과 반입·양중·작업면 공유 | 내 대응이 다음 사람에게 어떻게 전달되는가? | 인계 전후 같은 동선 확인 |
| 21-30 복합 지하 | 환기·배수·굴착 반출·기존 설비 혼재 | 무엇을 알고 무엇을 더 확인해야 하는가? | 미확정 사항을 숨기지 않는 재확인 |
| 31-40 상부 교차작업 | 상부 반입·외부 비계·옥탑·작업 순서 | 일정 압박 속에 어떤 순서를 지킬 것인가? | 서로 다른 작업팀의 순서 합의 |
| 41-50 통합 인계 | 설비 격리·시운전·결함 확인·운영팀 인계 | 내가 떠난 뒤에도 무엇이 남아야 하는가? | 완료와 남은 확인을 함께 전달 |

이는 50번의 필수 대화를 의미하지 않는다. 일반 구역은 기존 한 줄 무전과 정확한 결과를 유지하고, 각 장의 중요한 전환에서만 선택/성장 장면을 제안한다. 중앙 전투 팝업·추가 버튼 연계를 늘리지 않는다. 보급에서는 전투가 멈춘 기존 안전한 선택 흐름을 유지한다.

## 6명 × 5장 인과선

| 인물 | 01-10 | 11-20 | 21-30 | 31-40 | 41-50 |
|---|---|---|---|---|---|
| 안전관리자 | 듣고 직접 확인 | 중지 이유·재개 조건 인계 | 모르는 것을 재확인 | 교차 반경·순서 조율 | 운영팀에 근거와 잔여 확인 전달 |
| 강태식 | 작업반 이동 챙김 | 다음 팀 통로 함께 확인 | 좁은 면의 배치 다시 조정 | 작업반 간 순서 설명 | 후배가 설명할 수 있게 인계 |
| 윤성호 | 자재·결속 차이 관찰 | 반입과 작업 위치 비교 | 기존 구조와 보강 차이 질문 | 상부 작업에서 작은 이상 전달 | 기술 근거를 다음 작업자에게 남김 |
| 이재훈 | 계획과 설치 대조 | 공정 사이 불일치 확인 | 기존·신설 설비 구분 | 계획 변경의 이유 공유 | 도면·실제 상태·잔여 확인 분리 |
| 임준호 | 작은 이상을 먼저 보고 | 다음 팀의 답을 듣기 | 모르는 설비를 질문 | 급한 상황에서도 신호 확인 | 자기 판단을 근거와 함께 설명 |
| 안전감시자 | 출입·무전 확인 | 반입 신호 지점 맞추기 | 사각과 통신 제한 전달 | 겹친 반경을 팀과 분리 | 운영팀이 쓸 신호 체계 인계 |

인물별 마지막 장면은 좋은 경험의 방향이지 승진 확정이 아니다. 각 인물의 진로 후보는 기존 직무 안의 전문기술/협업·전수/관찰·개선처럼 구분하되 이름과 조건은 별도 승인한다. 보유 장비나 유료 구매로 특정 진로를 독점하지 않는다.

## 첫 실행 묶음: stage_12 철근 반입·배근

첫 시범은 실제 campaign20의 stage_12를 제안한다. 이 구역은 RUNAWAY_CART·UNHELMETED 위험 구성, safety_monitor 무전, 철근 반입과 배근이 동선을 공유하는 기존 설명을 가진다. 보스·체력·시간·해금·보상은 변경하지 않는다. 다른 시범 stage ID가 이미 승인돼 있으면 그 결정이 우선이다.

준비: 기존 선택 캐릭터 역할과 '다음 팀에게 무엇을 남길까' 한 가지 관심사 표시. 전투: 기존 통로 정리·제동·통제 구역 사건을 읽기 관측. 결과: 실제 확보/제동/잔여 확인만 요약하고, 승인된 인계 대화에서 인물의 판단을 연결. 기록: 성장 CG를 다시 볼 근거 사건을 하나 남김. 다음 구역: stage_13 야간 콘크리트 타설의 기존 조명·접근 통제 설명으로 연결하되 없는 지도 변경이나 보너스를 약속하지 않는다.

2026-10-09 사용자 직접 '안전관리자: 대표 주인공 중심' 선택으로 첫 시범 인물은 안전관리자(characterId `player`)로 확정했다. 기존 대표 인물의 안정감을 유지한다. 임준호와 나머지4명 전체 대사는 동일 사건의 관점 확장 후속이며 첫 시범 전에 전체 제작하지 않는다. 인물 선택을 대사/원화/진로 공식 최종 승인으로 확대하지 않는다.

## 이미지와 소리의 단계별 납품

본편3단계 이미지와 현 시그널 워치 전투 원화를 먼저 슬롯·승인 상태별로 목록화한다. 새 이미지가 필요한지 확인하고 승인된 기존 파일이 목적에 맞으면 재사용한다. 미승인 파일을 단순히 이미 배포됐다는 이유로 승인 처리하지 않는다.

장 전환 CG는 같은 인물의 얼굴/PPE/체형을 유지하고 배경 공정·함께 일하는 상대·표정·도구 사용의 변화를 보여준다. 흙먼지나 피로를 무능력·실패의 외모 낙인으로 쓰지 않는다. initial/focused/skilled는 3단계 납품 계약, 진로 후일담은 별도 그림이며 8방향 보행 아틀라스와 별개다. 인물×단계×진로×구역의 모든 조합을 생성하지 않는다.

성장 음성은 짧은 자기 판단 또는 동료의 구체적인 응답으로 한다. 먼저 상황·발화자·말투·중복 억제를 localization 초안으로 검수한다. 새 음원 최종 제작/사용권/청취 승인은 별도이며 이전4voice 승인으로 확대하지 않는다.

## 구현·검증 순서

### 2026-10-09 현재 시범 구현

안전관리자 STAGE 12의 사용자 승인 CG와 A/B 안전관리자 문장만 로컬 준비/결과/다시보기에 연결했다. 다음 준비는 기존 STAGE 13이며 새 보너스나 지도 상태를 만들지 않는다. 동료 응답·진로·다른 인물 CG는 승인된 것으로 간주하지 않는다.

결과 화면은 실제 종료 인계와 저장 기록 일치를 요구한다. 저장 누락/오류/불일치·다른 인물·중단 상태는 장면을 숨긴다. 결과부터 STAGE 13 준비/다시보기 PC·폰 세로·가로 fixture와 해금/기존 장비 보유 fixture UI봇의 실제 STAGE12 완주·별/정산/reload/STAGE13 준비 검증 완료. 자연 구매/선행 해금·사람·실기기는 남아 있다. 최신 항목별 증거는 `SURVIVORS-GROWTH-IMPLEMENTATION-STATUS-20261009.md`를 따른다.

PR162 원격13404의 GitHub 검사는 성공이나 Vercel 배포 한도 실패로 로컬 후속은 운영 미반영이다. 최신 사용자 지시로 동기화는 요청 시에만 수행한다. 배포 대기를 로컬 구현 중단 사유로 사용하지 않는다.

1. 현 저장의 요원별 완수/인계 기록, 본편 growth 플래그, 실제 stage_12 사건의 소유 모듈을 조사한다. 각각의 필드를 추정하거나 중복 저장하지 않는다.
2. 시범 인물·사건·대화2안·근거·원화 슬롯을 승인표로 확정한다. Career/PSI/Dark Path 수치와 직업 해금 공식은 아직 도입하지 않는다.
3. 승인된 한 사건만 domain 계약과 기존 준비/결과/기록에 연결한다. 건너뛰기·다시보기·저장 오류/재시도·중복 완료·캐릭터 전환을 회귀한다.
4. 자연 UI 플레이에서 사건-결과-기록-다음 준비를 확인하고 fixture와 구분한다. PC·폰가로·세로에서 몸체/위험/버튼 가림과 일시정지를 검증한다.
5. 승인된 이미지 파일과 대사만 연결하고 최신 CI·Vercel·운영 검증 후 적용한다. 작은 시범 완료 전 나머지49구역과6명 전체 제작을 병렬 확대하지 않는다.

기술적 완료와 Director 시각/청취/실기기 완료는 분리한다. 지금 문서가 있는 것과 새 성장 기능이 구현됐다는 것은 다르다. 진행은 실행 가능한 묶음으로 이어가되 승인 대기 항목을 자동 승인하거나 범위를 끝없이 생성하지 않는다.
