# PSI 야간 긴급 순찰: 품질 점검과 개선 기획

작성일: 2026-10-03 / 기준 커밋: 32b07b34affd15a314814f5296bf03905bd5aedf

## 결론

현재 SURVIVORS는 이동, 자동 공격, 성장 선택, 진화, 5개 스테이지, 영구 강화, 궁극기, 보상까지 갖춘 플레이 가능한 프로토타입이다. 다만 출시 품질은 아직 입증되지 않았다. 가장 큰 부족은 슈팅 모드에 연결되지 않은 고품질 음악, 발사와 명중의 소리 피드백 부족, 모바일 HUD 겹침, 프레임/난수에 따른 재현성 부족이다. 콘텐츠 양보다 Stage 01의 3분 경험을 먼저 완성한다.

전체 제품은 전략·추리·디펜스이고, 이번 요청의 주 대상은 `PatrolSurvivorsGame`의 액션 모드다. 기존 G8-A 디펜스 오디오의 승인과 자산은 존중하되, 이를 슈팅 오디오 완성의 증거로 대체하지 않는다. 세계관과 게임성에 대한 아래 변경은 제안이며 기존 상위 설계 원칙의 변경을 확정한 것이 아니다.

## 점검 범위와 증거

- 최신 GitHub main을 별도 폴더에 복제해 읽었다. 기존 사용자 작업 폴더는 수정하지 않았다.
- 슈팅 domain/engine/UI/테스트, 디펜스 오디오 상태와 믹서, 설계 원칙, 기존 QA 장부를 확인했다.
- 브라우저에서 타이틀 → SURVIVORS → Stage 01 시작을 실행했다. 1264x625와 390x844 화면을 캡처했다. 전체 5개 스테이지 클리어와 실물 Android 조작은 미검증이다.
- `npm run typecheck`: PASS.
- 슈팅 3개 테스트 파일: 23/23 PASS. UI 테스트는 jsdom에서 canvas getContext 미구현 경고가 있어 실제 렌더 품질을 증명하지 못한다.
- 디펜스/밸런스/오디오 5개 테스트 파일: 30/30 PASS.
- `node scripts/check-g8a-premium-audio.mjs --require-final`: 24/24 승인 자산 존재, PASS.
- `npx vite build`: 변환 387개 이후 메모리 할당 실패. 정식 `npm run build` 및 전체 release 검사는 완료하지 않았다. 코드 결함으로 단정하지 않는다.
- 최초 Vite 직접 실행에서는 자산 전처리 누락으로 로딩 실패. `npm run predev` 후 정상 로딩됐다. 사용자 실행은 README의 `npm run dev`를 사용한다.
- 직접 청취 평가를 수행하지 않았다. 오케스트라 음색, 마스킹, 루프 품질에 점수를 매기지 않는다.

화면 증거: 저장소 루트 `qa-shooting-desktop.png`, `qa-shooting-mobile.png`.

## 보존할 강점

액션 엔진이 React 파일 밖에 있고, 캐릭터 능력·진화·성장·공정별 스테이지의 소재가 이미 있다. 히트스톱, 넉백, 궁극기 컷인, 피격 플래시도 구현돼 있다. 이 기반을 활용해 피드백의 시간·빈도·일관성을 조정한다. 디펜스에는 원본 보존, 24개 오디오 슬롯, 동적 상태, 실기기 승인 이력이 있어 슈팅 제작에서도 사용할 수 있는 제작 체계가 있다.

## 목표 경험: Stage 01 3분

장르 정의: 이동과 위치 선정 중심의 자동 공격 서바이벌 슈팅. 수동 조준 추가는 별도 결정이며 이번 기본안에 포함하지 않는다.

| 구간 | 플레이 목적 | 연출과 소리 | 검수 질문 |
|---|---|---|---|
| 0-20초 | 이동, 자동 대응, 수집을 이해 | 현장 공기와 낮은 현악, 명확한 첫 공격/수집음 | 설명 없이 이동과 대응의 관계를 이해하는가 |
| 20-60초 | 첫 퍽 선택으로 차이를 체감 | 선택 때 짧은 음악 완화, 강화 후 새 음색 | 강화 직후 무엇이 달라졌는가 |
| 60-120초 | 통제 구역/동선과 빌드 선택 | 저현 ostinato와 제한된 타악 추가 | 위험 예고를 보고 피하거나 개입할 수 있는가 |
| 120-165초 | 대표 중장비 위험과 궁극기 | 위험 경보 우선, 음악 duck, 호른 개입 모티프 | 화면을 잠깐 못 봐도 주요 위험을 구별하는가 |
| 165-180초/결과 | 정리와 다음 단계 동기 | 현장 복귀 ambience, 절제된 coda | 승패 원인과 다음 개선을 이해하는가 |

이 타임라인은 제안이다. 기존 boss/spawn 수치를 먼저 측정하고, 승인 후 수치를 조절한다. 시간 생존만으로 승리할지 대표 위험 통제도 요구할지는 Director 결정 사항이다.

## 제작 순서와 완료 조건

1. Q01 안정성: 오디오 수명, focus, stage 식별, 저장 검증. 다른 stage로 전환해도 배경·별·해금 일치. 종료 보상은 1회. 기존 저장 유지.
2. Q02 전투 기반: 시드 RNG, 고정 step, 고속 충돌. 같은 시드/입력에서 simulation 결과 일치. 30/60/120Hz 테스트에서 실시간 길이와 보상 일관성 확인.
3. Q03 모바일/가독성: 390x844, 360x800, 844x390, 1440x900. HUD/콤보/궁극기/퍽 선택이 겹치지 않음. 터치 취소/두 손가락/회전/홈 복귀 확인.
4. Q04 오디오 엔진과 최종 자산: 아래 SOUND 기획을 기준으로 기존 자산 재사용 가능 여부부터 판단. Music/SFX/Voice/Ambience 버스, mute/pause 수명, 디코딩 실패 처리.
5. Q05 Stage 01 최종 아트와 연출: 실물 현장 맥락, 위험 실루엣, 공격-명중-통제 완료를 일관되게 표현. 새 placeholder를 final로 계산하지 않음.
6. Q06 사용자/실기기 검수: 신규 플레이어 5명 이상, 10분 반복 청취, 실물 Android. 자료를 보고 추가 stage 확대 여부 결정.

정량 목표는 제안값: 입력 시각 반응 p95 100ms 이하, 대표 Android에서 60fps 목표와 p95 프레임 20ms 이하, 10분 후 컨텍스트/voice 누적 없음, 신규 사용자 5명 중 4명 이상 첫 강화·위험·결과 이해. 성능 목표 실패 시 실측 결과로 조정하며 성공 수치를 만들어내지 않는다.

일정은 미산정이다. Q01-Q03은 코드/실측 작업, Q04-Q05는 최종 음원·아트 제작과 승인에 의존한다. 실측 없이 AAA/출시완료/오케스트라급 달성을 선언하지 않는다.
