# 플레이 화면 후속 검증 · 2026-10-19

## 범위와 방법

우선순위 구현 보고서의 후속 검증이다. localhost:5189 개발 서버를 연결된 브라우저에서 실제 버튼·선택지·슬라이더로 조작했다. 게임 상태, 자원, 해금, 저장 데이터를 주입하지 않았다. DOM 검사로 노출 여부와 경계를 측정하고 JPG를 보관했다. 저장소에 남긴 검증용 선택 기록은 삭제하지 않았다.

스토리 화면은 1440×900, 390×844, 844×390에서 확인했다. 읽기 설정을 UI로 135%로 올려 본문 대비, 다음 버튼, 선택지, DAY02 안내를 확인했다. 하나의 진행 경로에서 첫 번째 활성 선택지를 택해 26개 이벤트와 완료 회고까지 139회 조작했다. 모든 분기와 모든 음성의 청취 검수를 뜻하지 않는다.

도착 장면에서 새로고침 후 이어 읽기를 확인했고, 중간 이벤트 e01_08i_restart_pressure의 situation 노드에서 현장 홈으로 나갔다가 동일 이벤트·노드로 돌아왔다. 노드 안의 읽기 페이지는 처음부터 표시됐다. 세부 추적은 `artifacts/player-visible-qa-20261019/story-trace.json`에 있다.

## 발견하여 수정한 문제

### DAY02 및 읽기 안내가 선택 화면에서 숨겨짐

기존 emergency-ux-fix.css와 production-scenes.css의 SHOW_CHOICE 규칙이 `.choice-content` 이외의 직계 자식을 `display:none!important`로 숨겼다. `.story-reading-guide`는 DOM에 존재해 기존 접근성 검사에는 통과했지만 실제 화면에서는 사라졌다. 음성 건너뛰기와 다음 날 확인 안내도 이 컨테이너에 들어 있어 영향을 받았다.

`src/ui/story-player.css`에서 cinematic 플레이어의 `.presentation-area > .story-reading-guide`에만 `display:flex!important`를 적용했다. 게임 규칙과 선택 결과는 변경하지 않았다. 수정 후 DAY02 선택 화면에서 computed display가 flex이며 안내 문구와 선택지를 동시에 확인했다. 390px 세로 화면에서 세 선택지가 화면 안에 있었고, 844px 가로 화면의 선택 패널은 내용 높이에 맞춰 스크롤 가능했다.

### 플레이 가능한 스토리를 준비중으로 표시

홈의 하단 바로가기와 미완료 기록 문구에 준비중 설명이 남아 있었다. `content/localization/playable-ko.json`과 `content/episode01/ko.json`에서 EP.01 플레이 및 로컬 선택 이어 읽기 설명으로 고쳤다. 미완료 장면은 실제 완료 기록이 없다는 뜻으로 표시한다. 새 플레이 콘텐츠는 추가하지 않았다.

## GUARD 모바일 검증

390×844에서 GD-01 준비 → 강태식 선택 → 위험 정보 패널 → P1 펄스 대응기와 P3 흐름 제어기 구매 → 첫 웨이브 시작을 실제 UI로 확인했다. 위험 유형과 대응 요약이 상세 진입 순서보다 앞에 보인다. 자원은 구매 비용대로 220 → 140 → 50이 됐다.

전체 테스트 전처리의 자산 생성으로 개발 서버가 다시 로드되어 전투가 중단됐다. 작전실의 이어하기로 두 장비와 진행 중인 1파가 복원됐고, 일시정지 상태에서 재개할 수 있었다. 이 전처리 리로드를 게임의 자연스러운 웨이브 종료나 클리어로 계산하지 않는다.

이후 일반 판매 조작으로 두 장비를 제거했다. 1파 종료 시 보호막 6, 2파에서 보호막 0이 되었고 방어 실패 대화상자와 전술 회고가 자동 표시됐다. 최근 이탈 20/24개가 불안정 파형으로 표시되고 재도전의 기존 시작 자원 안내가 나왔다. 무배치 이탈 표본에 빈 조준 목록이 나타나는 것을 발견해 명시적인 ‘이탈 당시 배치된 장비가 없었습니다’ 문구로 바꿨다. 구형 기록의 조준 정보 없음과 구별하는 UI 회귀 검사를 추가했다.

저장된 패배 기록을 작전실에서 다시 펼쳐 수정 문구를 실제 화면으로 확인했다. 다음 작전 준비에서 같은 동료를 선택했을 때 보호막 20, 자원 220, 1/6파, 8개 빈 패드로 시작했다. 이는 작전실을 통한 새 준비 경로 검증이며 결과 대화상자의 ‘다시 도전’ 버튼 자체를 누른 검증으로 확대 해석하지 않는다.

## 자동 검사

첫 전체 검사는 2,314 통과·1 실패·기존 1 skip이었다. 실패는 홈 미완료 기록 문구에 ‘아직’을 추가하면서 기존 문장 계약과 어긋난 것이었다. 기존 첫 문장 ‘이 장면의 완료 기록은 없습니다’를 보존하고 뒤 설명을 갱신해 해결했다. 새 무배치 회고 검사 5개는 통과했다. 빌드와 병행한 후속 검사에서 홈 탐색의 기존 5초 제한이 한 번 초과되어, 병행 작업 종료 후 전체 검사를 다시 실행했다. 최초 실패 로그도 지우지 않고 보관한다.

최종 결과: `npm test -- --maxWorkers=4` 2,316 통과·0 실패·기존 1 skip, `npm run typecheck` 통과, 공식 `npm run build` 통과. 빌드의 기존 청크 크기 경고는 남아 있다. 실제 브라우저에서 수집된 오류·경고 로그는 0건이었다. 읽기 글자 크기는 검증 후 100%로 복원하고 임시 뷰포트도 해제했다.
