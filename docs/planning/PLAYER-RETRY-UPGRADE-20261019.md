# 오늘도 무사히 · 재도전과 조준 기록 보강

2026-10-19. 이전 우선순위 구현과 플레이 화면 검증의 후속 보수다.

## 변경

- `SetTargetMode` 명령을 구매·업그레이드와 같은 즉시 저장 경로에 연결했다. 기존에는 조준 변경이 다음 2초 자동 저장이나 다른 저장 동작까지 메모리에만 남을 수 있었다. 실행 중 빠르게 새로고침해도 가장 최근 저장에 조준 변경이 포함되도록 한다. 저장 실패는 기존 저장 오류·재시도 UI를 사용한다.
- 실패 회고의 빠른 신호·체력 우선 조준 비교 조언은 그 조건이 실제 기록된 가장 최근 이탈 표본을 함께 표시한다. 뒤에 다른 적이 이탈하거나 장비가 모두 팔렸어도 무관한 표본을 조언의 근거처럼 보여주지 않는다. 조건에 맞는 표본이 없으면 기존의 마지막 조준 기록을 보여준다.
- 전투 수치, 보상, 시작 자원, 저장 형식, 새 이야기와 미술 자산은 변경하지 않았다.

## 회귀 사례

실제 DefenseGame UI 검사에서 장비 구매 → 조준 변경 → 저장 검사 → 언마운트 → 다시 마운트 → 이어하기 → 선택된 조준을 확인한다. 가드에서는 출구 직전 적이 있는 테스트용 중단 상태를 복원하고 실제 엔진으로 패배시킨 뒤, 결과 화면의 다시 도전 → 동료 선택을 실행한다. 새로운 실행 ID, READY, 1파, 초기 보호막·자원, 빈 장비 목록과 이전 패배 기록 1건을 확인했다. 테스트용 상태는 자동 검사 안에서만 생성한다.

혼합 이탈 표본에서는 빠른 신호가 체력 우선 조준과 함께 관찰된 두 표본 뒤에 일반 적의 무배치 이탈을 추가해, 가장 최근의 관련 표본을 선택하며 원본을 수정하지 않는지 확인했다.

관련 3파일 21검사 통과. 이 UI 검사의 음성 재생은 jsdom에 없으므로 mock을 사용하며 청취 검수를 의미하지 않는다.

## 검증 기록

타입 검사 최초 실행 통과. 전체 검사 첫 실행은 394파일 2,296검사 통과·기존 1 skip 뒤 두 작업자 프로세스가 종료되어 실패로 남겼다. 첫 공식 빌드도 TypeScript 네이티브 검사기의 `VirtualAlloc errno=1455 / out of memory`로 중단됐다. 작업자 수를 줄인 후속 검사와 빌드 결과는 완료 후 기록한다. 최초 로그는 덮어쓰지 않는다.

브라우저는 개발 서버에서 홈의 게임 타이틀과 가드 진입 버튼을 확인했다. 이후 전처리의 자산 재생성과 개발 서버의 동적 모듈 로딩 실패가 겹쳐 가드 진입 화면 검증은 완료하지 못했다. 이 결과를 실제 재도전 버튼의 브라우저 통과로 계산하지 않는다. 새로고침과 재도전의 조작 검증은 위 React DOM 통합 검사 결과다.

로그: `artifacts/player-retry-upgrade-20261019-*.log`.

최종 전체 회귀: `npm test -- --maxWorkers=2` 종료 코드 0, 396파일·2,319검사 통과, 기존 1파일·1검사 skip. 규칙이나 기대값을 완화하지 않고 동시 작업 수만 줄였다. 공식 빌드는 TypeScript의 Go 런타임 병렬도를 `GOMAXPROCS=2`로 제한해 재실행한다.

최종 공식 빌드도 종료 코드 0으로 통과했다. 기존 500KB 초과 청크 경고는 유지한다. 타입·엔진 경계 검사와 공식 prebuild 계약 검사를 포함한다.

완성 빌드의 별도 미리보기 `127.0.0.1:5193`에서 홈 → 가드 작전실 → GD01 → 강태식 → P1 펄스 구매 → 강한 위험 조준 → 새로고침 → 가드 → 중단한 작전 이어하기 → P1 선택을 실제 UI로 실행했다. 자원 140, 보호막 20, 1/6파와 ‘강한 위험’ 선택 상태(`aria-pressed=true`)를 확인했다. 상태·저장 데이터 주입은 하지 않았다. 이 흐름은 조준 복원의 브라우저 확인이며, 2초 이내 저장 시점 자체는 앞의 타이머 미진행 DOM 검사로 검증한다. 콘솔에서 반환된 오류 1건은 앞선 5192 개발 서버의 로딩 실패이며 5193 미리보기 URL의 새 오류는 없었다. 화면 캡처는 브라우저 캡처 명령 시간 초과로 보관하지 못했다. 실제 브라우저에서 패배 후 재도전 전체를 추가 수행한 것은 아니다.
