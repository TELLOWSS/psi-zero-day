## 1. 목표와 범위

목표는 접속부터 플레이 종료까지 ‘현장 안에서 직접 위험의 연쇄를 끊고 있다’는 체감을 만드는 것이다. 시그널 워치와 동등한 진입 위계, 화면을 채우는 현장, 한 동작으로 이어지는 조준과 발사, 알아보기 쉬운 대응 장비가 핵심이다.

2026-09-24 마스터 바이블의 WORLD FIRST / MOBILE FIRST / IMPACT FIRST / AUDIO = GAMEPLAY / ONE PRODUCTION GENERATION을 적용한다. 해당 문서는 본편 DefenseGame의 기준이므로 브레이커에 디펜스 전용 보드·웨이브·타워 ID를 이식하지 않는다. 최신 브레이커 GDD의 독립 모드·분리/반사/회수 정체성과 현재 5작전, LAB, 시험판, 저장 구조를 보존한다. 별도 게임을 새로 만들거나 시그널 워치 엔진을 바꾸지 않는다.

이번 범위는 요청한 1–6에 대한 진입·화면·조작·표현 개선이다. 스테이지 수 확대, 보스 밸런스 변경, 신규 유료 장비는 범위에 포함하지 않는다.

## 3. 홈 구조

### 화면의 역할

브랜드·메인 카피 → 플레이 모드 카드 → 누적 성장 순서로 읽힌다. 시그널 워치와 브레이커는 각각 이름, 대표 현장 이미지, 핵심 플레이 설명, 실제 진입 동작 하나를 가진다. 준비중 모드는 기존 프리뷰로 유지한다.

### 이번 수정

- 중복 `commercial-mode-navigation` 제거. 실제 큰 카드 링크/버튼은 유지.
- ‘새 스토리 준비중’ 추가 카드 제거.
- 진행 대시보드에서 모드별 홍보/설명을 제거하고 해금 구역과 연구 데이터만 표시.
- 도감·인물·기록·현장/공정은 각각 기존 목적을 가진 진입점을 유지.
- 장식 캐릭터와 기존 브랜드 최종 자산을 변경하지 않음.

검증: 홈에서 브레이커 게임 URL로 향하는 앵커는 정확히 한 개여야 한다. 준비중 모드는 실제 출시 모드로 변하지 않아야 한다. 방문 전후 본편 저장 상태가 유지되어야 한다.

## 4. viewport 전장

### 공통

- `shell/layout/main-panel/game-card/canvas-wrap`을 viewport에 맞춘다.
- 카드 border/radius와 외부 여백은 제거한다. 전장 위에 HUD·조작·지도·정지 화면을 배치한다.
- `100dvh`와 safe-area inset을 사용한다. 모바일 브라우저의 표시 가능 영역을 채우며 OS 상태표시줄/브라우저 크롬 제거는 Fullscreen API가 허용하는 환경에서 별도로 시도한다.
- 전체화면 요청이 거절되어도 현재 전면 레이아웃은 유지한다. 이를 실패로 강제 종료하지 않는다.
- 배경은 화면을 채우는 기존 최종 현장 자산을 사용한다. 물리 월드는 기존 1100×620 좌표계다.
- 창 크기에 맞춰 비트맵을 조정한다. quality high/balanced/low는 DPR 상한 2/1.5/1. 기존 공격·충돌 판정은 유지한다.

### 세로

실제 크기의 캐릭터와 위험을 유지하기 위해 현장 전체를 작게 압축하지 않는다. 화면 높이에서 상단 안내와 하단 조작 공간을 확보하고, 캐릭터 X를 따라 수평 카메라가 움직인다. 지도의 사각형은 현재 시야를 보여준다. 화면 밖 위험은 지도에 계속 표시되고, 지도를 터치하면 해당 월드 좌표로 조준·발사한다.

카메라 확대는 판정 범위를 바꾸지 않는다. 터치 좌표는 camera scale/offset 역변환을 거쳐 `setAim`에 전달된다. 카메라는 캐릭터 이동으로만 이동하므로 조준 손가락을 움직일 때 카메라가 다시 목표를 움직이는 피드백 루프를 피한다.

### 가로·PC

세로 높이에 맞춘 월드 배율로 현장 전체를 중심 배치한다. 넓은 양측은 같은 최종 현장 배경으로 채운다. 캐릭터·신호를 과도하게 확대해 위아래 물리 영역을 잘라내지 않는다. 좌우 조작과 중앙 진행 정보가 분리된다.

### 태블릿

화면폭이 아니라 세로/가로와 가용 높이에 따른 동일 카메라 규칙을 사용한다. 큰 화면에서 컨트롤을 무한히 확대하지 않고 일정한 손가락 목표 크기를 유지한다.

## 5. 조작 명세

| 행동 | 기본 조작 | 종료/예외 |
|---|---|---|
| 이동 | 왼쪽 원형 패드에서 수평 드래그. 입력값 -1~1 | 손 떼기·취소·캡처 해제는 즉시 0 |
| 조준/발사 | 전장 누른 채 드래그. 첫 입력에 발사, 유지 중 엔진 쿨다운에 따라 반복 | 손 떼기·취소·정지·다른 스테이지 진입 즉시 중단 |
| FIRE | 오른쪽 원형 FIRE를 누른 동안 현재 방향으로 반복 | 키보드 접근 클릭도 한 발 가능 |
| 키보드 | A/D 이동, 기존 단축키 보존. 발사키 유지 가능 | 키 해제/창 포커스 상실/정지에서 입력 초기화 |
| 장비 자동 | 기본 ON. 조준점 근처 130 월드 단위 안의 가장 가까운 코어를 판단 | pulse+net 장착 시에만 적용. 큰 코어 pulse, 작은 코어 net |
| 장비 수동 | 자동 OFF 후 두 장비 버튼/단축키 선택 | 6장비 전체를 자동 정답화하지 않음 |
| 시설 | 방호판/자력장/벨트 별도 버튼 | 해당 작전에 없는 벨트는 숨김 |
| 먼 신호 | 전체 지도 터치 → 월드 좌표 조준·발사 | 자동으로 표적을 추적하거나 목표를 명중시키지 않음 |
| 정지 | HUD 정지, 설정, Escape, 창 이탈 | 시간·쿨다운·입력 유지 중단. 재개에 새 손가락 입력 필요 |

자동 전환은 입력 부담을 줄이는 보조이며 물리·명중·정답 판단을 대체하지 않는다. 반사, 시설 개입, 보스 노드, 다른 4장비의 상황판단은 그대로 남는다. 수동 전환과 ‘손 떼면 한 발’ 기존 방식은 설정에서 선택할 수 있다.

멀티터치: 이동·조준·FIRE는 서로 다른 pointerId를 소유한다. 두 번째 전장 터치가 첫 조준을 탈취하지 않아야 한다. pointercancel 또는 lostpointercapture가 발사를 추가로 발생시키지 않아야 한다.

## 6. HUD와 그래픽

### 정보 위계

- 상단: 작전 / 회수 / 점수 / 생명 / 정지. 세로에서는 오른쪽 상단에 생명 상태를 별도 배치.
- 상단 한 줄: 지금 해야 할 행동. ‘분리 → 반사 → 회수’ 기존 단계 안내를 유지한다.
- 좌측 상단: 현장 전체 지도, 현재 시야, 신호체·플레이어 위치.
- 좌측 하단: 이동.
- 우측 하단: 장비·발사·자동 전환. 그 위에 시설.
- 하단 중앙: 진행과 연쇄. HUD는 전장 반응을 가리지 않는 반투명 재질.

### 표현 수정

기존 `breaker-six-tools-final-v3.webp` 장비 아틀라스를 실제 슬롯 아이콘으로 사용한다. 셀은 장비 spec.cell로 결정하여 해금된 다른 장비도 잘못된 아이콘을 쓰지 않는다. 선택된 장비는 테두리·배경·약한 빛으로 구분한다. FIRE는 따뜻한 금속색, 장비는 청록 대응장치, 시설은 낮은 명도의 기능 버튼이다.

문자 기호는 실제 장비 이미지가 있는 슬롯에서 최종 그림의 대체물로 쓰지 않는다. 작은 버튼 안의 글자는 행동 이름을 보조한다. 생명/판정/코어/발사 연출의 기존 고해상도 공유 자산은 그대로 사용한다. 영상의 저품질 원인은 자산 자체만이 아니라 축소와 레이아웃이었으므로 먼저 전장에서 실제 크기로 읽히도록 한다.

### 최종 아트 판정

이번 변경은 새 캐릭터 애니메이션이나 전체 스테이지 최종 아트를 제작했다는 의미가 아니다. 별도 최종 자산 제작이 필요한 항목은 다음과 같다.

1. 모든 장비의 손·총구·발사·명중·소멸 일관성.
2. 캐릭터 이동/조준/반동과 이동패드의 속도 대응.
3. 배경 조명과 코어/시설 발광의 색 일치.
4. 장비별 명중 재질음과 회수 피니시의 동기화.
5. 폰·태블릿 실제 패널에서 코어/인물/장비의 선명도.

이 항목의 최종 평가는 시그널 워치와 같은 기기·같은 화면 방향·같은 품질 설정의 연속 플레이 비교로 한다. CSS 적용이나 테스트 통과만으로 그래픽 최종 LOCK을 선언하지 않는다.

## 7. 성능·접근성·회복

렌더 해상도는 기기 DPR을 무제한 적용하지 않고 품질별 상한을 유지한다. Reduced Motion은 기존 흔들림과 장식 감소를 따른다. 기본 공격 쿨다운을 줄이거나 입자 수를 임의로 늘리지 않는다. 전체 지도는 220×124 작은 canvas로 제한한다. 정적인 현장 배경은 품질별 해상도로 한 번 캐시하고, 프레임마다 원본 이미지를 재분할하지 않는다.

주요 터치 목표는 48px 이상. 장비 자동 선택은 34px의 보조 토글이며 발사·장비·이동·시설과 떨어져 둔다. 버튼은 키보드 focus-visible, 한글 이름, aria-label을 유지한다. 자동 전환 토글은 aria-pressed를 갱신한다.

오프라인 캐시 버전을 갱신하여 수정된 HTML/JS/CSS가 이전 shell과 섞이지 않도록 한다. 저장 키와 기록은 기존 namespace를 유지한다. 오디오 autoplay 제한에 따른 무음도 게임 로딩을 막지 않아야 한다.

## 9. 제작 순서와 완료 판정

A. 영상 근거와 소스 진단 → B. 홈 반복 제거 → C. viewport·카메라·지도 → D. 연속 조준발사·이동·자동/수동 전환 → E. 장비 그림·HUD 재질 → F. 브라우저 6화면·입력·회복·저장 회귀 → G. 실제 폰/태블릿 비교 → H. 부족한 최종 아트만 교체.

A–F가 코드와 자동 검증 범위다. G–H가 남으면 ‘구현 및 브라우저 검증 완료, 실기기/최종 아트 판정 대기’로 구분해서 보고한다. 화면이 크게 보이는 것만으로 게임 조작·그래픽 최종 완성이라 하지 않는다.
