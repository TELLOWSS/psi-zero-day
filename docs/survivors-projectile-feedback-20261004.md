# 장비별 발사 → 실제 접촉 → 잔여 효과 연결

상태: 구현 및 제한된 브라우저 검증 완료. Android 실기기·영화급 Final Art Lock 미완료.

## 적용 범위

기존 발사체 소재와 순수 TypeScript 엔진을 유지한다. 엔진이 발사·확정 접촉·소멸 사실만 별도 큐로 전달하고 UI가 이를 소비한다. 사람을 공격하는 연출로 바꾸지 않는다. 충돌 위치를 화면에서 추정하지 않으며 데미지·관통·수명·밸런스·저장 상태를 바꾸지 않는다. 발사음과 기존 치명타 hit stop은 기존 경로를 유지한다.

| 장비 소재 | 발사 / 접촉 / 잔여 효과 |
|---|---|
| 무전·위성 | 짧은 신호 전면 / 바닥 확인 파동 / 조용한 감쇠 |
| 소화기·극저온 | 기존 캐시 소재의 작은 분사 / 확장되는 접촉 구름 / 축소 잔여물 |
| 드론·진화 드론 | 방향성 점등 / 짧은 교차 접촉선 / 잔광 |
| 테슬라 | 짧은 아크 / 바닥 방향 접촉 아크 / 감쇠 |
| 전자기 | 작은 격자 전면 / 넓어지는 격자 / 감쇠 |
| 작업중지 | 압력파 시작 / 얇은 접촉파 / 감쇠 |
| 라바콘 | 승인 스프라이트 유지 / 바닥 접촉선 |

근로자 접촉은 녹색 확인 표시로 표현한다. 일시정지 중 새 효과의 시간이 진행하지 않고 재시작 때 효과를 비운다. 움직임 감소 설정에서도 작은 정적 확인 표시를 남긴다. 소멸은 충돌 완료와 자연 만료를 모두 처리하며 같은 발사체의 소멸 이벤트는 한 번만 발생한다.

## 혼잡 대응

- 엔진 사실 큐: 최대 192개. 초과하면 접촉 이외의 장식 사실부터 제거.
- UI 효과: 최대 64개. 접촉 반응 우선, 발사체·단계·24 단위 셀별 중복 완화.
- 발사체 90개 초과: 기존 소재의 세부 요소 감소, 별도 소멸 장식 생략.
- 기존 소재 캐시 재사용. 새 이미지 자산·엔진 교체·저장 구조 변경 없음.

## 검증 근거

- 전체 회귀: 202개 파일 / 1,083개 테스트 통과.
- 마지막 근로자 소멸 표시 보정 후 관련 6개 테스트 및 typecheck 재통과.
- production build 통과. 최종 보정 후 build 재실행 결과는 PR 검증 기록 참조.
- 새 검사 `scripts/verify-survivors-projectile-feedback.mjs`: 네 화면 크기의 실제 시작·이동·일시정지 확인 및 별도의 구성된 스트레스 장면 통과. 보고서: `qa/projectile-feedback-20261004/report.json`.
- 구성된 장면: 위험 180개 / 발사체 120개 / 180회 업데이트. 각 실행에서 확정 접촉 21,603건, 소멸 12,957건을 관측, UI 효과 최대 64개, pageerror 없음.
- CPU p95는 데스크톱 Chromium의 update+draw 측정값이다. 실기기 FPS·GPU 합성 시간·장시간 발열 인증으로 해석하지 않는다.
- 기존 `verify-survivors-browser.mjs`는 360×800 smoke를 통과했지만 다음 화면에서 패배 후 HUD를 조회하며 중단. 전체 기존 브라우저 게이트 PASS로 기록하지 않는다. 새 검사는 장시간 성장·궁극기·승리의 검증을 대신하지 않는다.

재현: Vite 서버가 같은 실행 환경에서 켜진 상태로 `CHROME_BIN=<Chromium 경로> node scripts/verify-survivors-projectile-feedback.mjs` 실행. 기본 URL은 127.0.0.1:4173. Playwright는 공용 런타임의 설치 경로를 사용한다.

## 다음 품질 게이트

1. Android WebView 실기기에서 Stage 20, 정상 성장으로 강화 장비 확보 후 10분 세로·가로 혼잡 플레이. 기기/OS/WebView 버전, 프레임 시간 p50·p95·p99, 메모리 증가, 발열, 일시정지·복귀·터치 취소를 기록한다. 60Hz 목표에서 p95 16.7ms 이내는 제안 기준이며 현재 합격 측정값이 아니다.
2. 미통과 장시간 브라우저 검사는 패배·레벨업·결과 전환을 인식하도록 검수 흐름을 보완하고 다시 실행한다.

4. 최종 자산과 현장음·발사음·접촉음·제한된 카메라 반응을 같은 플레이 영상에서 평가한 후 영화급 Production Lock을 판정한다. 이번 코드 효과만으로 Final Art를 승인하지 않는다.
