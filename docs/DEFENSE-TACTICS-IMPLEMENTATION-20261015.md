# 디펜스 우선 구현 — 현장 재구성·추천·장비 특화

2026-10-15 · 기준 기획: [통합 종합기획서](NEW-PSI-INTEGRATED-MASTER-PLAN-20261015.md) 8·10~13절.

## 구현 범위

사용자의 ‘디펜스 먼저 구현’ 지시에 따라 기존 `DefenseGame`을 직접 보강하고, 메인에서 **디펜스 · 현장 재구성**으로 기본 훈련에 진입하도록 연결했다. 새 캠페인·새 맵·PSI 공식·현장 안전 승인 기능을 만들지 않았다. 본편 스토리는 준비중을 유지한다. 훈련과 실제 현장 조치는 준비/전투/결과에서 구분한다.

기존 ramp-01 / 1000×600 / 8패드 / 10웨이브 / 초기 방호20·자원200 / 50ms / 비용·매각·위험 구성·장비 수치는 유지했다. 본편 사실과 훈련 클리어가 필요한 경사로 재구성 이벤트는 직접 요청으로 잠금을 우회할 수 없도록 보강했다.

## 플레이어가 달라지는 부분

- **추천 확인:** 현재/다가오는 위험, 은폐 신호의 사전 준비, 실제 경로의 대응 범위, 배치·개조의 비용 대비 효과로 후보를 계산한다. 추천은 장비를 공짜로 놓거나 자동 실행하지 않고 해당 패드의 준비 화면을 연다. 사용자가 표시된 비용을 확인하고 확정하면 기존 엔진 명령이 자원을 차감한다. 추천 외 장비·수동 배치도 유지한다.
- **성장 트리:** 표준형→현장 개량형→A/B 특화의 네 노드를 실제 장비 이미지와 연결선으로 보여준다. 현재 장착·완료한 단계·선택 가능한 성장·고르지 않은 경로를 구별한다. 공격 간격, 대응력, 장갑 무시, 범위/대상 수, 감속·탐지 유지시간을 콘텐츠의 실제 값으로 표시한다. 개조비와 누적 투자·잔여 자원을 분리했다.
- **다음 위험:** 화면 위의 짧은 띠에서 파 번호·종류·예정 수를 보여준다. 전투판 위의 긴 목록을 옮겼다. 최종 파에 ‘다음 파’가 다시 있다고 표시하던 문제도 수정했다. 은폐와 보스 방호20 소모/HP60% 장갑 변화는 진행 전에 안내한다.
- **계획과 몰입:** 세로 회전 강요 모달을 제거했다. 배치/개조를 살필 때 전투·파 사이 시간이 멈추며, 닫기만 해서는 재개하지 않는다. 재개/다음 웨이브는 명시적으로 누른다. 튜토리얼·무전·예고를 현장 밖 정보 영역으로 옮기고, 짧은 가로 화면은 지도 옆의 스크롤 패널을 사용한다.
- **정확한 터치:** SVG 지도와 HTML 패드 버튼을 같은 비율의 사각형에 맞췄다. 지도만 letterbox되고 터치 버튼이 다른 위치로 나뉘는 문제가 생기지 않도록 실제 화면 좌표를 검사한다. 장비 관리창에 원래 현장으로 돌아가는 버튼을 추가했다.
- **가로 장비 누락:** 기존 작은 가로 화면 CSS가 세 번째 이후 장비를 숨겨 CONTROL/SENSOR를 구매할 수 없었다. 네 종류를 모두 표시하고 스크롤로 접근하도록 수정했다. 처음 배치뿐 아니라 은폐가 등장하는 후반까지 실제 플레이해 확인한다.
- **결과:** 사용한 배치·특화, 놓친 위험 유형, 다음에 검토할 장비를 정리한다. 재도전/허브 복귀를 보존하고, 훈련의 성공을 실제 안전 확인으로 표시하지 않는다.

## 함께 고친 정합성·저장 문제

1. **첫 진입 탭 잠금:** React StrictMode의 폐기되는 첫 mount가 잠금을 먼저 가져가 자기 자신을 ‘다른 탭’으로 막는 문제가 실제 브라우저에서 드러났다. 폐기된 mount는 비동기 잠금을 시작하지 않도록 바꿨다. 실제 두 번째 탭의 중복 수정 차단은 유지한다.
2. **비상정지:** 3.5초 효과·28초 재사용 대기라는 기존 의도를 순수 엔진과 세이브에 반영했다. UI ref만 초기화해 재접속으로 연속 사용하던 경로를 막고 즉시 저장한다. 선택 필드로 확장해 구버전 세이브도 읽는다. 과거 저장에 없던 남은 대기시간까지 추측해 복원하지 않는다.
3. **보상 표시:** 결과 렌더링 effect가 반복해 `psi.fieldguide.points`를 올릴 수 있었고, 패배 화면도 지급하지 않은 FG를 표시했다. 이 비정규 경로와 잘못된 안내를 제거했다. 이미 보유한 FG를 차감하지 않는다. 기존 정식 결과 정산·최초 클리어/3별 장식 보상과 중복 방지 기록은 보존한다.
4. **키보드:** 버튼·링크·선택 요소에 포커스가 있을 때 전역 Space/Enter가 기본 클릭과 중복 실행되지 않게 했고 키 반복도 제외했다.
5. **세계관:** 윤성호를 현장 총괄 소장으로 부르던 무전을 현재 캐릭터의 이름·역할과 연결했다. 과장된 실재 현장 ‘시간 정지’ 대신 훈련의 대응 일시 정지로 안내한다. 이전 ‘워치만 플레이 가능’ 안내도 실제 진입 가능한 모드에 맞췄다.

## 아트와 기술 경계

현재 승인된 디펜스 현장·장비·인물 자산을 재사용했다. 이번 작업으로 새 AI 원화/최종 아트를 만들었다고 계산하지 않는다. 트리는 실제 해당 티어의 자산을 표시하며 기능이 없는 가짜 장비를 추가하지 않았다. 고품질 최종 후보 교체와 사람의 최종 시각 승인은 별도다.

추천은 `src/app/defense-tactics.ts`의 읽기 전용 투영이다. Build/Upgrade/Sell/UseSupport와 승패·자원·공격 판정은 기존 순수 엔진이 소유한다. 새 서버/결제/광고/클라우드 저장·전체 세이브 통합은 없다. 새 UI 문구는 `content/localization/defense-tactics-ko.json`의 text_id로 표시한다.

## 검증과 증거

자동 회귀·타입·완성 빌드, 실제 Chrome 화면/정상 플레이 결과는 [검증 기록](qa/defense-tactics-20261015/verification.md)에 정리한다.

- 엔진에서는 COORDINATOR/OBSERVER 각각 추천·정상 구매·지원만 사용해 10파를 완주한다. 승리/방호/자원/적 상태를 주입하지 않는다.
- 브라우저는 허브→지원 선택→추천→실구매→L2→검토 중 정지→닫아도 정지 유지→허브 복귀→저장 이어하기를 세로390×844·가로844×390·PC1440×900·작은 세로320×568·작은 가로568×320에서 검사한다.
- 별도 완주 스크립트는 정상 UI 버튼으로 구매·개조·지원·파 시작을 수행한다. 시간을 빠르게 실행하는 Playwright clock을 사용하며 전투 상태를 만들거나 수정하지 않는다. 사람의 실제 손 조작/재미/기기 성능 측정은 아니다.
- PC에서 같은 저장을 공유하는 두 번째 탭이 차단되는지, 이미 로드한 훈련이 네트워크 없이 계속되는지 확인한다. 서비스워커를 통한 웹의 최초/재접속 오프라인 실행까지 새로 구현한 것은 아니다.

재현 명령: `npm run typecheck`, `npm run build`, `npx vitest run --maxConcurrency=4`. 브라우저용 `scripts/verify-defense-tactics.cjs`, `scripts/play-defense-tactics.cjs`는 실행 중인 완성 빌드를 대상으로 한다. `PSI_PREVIEW_URL`(기본 localhost:4176), `PSI_PLAYWRIGHT_MODULE`, `CHROME_BIN`을 환경에 맞게 지정한다. 실행 증거는 `docs/qa/defense-tactics-20261015/`에 기록한다.
