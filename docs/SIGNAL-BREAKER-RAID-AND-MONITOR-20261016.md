# 시그널 브레이커 레이드 전투와 보스 모니터 구현

2026-10-16. Director가 첨부한 `PSI_SIGNAL_BREAKER_RAID_BOSS_SYSTEM_2.0_20261016.docx`와 이어진 보스 공략 보조 요청을 구현한다. 대상은 기존 EP01~EP03의 15개 작전이다. CH16~20과 본편 50보스는 추가하지 않는다. 아래 수치와 동작은 구현 기준이며 재미·Android 실기기 품질 승인을 뜻하지 않는다.

## 전투 설계

전투 판정은 기존 독립 브레이커 엔진의 순수 JavaScript 모듈이 소유한다. UI는 입력을 전달하고 스냅샷을 읽는다. 기존 엔진과 동일한 배포·CommonJS 테스트 형식을 유지했으며 React와 저장소를 전투 모듈에 넣지 않았다.

`INTRO → OBSERVE → WARNING → STAGGER → BURST → TRANSITION`을 기본 흐름으로 사용한다. 실패하면 `RECOVERY`에서 다시 예고하며 체력을 초기화하지 않는다. 후반에는 `SUPPORT`와 순차 대응을 추가한다. 경고가 확정되기 전 입력, 지속 중인 앵커·미스트·스캔 효과는 새 대응 성공으로 인정하지 않는다.

| 보스 | 실제 입력·충돌로 인정하는 대응 | 후반 변화 |
|---|---|---|
| 반입 차단문 | 경고 구역 이탈 후 반사한 발사체의 본체 명중 | 방향 전조, 연속 대응, EP03 보조 코어 |
| 컨베이어 | 실제 경고 이후 벨트 정지 또는 방향 전환 | 최초 방향을 다시 읽고 다른 방향으로 조작 |
| 집진 필터탑 | 실제 경고 이후 흡입부에 미스트 발사체 명중 | 방향 확정 대기, EP03 보조 코어 |
| 장력 드럼 | 실제 장력 신호 이후 앵커가 레일과 충돌하며 잠금 | P2 보조 코어, 상위 난도·EP03 순차 대응 |
| 가설 전력 | 실제 경고 이후 본체 주변 회로에 스캔 도달 | 순환 위험 구역, P3 회피와 두 차례 대응 |

각 페이즈는 70% / 35% / 0% 체력 하한을 가진다. 대응 미성공 상태의 공격은 하한을 넘지 못하며 마지막 페이즈에서도 1HP를 남긴다. 한번의 과도한 피해로 여러 페이즈를 건너뛰지 않는다. 초과 피해의 일부는 최대 체력 15% 한도의 브레이크 압력으로 전환한다. 약점창에서는 1.5배 기본 피해 보상과 최대 0.15배 압력 보상을 주며 초과 피해 전체를 일괄 방출하지 않는다.

스토리 / 표준 / 베테랑 / 악몽의 실제 경고 창은 2.0 / 1.8 / 1.5 / 1.3초, 약점창은 5.5 / 5.0 / 4.2 / 3.5초다. 후반 방향 판독 전조는 별도 0.65초이며, 실패 후 재예고는 5.5~7초다. 보스 전투에서는 기존 웨이브 제한시간 패배를 적용하지 않아 필수 기믹 도입과 제한시간이 충돌하지 않게 했다.

## PSI 보스 모니터 기획

사용자가 언급한 SBM은 문맥상 DBM 계열 보스 경보를 뜻하는 것으로 해석했다. 참고한 기능은 다음 패턴 시간, 개인 위험 경고, 즉시 필요한 행동을 읽기 쉽게 전달하는 원리다. [DBM 공식 저장소](https://github.com/DeadlyBossMods/DeadlyBossMods)의 코드·문구·음원·아이콘·UI를 복사하지 않았다.

1. **전체 안내:** 전조 대기 → 지금 이동 → 대응 장비 → 보조 코어 → 집중 공격을 현재 상태에 맞춰 하나씩 안내한다.
2. **핵심 경고:** 플레이어가 실제 위험 구역에 있을 때의 이동 경고만 표시한다.
3. **끄기:** 보조 안내만 숨긴다. 기본 전투 경고와 판정은 그대로 유지한다.

모니터는 읽기 전용 스냅샷과 플레이어 위치로 메시지를 계산한다. 조준·이동·장비 사용·기믹 해제 입력을 대신하지 않고 난도·피해량도 바꾸지 않는다. 카운트다운은 브라우저 타이머가 아닌 시뮬레이션 시간을 따른다. 위험 경고를 일반 준비 메시지보다 우선한다. 색 외에도 문구·방향 화살표·고정 해칭을 사용하며, 동작 감소에서도 정보가 사라지지 않는다.

기본 경고음은 자체 합성음이다. 선택형 음성은 기기에 설치된 한국어 음성만 사용한다. 해당 음성이 없으면 문자·경고음을 사용한다. 일시정지 시 재생 중인 음성은 취소하고 예약 안내가 한꺼번에 나오지 않게 한다. 모니터 경고가 발생하면 BGM을 잠시 낮추며 기존 전체 음소거를 따른다. 설정은 기존 로컬 저장에 추가한다.

## 도감과 훈련

도감은 미조우 / 관찰·부분 해독 / 공략 성공으로 구분한다. 최초 플레이 전에는 보스 위험 특성만 읽을 수 있고, 실제 경고를 본 페이즈만 훈련 목록에 나타난다. 훈련에서는 0.75배속·1배속과 무적 연습을 선택한다. 선택한 페이즈만 연습하며 이후 미조우 페이즈로 진행하지 않는다. 훈련 엔진에는 캠페인 기록·보상·숙련도·체크포인트를 발급하지 않는다.

실전 결과에는 대응 성공·실패 횟수, 약점창 피해 비중, 마지막 놓친 패턴과 다음 대응을 표시한다. 3회 이상 실패 시 연습·스토리 난도 선택을 안내하되 자동으로 변경하지 않는다. 난도별 기록은 별도로 보관하며 첫 공략의 칭호는 전투력에 영향을 주지 않는다. 이 기록을 실제 근로자 위험성평가 지표와 혼합하지 않는다.

## 저장과 오프라인

기존 캠페인 기록·재화·장비 저장은 유지하고 `raidMastery`, `settings.raidDifficulty`, `settings.raidMonitor`를 추가한다. 새 전투 체크포인트는 `raidVersion: 2`를 기록한다. 해당 필드가 없는 예전 체크포인트는 예전 전투로 복원한다. 완료 기록은 실행 ID로 중복 집계를 방지한다. 새 모듈과 CSS는 전용 서비스 워커의 필수 오프라인 목록에 넣고 캐시 버전을 변경했다.
