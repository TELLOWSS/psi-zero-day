# TASK-008G — Instruction Cascade / 전달 왜곡

## 목표
안전한 원지시가 존재했다는 사실과 실제 작업자가 같은 지시를 받았다는 사실을 구분한다.

## 현장 상황
1. 이재훈 공사대리: `안전대 설치 확인 후 작업` 지시.
2. 강태식 반장: 같은 안전조건을 전달하면서 `오늘 물량을 빨리 끝내라`는 일정 압박을 함께 전달.
3. 작업조 전달 과정: 안전조건은 빠지고 긴급한 생산문구가 강조됨.
4. 임준호: `빨리 마감하라`는 말만 듣고 작업.
5. 사후에는 각 단계가 자신이 한 말만 근거로 책임을 설명함.

## 플레이어 선택
- `instruction_accept_top`: 원도급/공사팀 원지시가 정상이라는 사실을 중심으로 작업반 전달 문제로 닫는다.
- `instruction_blame_worker`: 마지막 작업자의 지시 미준수로 정리하고 재교육한다.
- `instruction_reconstruct_chain`: 공사팀 → 반장 → 작업조 → 근로자의 실제 전달문구와 시각을 대조한다.

## 후속 결과
- `condition_loss_unresolved`: 원지시는 맞지만 전달경로의 조건누락 원인은 남아 재발 가능.
- `worker_blame_hides_chain`: 최종 작업자 책임으로 닫히며 다음 모호한 지시에 대한 질문·보고가 위축.
- `conditional_phrase_restored`: `안전대 설치 후` 조건이 작업조 전달 단계에서 사라졌음을 재구성.

## 설계 원칙
- 누구 하나를 자동 거짓말쟁이로 만들지 않는다.
- 의도와 실제 수신 내용을 구분한다.
- 일정 압박 문구가 안전조건보다 더 강하게 전달될 수 있음을 표현한다.
- 마지막 작업자 개인책임으로 끝내는 선택도 가능하지만 그 선택은 보고문화에 후속비용을 남긴다.
- 공식 안전지시가 존재했다는 기록만으로 실제 현장 전달 완료를 증명하지 않는다.

## 엔진 경계
기존 event condition / flag / relationship / player-stat primitive만 사용한다. `src/engine/*` 규칙이나 PSI 공식은 수정하지 않는다.
