# 다음 작전의 현장 변화와 스토리·디펜스 연계

## 구현 범위

인계가 설명으로 끝나지 않도록 세 곳의 기존 실행 경로에 연결했다. 공개 메인의 스토리·디펜스 준비중 게이트는 유지한다. 새 캠페인, 무료 능력 보너스, 증거 자동 획득, 직업·진로 공식은 추가하지 않는다.

1. **다음 슈팅 작전:** STAGE12에서 실제 잔해를 정리하고 작전을 완료하면 STAGE13의 반입 통로 잔해가 제거된 상태로 시작한다. 같은 좌표의 연속 맵이라는 의미가 아니라 다음 작업 구역의 수신 통로에 반영하는 시범 규칙이다. 기존 정리 완료 바닥 표시를 사용한다. 실제 이동·돌진·투사체 충돌 검사에 hp=0 상태가 반영된다.
2. **본편 스토리:** 실제 전략 행동 패널의 순찰 인계함에서 현재 활성화된 진입·경사로·출입 통로 확인 또는 현장 확인 행동을 추천한다. 기록을 선택하고 추천을 누르면 기존 실행 확인 카드가 열린다. 최종 실행은 기존 `choose_event` 명령과 세션 revision 검증을 사용하며 기존 시간·결과·선택 기록을 따른다. 현재 선택할 수 없는 행동을 새로 만들지 않는다.
3. **실제 디펜스:** READY/INTERMISSION에서 인계함을 열면 정리·제동 기록은 CONTROL, 통제 구역 기록은 SENSOR 배치를 제안한다. 사용 가능한 장비와 빈 패드만 대상으로 하고 비용·보유 자원을 보여준다. 클릭은 기존 `Build` 명령·지속 저장 경로를 사용한다. 실제 자원이 차감되며 같은 종류가 이미 배치됐거나 전투 중이면 추가 추천을 하지 않는다. INTERMISSION에서 열면 기존 `SetPaused` 명령으로 자동 다음 웨이브를 멈춘다. 닫는 것만으로 재개하지 않으며 배치를 마친 뒤 기존 재개 버튼을 사용한다.

## 기록과 재시도

기존 버전1 인계에 선택 필드 `clearedTerrainIds`를 추가했다. 이전 저장의 수치 기록은 그대로 읽지만 장애물 ID가 없는 기록으로 물리 현장을 바꾸지는 않는다. 완료 결과에서 실제 hp가 0인 잔해만 기록하며 다음 작전에서 넘겨받은 잔해는 새 정리 증거에서 제외한다.

STAGE12의 마지막 유효 인계만 사용한다. 그 기록이 실패면 이전 성공 기록을 되살리지 않는다. 정리 횟수보다 많은 ID, 중복·비정상 ID는 거부한다. 다른 구역과 임의 장애물 ID는 시범 연계 대상이 아니다. 재시도해도 정리 횟수·보상·선물을 추가 지급하지 않는다. 저장 불가 환경은 기존 offline-first 예외 처리를 따른다.

## 검증

- `tests/operation-handoff-bridge.test.ts`: 실제 초기 상태·잔해 충돌 변화, 재시도 불변, 인계 중복 보상 방지, 구버전·실패·잘못된 ID, 현재 가능한 행동만 추천, 실제 EpisodeSession 명령·선택 기록·중복 거부, 실제 디펜스 비용 차감·인계 열람 중 대기 정지 검사.
- `tests/verify-handoff-bridge.mjs`: PC 1440×900 / 모바일 390×844 / 가로 844×390. 컴포넌트 fixture에서 실제 전략 확인 패널의 확인 전 미실행, 실제 디펜스 엔진의 비용 차감, 원본 인계 저장 불변, 가로 넘침과 브라우저 오류를 검사한다. 스토리 버튼의 fixture 선택은 합성 행동이며 본편 자연 완주로 계산하지 않는다.
- 같은 브라우저 검사에서 저장된 STAGE12 인계를 읽고 **실제 앱으로 STAGE13을 선택·시작**해 잔해 hp=0, 새 정리 횟수=0과 인계 표시를 확인한다. 구역 해금과 원본 인계는 QA에서 지정한다. 자연 전투 성과 또는 실제 현장 경험자의 몰입도 검증은 아니다.
- 기존 `verify-survivors-operation-story.mjs`의 36개 표시 조건, 실제 STAGE12의 두 정비 일시정지·결과 저장 회귀도 통과했다.
- 로그·스크린샷: `artifacts/handoff-bridge/`, `artifacts/handoff-bridge-tests.log`, `artifacts/handoff-bridge-build.log`, `artifacts/operation-story/report.json`.
- 최종 전체 회귀 **1,939개 통과 / 기존 1개 건너뜀**. 타입 검사·프로덕션 빌드 통과, 기존 500kB 초과 청크 경고 유지. 세 화면의 브라우저 검사 오류·가로 넘침 없음.

## 남은 경계

현장 연속성을 정의하지 않은 다른 구역에 같은 장애물 ID를 일괄 전파하지 않는다. 전체 구역의 연계 확대에는 구역별 수신 통로 정의가 필요하다. 본편·디펜스 공개 진입과 자연 플레이·실기기 체감 검수는 별도 출시 검토 대상이다. 이번 작업은 로컬 구현이며 GitHub/Vercel 재배포를 수행하지 않았다.
