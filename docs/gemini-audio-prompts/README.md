# Gemini 독립 오디오 프롬프트 패키지

2026-10-05 공식 문서 확인 기준. 각 번호 파일에 게임 설명과 출력 조건이 들어 있어 새 대화에서도 그 파일의 코드 블록 하나만 사용할 수 있다. 24개를 한 번에 요청하지 않는다.

## 먼저 알아둘 차이

- Gemini 앱: 입력창 도구의 **음악 만들기**를 선택한다. 보컬 없음 옵션을 선택하고 BGM은 긴 트랙, 짧은 음악 큐는 짧은 트랙을 사용한다. 계정/모델별 실제 메뉴와 길이 옵션을 우선한다.
- 다운로드: 생성 결과의 다운로드 메뉴에서 **오디오 전용 MP3**를 선택한다. 표지 포함 MP4가 아닌 음원을 전달한다. 앱이 WAV·멀티 스템·밀리초 길이·완벽한 루프를 지원한다고 가정하지 않는다.
- Lyria는 음악 생성이다. TTS는 말할 내용을 음성으로 만드는 기능으로 독립 효과음을 만드는 경로가 아니다. 순수 분사·발소리·도킹 Foley 지원은 아래 공식 음악/TTS 문서에서 확인되지 않아 별도 효과음 도구 경로로 분리했다.
- 음악 큐 05–09는 잘라 쓸 후보를 생성하는 실험적 제작 방식이다. 긴 음악 전체에서 정확한 2초 효과를 얻는 보장은 없다. 두 차례 시도에도 잘라 쓸 구간이 없으면 전문 제작으로 넘긴다. 텍스트/코드 응답은 음원 완성이 아니다.
- WAV 변환은 편집·연결용 작업일 뿐 MP3의 손실 정보를 복원하거나 원본을 24bit 고음질 녹음으로 만드는 작업이 아니다.

## 순서

1. **02 기본 순찰** 한 개를 먼저 생성하고 음색을 승인한다. 기존 foundation 음원을 유지하려면 이 단계는 생략한다.
2. 같은 색감이 필요한 01/03/04를 각각 생성한다. 이전 대화 기억에 의존하지 말고 각 파일의 독립 프롬프트를 사용한다. 필요하면 허용되는 현장 스크린샷을 함께 첨부한다. 정확한 동기 재현이나 오디오 참조 업로드 지원은 보장하지 않는다.
3. 05 진화, 06 궁극기 효과, 07 보스 경고, 08 성공, 09 실패를 한 개씩 생성한다. 승인된 소장 실제 목소리는 새로 만들거나 복제하지 않는다.
4. 10–24는 순수 효과음/환경음 지원 도구에 전달한다. Gemini가 지원하지 않는다고 답하면 억지로 음악 생성으로 우회하지 않는다. Gemini는 제작 브리프를 이해하는 역할로만 사용한다.
5. 파일을 번호와 이벤트명으로 구분해 전달한다. 후보 청취·편집·실제 재생 연결은 별도 단계다. 생성물의 이용 조건과 출처 기록을 보존하고 모델의 권리 확약을 증거로 삼지 않는다.

## 한 개 생성 후 변형 요청

```text
방금 생성한 한 이벤트의 B 변형을 하나만 생성하라. 이 대화의 게임 설명과 이벤트 역할을 유지하고 길이·어택·체감 크기는 A와 비슷하게, 질감의 미세한 부분만 바꾼다. 다른 이벤트나 음악을 추가하지 않는다. 이전 파일을 실제로 참조할 수 없다면 그대로 재현했다고 주장하지 않는다. 실제 오디오 생성 기능이 없으면 그 한계를 먼저 밝힌다.
```

## 수정 요청

```text
같은 한 이벤트를 다시 생성하라. 장면과 게임 설명은 유지한다. 현재 결과의 문제는 [들리는 실제 문제 한 개]다. 바꿀 조건은 [구체적인 한 조건] 하나뿐이다. 나머지 음색과 에너지는 최대한 유지하되 정확한 동일 파형 재현을 보장하지 않는다. 다른 이벤트·보컬·대사를 추가하지 않는다. 실제 오디오 결과를 제공하라.
```

## 검수와 게임 연결

기존 제작 명세의 이벤트 매핑을 유지한다. 새 음원은 CANDIDATE로 입고하고 실제 파일의 길이·피크·무음·루프·모노 호환성·권리 기록을 확인한다. 루프 경계와 짧은 큐의 자르기는 후편집 대상이다. 승인 뒤 기존 4개 버스·반복 제한·공간 처리·음성 우선순위에 연결한다. 이번 패키지 자체는 음원 생성/청취 승인/런타임 교체를 뜻하지 않는다.
