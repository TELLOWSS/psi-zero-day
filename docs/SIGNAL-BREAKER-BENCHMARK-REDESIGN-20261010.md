# 시그널 브레이커 — 벤치마킹 기반 화면·아트·UX 재설계 기획서 v3

## 1. 이번 재기획의 결론

전체화면 API를 켜는 것은 몰입형 화면의 완성이 아니다. 하나의 현장 안에서 배경·발판·캐릭터·장치가 같은 원근과 배율로 보이고, 플레이어가 판단해야 할 경로가 UI에 가려지지 않아야 한다. 이번 첨부 화면은 이 기준에서 **시각 품질 재검수 FAIL**이다. 이전 자동 테스트 통과를 미술·게임 경험의 통과로 해석하지 않는다.

핵심 재미는 **관찰 → 직접 각도 조절 → 직접 발사 → 반사·장치 반응 → 회수 → 다음 경로 판단**이다. 이동 방향을 바꾸면 조준 방향만 함께 반전하고 직접 정한 상향 각도를 유지한다. 자동 표적 추적·무입력 발사는 도입하지 않는다.

완성 목표는 산업 현장의 재료감과 깊이가 살아 있는 수동 물리 아케이드다. UI는 판단에 필요한 최소 정보만 제공하고, 현장 장치의 실제 변화가 진행을 알려야 한다.

소스 확인 결과:

- `src/app.js`의 `draw()`는 화면을 채우는 배경용 `backdropScale`과 게임 객체용 `camera.scale`을 별도로 사용한다. 특히 세로 기본 시야에서 `background()`는 같은 월드 변환의 배경을 생략한다. 따라서 배경 건축물과 게임 객체의 공간 대응을 보장하지 못한다.
- `src/premium-art.js`의 `background()`는 원본 그림을 바닥 경계에서 잘라 각각 다른 높이로 재배치한다. `underfloor()`도 남은 하단을 추가 밴드로 그린다. 붙인 느낌·바닥 비율 차이가 생길 수 있는 구조다.
- 현 맵 5장 원본은 1672×941이다. 크게 보이는 것과 고해상도인 것은 다르다. 기존 DPR 캐시 확대는 새 디테일을 만들지 않는다.
- `updateCamera()`는 주로 플레이어 위치와 화면 비율을 사용한다. 조준 표적·첫 반사점·보스 노드를 함께 보장하는 시야 계약이 없다.

이 항목은 구현 원인과 시각 증거의 대응이다. 합성 구조를 수정하지 않고 새 그림만 연결하는 처방으로 종료하지 않는다.

## 4. 화면과 카메라 — 하나의 현장 계약

### 4.1 공간 계약

물리 월드 `1100×620`, `GROUND=536`과 실제 충돌 좌표는 유지한다. 현장 구조물·보행 바닥·장치·캐릭터는 같은 월드 카메라 변환을 사용한다. 원경/중경의 패럴랙스는 허용하되 장치가 연결된 기둥·벽·바닥은 패럴랙스하지 않는다.

화면 밖 공간은 같은 현장의 확장 아트로 채운다. 하나의 맵을 두 배율로 겹치거나 수평 띠를 늘려 채우지 않는다. 바닥을 이미지 퍼센트로 잘라 정렬하지 않고, 제작 시작부터 월드 기준선과 앵커를 별도 메타데이터로 맞춘다. AI 결과에 충돌 좌표를 맡기지 않는다.

### 4.2 세로 모드의 실제 제약과 해결

390×844에서 가로 1100 월드를 전부 넣으면 1월드px당 약 0.355CSSpx다. 기존 60월드px 캐릭터는 약21CSSpx로 작아진다. 전체를 크게 보이게 하면서 동시에 가로 맵 전부를 한 세로 화면에 넣는 것은 불가능하다. 이 제약을 흐린 확대 배경과 큰 미니맵으로 숨기지 않는다.

세로는 **판단에 필요한 구간을 크게 보여 주는 카메라 + 필요할 때 전체 경로 확인**을 기본으로 한다. 배경은 화면 끝까지 이어지며 게임을 작은 액자에 넣지 않는다.

| 화면 상태 | 시야 규칙 | 입력·가독성 조건 |
|---|---|---|
| 준비 | 임무 관련 장치·목표가 모두 들어오는 넓은 시야 | 소개 후 현재 조작 시야로 부드럽게 이동 |
| 이동 | 플레이어 앞쪽 60%, 뒤쪽 40%의 시야 배분을 초기 후보로 적용 | 좌우 방향 전환 때 급격한 카메라 점프 금지 |
| 조준 | 플레이어·조준점·첫 유효 반사점의 합집합에 여백 추가 | 조준점은 직접 입력값. 목표를 자동 선택하지 않음 |
| 발사 | 발사 시 카메라를 고정하고 투사체가 안전 영역을 벗어날 때만 완만히 추적 | 손가락 아래 좌표가 카메라 이동 때문에 바뀌지 않도록 드래그 시작 변환 고정 |
| 보스 | 현재 필수 노드와 다음 노드, 플레이어가 보이는 범위 확보 | 핵심 노드를 화면 밖으로 잘라 놓은 채 안내만 표시하지 않음 |
| 전체 경로 확인 | 두 손가락 축소 또는 44px 시야 버튼으로 전체 범위 확인 | 축소 중 물리 시간 정지, 입력 종료 시 이전 시야 복원. 카메라 UX 변경이며 정답 제공 없음 |

조준 합집합이 너무 넓으면 전체 경로 확인으로 연결하고, 조작 캐릭터의 최소 표시 높이 40CSSpx 후보를 우선한다. 밖에 있는 선택적 장치는 방향+거리 표식으로 알린다. 이번 샷에 필요한 반사점·노드는 기본 시야 또는 전체 경로 확인에서 완전히 보여야 한다. 화면 가장자리에서 장치를 반만 보여 주는 것은 의도적 정보 전달로 인정하지 않는다.

가로/태블릿은 가능한 한 전체 판단 구간을 한 번에 보여 준다. 기기 회전은 샷·각도·상태를 보존하며 활성 포인터만 안전하게 해제한다. 노치·홈바·브라우저 동적 높이를 반영한다.

## 5. HUD·조작 UI 재설계

### 5.1 상시 표시 / 상황 표시 / 정지 메뉴

| 계층 | 구성 | 명세 |
|---|---|---|
| 상시 HUD | 작전명, 회수 진행, 실드, 일시정지 | 세로 상단 48~56CSSpx, 가로 44~48CSSpx. 전체 폭 불투명 패널 금지 |
| 상시 조작 | 이동·각도 패드, 직접 발사, 장비 2슬롯 | 하단 엄지 영역에 배치. 캐릭터·첫 반사점 안전 영역 밖 |
| 조준 중 | 현재 각도, 짧은 예측선 | 패드 위 각도 표시. 손을 떼면 작은 표시로 축소 |
| 연쇄 발생 | 연쇄 수, 남은 창 | 1~2초 피드백과 작은 링/바. 큰 CHAIN COMBO 하단 패널 제거 |
| 상황 발생 | 게이트 개방 시간, 안정화 누적, 다음 노드 | 해당 장치에 붙는 작은 상태. 화면 중앙 상시 문장 없음 |
| 정지 메뉴 | 메인화면, 설정, 전체화면, 조작모드, 장비 자동전환, 도움말 | 일시정지 한 곳에서 접근. 플레이 중에는 큰 설정 버튼 제거 |
| 전체 경로 | 축소 시야/접근성용 미니맵 | 기본 미니맵 숨김. 색 점만으로 의미를 전달하지 않음 |

제안 크기(CSSpx): 발사 72~88, 장비 슬롯 48~56, 이동 패드 외경112~136, 보조 입력44~48. 실제 도달 범위로 조정한다. 시각 아이콘이 작아도 터치 영역은44이상이다. 기기 safe-area 안쪽에 12px 이상 간격을 확보한다.

방호판 각도·벨트 방향·끌기는 플레이에 필요한 수동 입력이므로 삭제하지 않는다. 현재와 같이 큰 버튼 3개를 캐릭터 높이에 나열하지 않고, 선택 장비의 보조 조작 1줄로 묶어 하단에 둔다. 관련 장치가 없으면 숨긴다. 버튼 합치기로 두 동작이 동시에 실행되지 않게 한다.

### 5.2 시각 언어

- 정보 색: 민트=회수/조준, 황금=발사/활성, 주황=위험, 보라=전력. 상태는 색과 형태/숫자를 함께 사용한다.
- 큰 둥근 사각형 반복을 폐기한다. 얇은 상태 바, 명확한 장비 실루엣, 절제된 산업 계기 재질을 사용한다.
- 텍스트는 한국어 중심. 작은 장치 글씨·잘리는 장비명·불필요한 영문/한글 중복을 제거한다.
- 글자와 정보 패널은 대비4.5:1 후보 기준으로 검수하고 배경 위에 직접 놓는 글자에는 국소 명암을 적용한다.
- 장비 아이콘은 동일 광원·크기·원근의 단독 실루엣으로 제작한다. 배경 장치와 같은 재료 세대를 사용한다.

## 6. 안내 UX — 읽는 패널에서 반응하는 장치로

최초 진입에는 안전한 연습 샷 한 번을 제공한다. 짧은 안내는 동시에 한 개, 최대 두 줄·문장당12~18자 후보다. 기본 노출2.5초, 입력 완료 시 즉시 퇴장. 접근성 설정에서 다시 보기와 긴 표시를 제공한다. 설명을 읽는 동안 위험 진행은 정지한다.

| 기존 안내 | 새 화면 표현 | 상세 설명 위치 |
|---|---|---|
| 충격·분리·큰 코어는 분리 후 회수 필요 | 큰 코어 파편 표식 → 분리 시 작은 코어로 실제 변화 | 첫 등장 연습/정지 도움말 |
| 분진·전력 안정화·0.75초 체류 필요 | 대상 주위 안정화 링과 짧은 ‘안정화 중’ 표시 | 장비 선택 도움말 |
| 회로를 읽고 릴레이를 순서대로 타격 | 다음 노드만 또렷한 번호/윤곽, 스캔 후 연결 순서 표시 | 작전 시작 한 줄 |
| 게이트 대기 | 게이트 개폐 동작, 남은 시간1자리, 작은 잠금 기호 | 최초 닫힘 시 설명 |

실패 설명은 엔진 이벤트의 실제 실패 원인만 사용한다. ‘아직 안정화되지 않음’, ‘게이트가 닫힘’처럼 다음 행동에 연결한다. 이미 잘 수행한 행동을 반복 교육하지 않는다. 장치 라벨이 코어·예측선과 겹치면 라벨을 이동/생략하고 상황 정보는 작은 HUD 슬롯으로 전달한다.

준비 화면은 전체 블러+큰 중앙 카드 대신 현장 위 짧은 제목/목표/시작 바를 사용한다. 대원 외형과 고급 설정은 펼침으로 둔다. 첫 챕터·LAB·기존 시험판은 한 번의 모드 선택에서만 노출한다. 결과는 회수량·핵심 명중 피드백과 재도전/다음 두 행동을 우선한다.

## 7. 미술 제작 — 고화질보다 먼저 같은 공간

### 7.1 자산 납품 계약

| 자산 | 납품 기준 | 금지 |
|---|---|---|
| 현장 레이어 | 원경, 중경, 플레이 구조, 전경을 실제 분리. 동일 소실점·광원·수평 기준 | 한 장 이미지 반복 확대, 바닥 띠 왜곡, 장치가 그려진 배경과 실제 장치 중복 |
| 고정 구조/발판 | 월드 기준 앵커·보행선·장치 고정점·광원 방향 메타데이터 | 생성 그림에 맞춰 충돌 판정 이동 |
| 장치 | 방호판·완충·자석·게이트·릴레이·보스 각 단독 투명 자산, 정지/활성/충돌 상태 | 아틀라스 이웃 셀 흔적, 잘린 그림자, 붙인 스티커 같은 무접촉 배치 |
| 캐릭터/장비 | 기존 정체성 유지, 맵 광원에 맞춘 림라이트·접촉 그림자·반동 상태 | 맵만 새 세대, 구형 장비/인물 혼합 |
| FX | 반사·분리·회수 서로 다른 형태/색/소리, 궤적을 가리지 않는 크기 | 전면 백색 플래시·긴 화면가림 |

제작 원본은 전체 현장 등가3840×2160 이상을 목표로 하되 **실제 반환 크기와 세부 선명도**를 확인한다. 단일 파일이 이 크기를 지원하지 않으면 독립 레이어와 실제 고해상도 타일로 제작하고 경계를 원본 단계에서 검수한다. 단순 보간 확대를 네이티브4K로 기록하지 않는다.

런타임은 1x/2x 레이어 또는 타일을 선택한다. 플레이 구조/장치는 최대 사용 확대에서 원본 1px보다 큰 화면 픽셀로 늘리지 않는 것을 목표로 한다. 원경의 의도적인 대기 원근은 예외지만 전경의 흐림을 원경 연출로 설명하지 않는다. 저사양은 장식/FX부터 줄이고 각도·목표·장치 윤곽을 보존한다.

### 7.2 한 세대의 현장 스타일

건설현장 재료(강재, 콘크리트, 전선, 먼지)를 명확히 구분한다. 배경의 명암·채도는 플레이 장치보다 낮게, 위험 코어는 형태와 제한된 발광으로 식별한다. 접촉 그림자·장치 브래킷·전선 연결로 설치 이유를 보이게 한다. 원경 크레인과 전경 장치의 원근이 같은지 별도 판정한다.

CH-01 대표 장면에서 맵+장치+캐릭터+UI가 함께 통과한 뒤 나머지 맵에 적용한다. 다섯 맵을 먼저 양산해 같은 합성 오류를 반복하지 않는다. 기존 이미지는 롤백으로 보존하되 최종 품질 완료 수에 포함하지 않는다.

## 8. 지루함을 줄이는 5개 작전 리듬

기존 장치와 규칙을 중심으로 배치·소개·피드백을 고도화한다. 새 장치 이름을 늘리는 것으로 해결하지 않는다. 수치 변경과 새로운 콘텐츠는 별도 구현 범위에서 검토한다.

| 작전 | 플레이 질문 | 도입 → 응용 → 마무리 | 현장 반응 |
|---|---|---|---|
| CH-01 반입 | 어느 각도로 첫 반사를 만들까? | 안전한 첫 반사 → 완충을 이용한 경로 → 한 번의 연쇄 | 방호판 충격·회수 통로 활성 |
| CH-02 컨베이어 | 움직이는 완충 위치와 벨트 방향을 어떻게 조합할까? | 이동 주기 관찰 → 타이밍 샷 → 방향 바꾼 회수 | 벨트 롤러·브레이크·표시등 변화 |
| CH-03 집진 | 안정화와 게이트 개방 중 무엇을 먼저 준비할까? | 누적 링 확인 → 개방 전 준비 → 포획망 대안 | 분진 감소·환기음 변화 |
| CH-04 양중 | 장력선을 언제 고정하고 어디로 반사할까? | 앵커 연결 → 고정 시점 → 순차 릴레이 | 케이블 긴장·고정등·진동 반응 |
| CH-05 전력 | 다음 약점을 읽고 노출 창에 명중할 수 있을까? | 스캔 → 직접 순서 타격 → 코어 노출 | 회로 점등·허브 정지·현장 정상화 |

시간 리듬 후보는 관찰3~5초 → 조작/샷5~10초 → 결과 확인1~2초다. 실제 플레이로 조정한다. 모든 스테이지에 연속 시간압박을 추가하지 않는다. 위험 패턴이 바뀌면 시각·음향 신호를 먼저 준다. 재도전은 즉시 현장으로 복귀하고 이미 본 안내는 접는다. 결과를 단순 점수 증가보다 멈춘 장치·맑아진 통로·복구된 전력으로 보여 준다.

이 설계는 원전의 WORLD FIRST / MOBILE FIRST / IMPACT FIRST / AUDIO=GAMEPLAY / ONE PRODUCTION GENERATION을 적용한다. 위험을 방치하거나 안전 하한선을 낮추는 선택에 새 보상을 부여하지 않는다.

| Gate | 작업 | 주요 파일 | 종료 증거 |

## 11. 검수 결과 기록과 남은 결정

이번에 완료한 검수: 첨부4장 시각 진단, 현재 렌더링/카메라 소스 확인, 원전·프로젝트 원칙 대조, 공식 벤치마크 자료 조사, 문서 내 구현/제안 구분. 런타임을 바꾸지 않아 이번 문서 작업에서 게임 테스트를 재실행하지 않았다.

구현 후 Director 검토 초점은 (1) 붙인 느낌 없는 한 현장, (2) 화면가림 없는 수동 조준, (3) 같은 세대의 장치·맵·캐릭터, (4) 설명을 읽지 않아도 보이는 장치 반응이다. 현재 이미지를 Final Art Lock으로 선언하지 않는다.

남은 제작 결정은 대표 Android/iOS 기종, 세로 축소 시야의 캐릭터 최소 크기/카메라 속도 실측, 최초 안내 길이와 접근성 설정이다. 위 숫자는 초기 제안값으로 기록하고 플레이 검증 후 확정한다. 운영 배포·최종 미술·실기기 PASS는 아직 완료되지 않았다.
