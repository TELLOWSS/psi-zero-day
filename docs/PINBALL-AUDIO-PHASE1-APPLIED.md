# 핀볼 1차 음원 적용 검증 — 2026-10-10

사용자 제공 ZIP의 51개 음원과 별도 Pneumatic_Payout을 브라우저 AudioContext(44.1kHz)로 디코딩했다. 샘플 피크, RMS, DC, 시작/끝 파형, 모노 합산 에너지, 공통 음원의 직접 상관을 검사했다. 원본 컨테이너 길이와 실제 디코드 길이는 구분한다. true peak/LUFS와 주관적 청취 승인은 이번 검사 범위가 아니다.

13개를 선택하여 원본 MP3 그대로 저장하고 게임 로딩 시 DC 제거·3ms 어택/25ms 릴리스 페이드·개별 게인을 적용한다. 원본 재녹음·무손실 복원·고해상도 제작으로 계산하지 않는다. 제공 파일의 권리 메모와 제작 정보는 manifest에 보존하며 최종 사용 조건은 공급자 확인 대상으로 남긴다. 사용자 요청은 적합한 자산부터 게임에 적용하는 것이다.

- 좌우 패들 각각 전용 음원.
- 일반 금속과 고무 접촉 각각 두 변형을 순환.
- 수동 퍼펙트 접촉 두 변형과 실제 발사 한 음원을 분리.
- 항만 성공은 모터 기동, 즉시 추가 공 출격, 짧은 구동 구간, 잠금으로 구성. 실제 없는 충돌음을 예약하지 않는다.
- 타워 공 포획은 잠금음과 연결한다.
- 전체 16 voice 제한. 잦은 접촉음은 예약된 성공음을 빼앗지 못한다.
- 일시정지·음소거·종료 시 미래 예약도 취소한다.
- 기존 음악 선택은 유지한다. 신규 음악은 full-scale 샘플·끝 구간·stem 누락 때문에 보완 전 적용하지 않는다.
- 유리·콘크리트는 현재 대응하는 재질 이벤트가 없으므로 임의로 모든 범퍼에 연결하지 않는다.

파일별 적용/보류 사유와 원본 SHA-256·디코드 지표는 content/design/pinball-audio-phase1-ingest-v1.json. 제작자 전달 문서는 docs/PINBALL-AUDIO-REMAINING-PROMPT-KO.md.

검증: 실제 패들 접촉의 퍼펙트/발사 구분·누르고 있을 때 반복 금지·탄 배열 포화 상태에서도 발사 이벤트 유지. 브라우저에서 13개 새 파일 로딩, 페이드/피크 제한, 좌우/변형/발사 라우팅, voice 우선순위, 일시정지·종료 취소 및 실제 앱 PC/모바일 플레이를 검사한다.

검증 결과: 자동 테스트 2,031개 통과/1개 기존 skip, 타입 검사·빌드 통과. 기본 실제 앱 5 화면 크기+전체화면 미지원 경로, 항만/타워 각각 PC·모바일 세로·가로 6 사례 통과. 13개 처리 자산의 피크가 0.7 이내이고 양쪽 끝 샘플이 0인 것을 확인. 6개 접촉+항만 성공 4개+음악의 OfflineAudioContext 검사 믹스 샘플 피크 약 0.722(이 fixture의 결과이며 모든 플레이 믹스·true peak의 보장은 아님). 좌우 패들의 반복 억제는 분리하여 동시에 눌러도 두 소리가 나오며, 발사는 접촉 뒤 18ms에 시작한다.
