# 성장 사건 근거 계약 V1

상태: 설계 초안. 신규 저장/대사/이미지/직업 해금은 아직 연결하지 않는다.

## 현재 관측 가능한 사실

| 근거 | 생산 경로 | 저장 필드 | 허용 표현 | 금지 추정 |
|---|---|---|---|---|
| 잔재물 정리 | engine clearTerrain | terrainRecord.rubbleCleared | 정리 횟수가 기록됨 | 다른 팀의 사고를 막았다 |
| 돌진 제동 | engine terrain collision | terrainRecord.cartStops | 돌진 제동 횟수가 기록됨 | 용감한 성격/운전 직업 확정 |
| 구역 통제 | operationControlledZones | handoff.zones | 확보한 구역 수가 기록됨 | 모든 위험 해소/법적 안전 인증 |
| 작전 결과 | victory 또는 defeat | handoff.outcome | 완료 또는 재대응 필요 | 사망/사고/인격 실패 단정 |

`operationHandoff`는 종료 때 수치를 복사한다. UI는 종료 처리에서 기존 app 저장을 호출한다. 준비 회고는 검증된 기록을 해당 characterId로 분리하여 읽는다. 피해/보상/내구도 계산에 개입하지 않는다.

현 저장은 캐릭터와 구역별 최근 기록으로 교체되며 시간순 사건 로그가 아니다. 행동 순서·판단 이유·동료 응답·선택 시각·재시도 횟수를 복원할 수 없다. 예전 저장에서 신규 선택을 소급 생성하지 않는다. 회고에 값이 없으면 근거 없음으로 표시한다.

## STAGE 12 시범 흐름

1. 준비: 기존 공정/목표와 선택 인물 역할을 읽는다. 주인공은 임준호/안전관리자 중 Director 선택 대기.
2. 전투: 현 엔진 행동을 그대로 사용한다. 대화를 강제로 열거나 새로운 시너지 과제를 만들지 않는다.
3. 종료: 실제 종료 기록과 일치하는 사실 요약을 먼저 표시한다. 통로 정리 0이면 통로를 정리했다는 대사를 선택하지 않는다.
4. 인계 대화: 승인 후 별도 선택 슬롯을 연결한다. '우선 확인할 내용을 묻는다'와 '관측한 내용을 설명한다'는 대화 방향 후보이며 현재 확정 대사가 아니다. 둘 다 가치 있는 선택, 보상/전투 능력 차이 없음은 제안이다.
5. 성장 장면: 승인된 대화의 변화와 실제 사건 근거를 함께 보여준다. 캐릭터 외형을 임의로 성숙/노화시키거나 현재 진로를 강제로 교체하지 않는다.
6. 다음 준비: 기존 STAGE 13 안내만 연결한다. 아직 없는 지도 변화·팀 반응·보너스를 약속하지 않는다.

## 신규 저장을 도입하기 전 확정할 항목

- 사건 식별은 characterId/chapterId/eventId/version과 승인된 sourceRecord 참조를 사용한다. 종료 수치만으로 선택 ID를 생성하지 않는다.
- 재도전은 실제 종료 기록을 갱신하되 이미 본 장면/대화 선택을 어떻게 다룰지 정책 승인 후 구현한다. 자동 직업 변경 없음.
- 건너뛰기와 다시보기는 새 클리어/성장/지갑 지급을 만들지 않는다. 저장 실패 시 장면 해금 성공으로 표시하지 않는다.
- 캐릭터 전환은 다른 인물의 선택과 이미지를 공유하지 않는다. legacy alias는 현재 계약과 대조한 명시적 마이그레이션만 허용한다.
- 검증은 domain 사건 투영, app 실패/복구/중복, UI 원인 표시와 닫기/다시보기, 자연 플레이 결과-다음 준비, 실기기를 구분한다.

## 납품 게이트

현재 구현은 chapter 기록과 인계 사실 회고까지다. 선택 대사, 진로 조건, 신규 schema, 성장 이미지 파일과 청취 승인 뒤에만 다음 연결을 수행한다. 새로운 이미지 후보를 반복 생성하거나 미승인 파일을 public에 넣지 않는다.
