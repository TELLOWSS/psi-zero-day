# 스토리 배경·읽기·선택 진행 수정

## 확인한 결함과 변경

- `playable.css`의 배경 표시 규칙 사이에 실제 줄바꿈 대신 문자 `\n`이 들어 있었다. 로딩 후 `opacity:1` 규칙이 정상 적용되도록 수정했다.
- 구형 세로 레이아웃의 `max-height:40dvh` 제한이 일부 장면의 배경에도 남아 있었다. 스토리 장면은 일관된 화면 영역을 사용하도록 제한을 해제했다. 새 화면 검사가 `e01_03_plan_breaks`에서 이 문제를 검출한 뒤 수정했다.
- directed 본편은 지도 아이콘이나 접힌 대체 선택지를 찾아야 하는 방식 대신, 현재 장면 아래의 동일한 읽기·선택 창에서 엔진이 제공하는 선택지를 직접 표시한다. 기존 전략 표시 경로와 사건·선택 효과·저장 형식은 보존한다.
- 음성 때문에 본편 진행 버튼이 잠기는 것을 해제했다. 독자가 버튼을 누르면 음성을 중지하고 읽기를 계속한다. 기존 비-directed 경로의 음성 잠금은 유지한다.
- 긴 대사는 짧은 읽기 페이지로 나눈다. `다음 문장`, `앞 문장`, 페이지 표시를 제공한다. 마지막 페이지에서만 엔진의 장면 진행 명령을 보낸다. 페이지 이동은 선택·효과·저장 상태를 바꾸지 않는다.
- 읽기 창의 크기를 줄이고 진행 버튼은 본문 스크롤과 분리했다. 현재 장소·시각과 진행 안내를 표시한다.
- 배경과 대체 자산 로딩이 모두 실패하면 오류와 재시도 버튼을 표시한다. 재시도는 엔진 상태를 변경하지 않는다.
- 펼친 선택 플레이 메뉴가 대사창 뒤에 가려지던 문제를 고쳤다. 실제 포인터 클릭 검사에서 GUARD 버튼이 가려지는 것을 검출한 뒤 레이어를 수정했다.

## 기술 검증 증거

검증 소스: `fd73061e03975abfcf1a79b332ff02bbf4730c0b`.

[GitHub Actions 전체 실행](https://github.com/TELLOWSS/psi-zero-day/actions/runs/39033197598): 타입 검사·회귀·운영 빌드·브라우저 검사 모두 성공.

- 테스트 파일 392개 통과·1개 건너뜀, 테스트 2,300개 통과·1개 건너뜀.
- directed UI에서 첫 선택·마지막 선택 경로 모두 26개 사건 완료. 읽기 페이지를 넘기고 되돌릴 때 엔진 상태가 바뀌지 않는 것을 확인했다.
- 새 브라우저 검사: 390×844, 844×390, 1440×900에서 각 26개 사건. 배경의 실제 이미지 디코드·불투명도·영역, 대사의 색·불투명도, 진행·선택 버튼의 화면 내 위치·최소 높이·포인터 가림 여부를 검사했다. 숨긴 요소에 DOM `.click()`을 호출하지 않고 Playwright의 일반 클릭을 사용했다. 페이지 오류 없음.
- 기존 5규격 자동 순회 및 저장 복구 검사도 성공. 손상 원본 보존, 저장 용량 실패, 필수 원화 누락 후 재시도, 선택 Watch/Guard 진입·복귀 시 본편 상태 보존을 확인했다.
- 동료 5명의 방향·동작 렌더링 계약 검사 성공.

선별 캡처·브라우저 결과는 [QA 폴더](qa/story-player-repair-20261017/)에 보관했다. 전체 아티팩트는 위 실행의 `crew-story-sync-evidence`에 있다.

## 검증 범위와 남은 품질 검토

위 결과는 자동 기능·표시·조작 검사이며, 사람이 내용을 읽고 선택의 의미를 판단한 직접 플레이나 실제 청취 검증이 아니다. 직접 플레이가 완료됐다고 보고하지 않는다.

캡처는 배경·대사·선택지의 표시를 확인하는 기술 증거다. 일부 인물 하단이 대사창과 겹치는 구도를 포함해 인물 배치·장면 전환·음향·대사 리듬의 최종 시네마틱 품질은 승인하지 않았다. 이번 변경을 완성된 영화식 연출 또는 본편 전체 품질 검증 완료로 해석하지 않는다. 실제 Android 성능·입력·청취 검사도 별도다.
