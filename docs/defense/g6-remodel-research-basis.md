# G6 REMODEL-01 — 공동주택 리모델링 연구 기준선

상태: `RESEARCH_BASELINE`  
목적: 게임의 리모델링 공법을 "낡은 아파트를 통째로 철거하지 않고 넓히는 공사"라는 인상 수준에서 끝내지 않고, **기존 구조를 남긴 채 조사·차단·선택철거·임시지지·보강·증축부 접합을 관리하는 현장**으로 모델링한다.

## 1. 게임에서 피해야 할 단순화

- "20평 → 40평"처럼 면적을 임의로 2배 만드는 규칙으로 구현하지 않는다.
- 주택법상 공동주택 증축형 리모델링은 세대 주거전용면적 기준 일반적으로 30% 이내, 85㎡ 미만 세대는 40% 이내 범위를 전제로 한다.
- 세대수 증가형·수직증축형은 별도 요건과 안전성 검토 체계를 가진다.
- 따라서 게임에서는 **수평증축 / 수직증축 / 기존-신설 구조 접합**을 서로 다른 공법 상태로 표현하되, 실제 허용 규모를 임의 숫자로 과장하지 않는다.

## 2. G6의 핵심 플레이 차이

신축은 "없는 것을 새로 만드는" 정보가 비교적 명확한 반면, 리모델링은 **기존 구조가 실제로 어떤 상태인지 확인하는 과정 자체가 게임플레이**가 되어야 한다.

핵심 상태:
- `AS_BUILT_CONFIDENCE`: 도면과 실제 구조의 일치/확인 수준
- `ISOLATION_STATE`: 전기·설비·기타 기존 계통 차단/확인 상태
- `TEMP_SUPPORT_STATE`: 임시지지 설치·검토 상태
- `STRUCTURAL_OPENING_STATE`: 선택철거/개구부 형성 진행 상태
- `CONNECTION_STATE`: 기존 구조와 신설 증축부 접합 상태

## 3. 안전게임으로 번역할 원칙

철거·해체 작업은 사전조사와 작업계획이 선행되어야 하고, 구조물 붕괴 방지를 위해 해체 순서와 임시지지 상태가 중요하다. G6에서는 이를 "정답 퀴즈"가 아니라 **정보가 부족하면 VEILED가 커지고, 지지가 불충분하면 ARMORED가 커지며, 철거·반출·보강이 겹치면 SWARM이 커지는 세계 상태**로 번역한다.

플레이어가 위험한 순서를 선택하도록 유도하지 않는다. 필수 선행상태가 확보되지 않으면 다음 구조 변경 단계는 잠긴다.

## 4. 대표 Vertical Slice

`APT_REMODEL / SELECTIVE_DEMOLITION_CONNECTION`

흐름:

`기존 구조 조사 → 계통 차단 확인 → 임시지지 검토/설치 → 선택철거 → 기존/신설 접합 준비 → 보강/접합 → 다음 공정`

대표 Risk 변화:
- 조사 초기: VEILED ↑
- 임시지지 전 구조 변경 시도: 진행 불가
- 선택철거 진행: ARMORED / SWARM ↑
- 폐기물 반출과 보강 동시작업: SWARM ↑
- 접합부 상태 확인 부족: VEILED ↑
- 지지/차단/접합 검증 완료: VEILED ↓, 다음 공정으로 전환
