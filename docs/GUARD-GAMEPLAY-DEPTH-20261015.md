# 시그널 가드 — 첫 구역 게임성 고도화

2026-10-15. [첫 3작전 구현](GUARD-CAMPAIGN-IMPLEMENTATION-20261015.md) 이후의 개선이다. [마스터 기획](DEFENSE-INDEPENDENT-CAMPAIGN-MASTER-PLAN-20261015.md)의 준비·배치·해소·회고와 [진화 기획](DEFENSE-TOWER-EVOLUTION-AV-MASTER-PLAN-20261015.md)의 P1 비교·발사구·분기 표현을 보강했다.

## 이번에 고친 플레이의 문제

| 확인한 문제 | 실제 변경 |
|---|---|
| 기획은 충분한 준비를 보장하지만 기존 엔진은 파 사이 10초 뒤 자동 시작 | 가드는 직접 다음 파를 누를 때까지 준비 유지. 게임 tick·자원·탐지/공격/지원 재사용도 함께 정지하여 기다림으로 무료 충전하지 않음. 기존 훈련 자동 시작은 유지 |
| 추천을 따라가면 비슷한 배치를 반복하기 쉬움 | 균형 설계/군집 제어/정밀 대응의 추천 방향. 같은 실제 비용·장비·엔진을 쓰며 가격/피해를 몰래 바꾸지 않음. 계정의 선택 선호만 로컬 보관 |
| 총 신호 수만 보이고 실제 진입 순서가 불분명 | 준비 중 펼쳐 보는 그룹별 진입 시작/끝 시각·수·기본 장갑·대응 관점. 진입 시간과 경로 통과 시간을 구분 |

| 진화 효과가 평행선/피치 차이 위주이고 몸체와 발사점이 어긋남 | 기존 16이미지에 정규화 발사 원점 기록. L3A/B의 선·파동·체결·초점 표현을 계열별 구분. 실제 명중 없는 가짜 점사/관통을 추가하지 않음 |
| 소리의 방향이 세로 화면과 다를 수 있음 | 가드의 세로 투영에 맞춰 좌우 pan 변환. 첨부 샘플의 A/B 어택·잔향·재생 속도 프로파일을 구분. 새 음원을 제작했다고 계산하지 않음 |
| 결과가 점수·별·최종 장비에 머묾 | 실제 엔진의 장비 계열별 피해/해소/발사 수, 한 공격의 최대 해소, 최대 동시 신호, 동료 지원/E-STOP 사용, 파별 해소·누출·방호 감소를 기록 |
| 기록을 추가하면 다음 작전 버튼이 밀림 | 결과 지표 다음에 다음 작전/재도전/작전실 버튼을 배치. 세부 기록은 펼침식이며 작은 가로 화면의 결과 배너를 축소 |

전투 중에는 새 정보창을 자동으로 열지 않는다. 진입표와 추천 방향은 준비 구간에서, 비교는 장비 선택의 시연을 열었을 때, 자세한 기록은 결과/작전실에서 사용자가 펼칠 때 보여준다. 몹 내구도나 보상을 일괄 상향해 시간을 늘리는 방식은 사용하지 않았다.

## 선택의 차이와 실제 측정

3작전 × 추천 3종 × 동료 4명의 **36개 대표 조합**을 정상 구매·합법 진화·지원으로 완주했다. 모든 가능한 배치나 사람의 재미를 전수 검증한 결과는 아니다. 첫 배치 후 나머지를 자동 추천에 맡기는 재현 입력이다.

강태식 대표 실행의 예:

| 작전 | 균형 설계 방호 | 군집 제어 방호 | 정밀 대응 방호 | 관찰 |
|---|---:|---:|---:|---|
| GD-01 | 20 | 16 | 20 | 균형/정밀은 같은 도면에 도달. 군집은 BURST 중심 도면과 최대5개 동시 해소 |
| GD-02 | 13 | 13 | 18 | 군집은 BURST 중심, 정밀은 PULSE·SENSOR 비중 증가. 군집 최대8개 동시 해소 |
| GD-03 | 8 | 8 | 11 | 정밀은 첫 배치부터 PULSE를 사용하고 다른 최종 배치를 형성 |

36개 실행의 시간/동료/배치/계열별 기여/파별 기록은 [엔진 원시 결과](qa/guard-gameplay-depth-20261015/engine-simulation.json)에 보관했다. 이 표를 특정 추천이 모든 사람·모든 배치에서 우월하다는 결론으로 사용하지 않는다. 일반 UI 플레이에서는 동료 사용 시각과 조작 시점이 다르므로 이 수치와 다를 수 있다.

실제 시연 검사에서 PULSE 장갑 시험의 B 피해가 A보다 크고, BURST 군집 시험의 A 해소가 B보다 많았다. 탐지가 없는 PULSE는 은폐 시험에 피해 0, SENSOR는 양 분기 모두 실제 피해가 발생했다. 가상 DPS나 시연용 추가 피해를 표시하지 않는다. 다른 장비의 감속·탐지 기여는 피해 순위만으로 평가할 수 없으며 특정 동료가 해소를 유발했다는 인과를 추측해 기록하지 않는다.

## 기록·저장 계약

`tacticalStats`는 가드에서만 활성화하는 선택 필드다. 짧은 공격 이벤트를 영구 저장하지 않고 최대4개 계열과 최대12개 파의 합계만 유지한다. 계열 피해는 엔진에서 HP에 실제 반영한 양이므로 과잉 피해를 더하지 않는다. `bestClear`는 한 공격의 실제 해소 수이며 시간 제한 콤보나 보너스 통화가 아니다. 새 보상·가격·영구 능력치를 지급하지 않는다.

현재 작전은 기존 가드 키에 저장하고, 정산 때 시나리오별 `lastTacticalReport` 하나를 남긴다. 같은 콘텐츠 버전의 최근 기록만 작전실에 표시한다. 기존 완료 횟수·별·해금·훈련 키는 유지한다. 기록 기능 이전의 활성 작전을 재개하면 `trackedFromTick`과 시작 시 누출/방호 기준을 저장하고 ‘재개 이후만 기록’이라고 표시한다. 과거 누출을 현재 파의 실적으로 잘못 합산하지 않는다. 결과 중복 적용도 기존 runId 정산 규칙으로 차단한다.

## 시청각 범위

새 몸체·캐릭터·전투판 이미지나 음원 파일은 추가하지 않았다. 기존 프리미엄 몸체의 광학구/방출부를 확인하고 [발사 원점 데이터](../content/defense/guard-combat-presentation-v1.json)를 작성했다. 이는 시각 보정 후보이며 최종 사람 검수를 대체하지 않는다. 실제 판정은 기존 즉시 공격이고 보여주는 탄의 이동은 표현이다. L3B를 다중 관통으로 표시하지 않으며 지속 필드도 새로 생기지 않았다.

한 번에 3개 이상 해소했을 때 대표 공격 하나에 실제 해소 수를 짧게 표시한다. 동시에24개 공격 그룹·8개 공격 버스 voice 상한은 유지한다. 새 파동은 실제 범위 안에서 확장하며 큰 불투명 장판이나 화면 중앙 팝업을 만들지 않는다. 동작 줄이기에서는 정적인 동일 정보를 제공한다. 기존 음원 상업 이용 증빙 상태는 이번 코드 보강으로 달라지지 않는다.
