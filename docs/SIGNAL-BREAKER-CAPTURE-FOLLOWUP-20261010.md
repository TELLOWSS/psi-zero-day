# 시그널 브레이커 실제 기기 캡처 후속 개선

2026-10-10 · 기존 몰입형 개선 계획의 후속 구현 및 검증 기록

## 검토 근거와 범위
사용자가 대화에 첨부한 세로·가로 전투, 작전 준비, 결과, 메인화면 캡처를 검토했다. 정지 화면에서 확인할 수 있는 배치·겹침·시야·정보 위계를 대상으로 수정했다. 조작감과 기기 성능은 정지 캡처만으로 판정하지 않고 별도 브라우저 회귀를 수행했다. 기존 게임 엔진, 스테이지, 캐릭터·장비·배경 자산을 유지했다.

## 화면별 문제와 구현 기준

|---|---|---|---|

## 조작 및 화면 설계
왼손 이동과 오른손 누른 채 조준·연속 발사, 자동 장비 전환/수동 선택은 기존 개선을 유지한다. 화면 회전은 렌더링 시야와 HUD만 다시 배치하며 작전을 초기화하지 않는다. 세로 기본 시야는 중요한 전투 영역을 넓게 보여주고, 더 큰 캐릭터와 정밀 조준을 원하는 경우 가까이 보기를 제공한다. 전체 현장의 먼 신호는 미니맵으로 접근한다.

결과의 우선순위는 해소 결과 → 보상/사용 장비 → 다음 현장 설명 → 재도전/다음 작전이다. 경로는 사용자가 열어 확인하며 배경에 실제 발사 경로를 겹쳐 보여준다. 추가 보상이나 진행 규칙은 바꾸지 않는다.

## 검증
- 독립 브레이커 Node 회귀: 31개 통과.
- 전체 Vitest, TypeScript 검사, 프로덕션 빌드: 최종 실행 결과는 동반 evidence/validation.txt 참조.
- 실제 Chromium 6개 전장 크기: 390×844, 844×390, 768×1024, 1024×768, 1280×800, 1920×1080.
- 캔버스가 viewport 전체를 차지하는지, 가로 overflow가 없는지, 발사 버튼이 화면 안에 있는지 확인.
- 누른 채 연속 발사, 손을 떼거나 취소할 때 발사 중단, 두 손가락 이동·조준, 정지/재개, 자동/수동 장비 선택, 세로 시야 전환, 화면 회전 확인.
- 보조 버튼과 자동 버튼의 영역 분리, 경로 접힘/펼침 양쪽의 결과 CTA 터치 대상 확인.
- 빌드된 메인화면에서 4개 크기(390×844, 844×390, 741×355, 1440×900)의 단일 브레이커 진입 → 준비 → 전체 화면 플레이 확인.
- 결과 스크린샷은 레이아웃 검증용 QA 승리 상태와 샘플 경로를 사용했다. 실제 클리어 또는 보상 밸런스 결과로 해석하지 않는다.

## 남은 실제 기기 확인
Android 브라우저/웹뷰와 iPad에서 주소창 변화, 노치·홈 인디케이터, 두 엄지 도달 범위, 3분 연속 플레이의 발열·FPS를 확인해야 한다. 캡처에 나타난 전체 화면 종료 안내는 브라우저/운영체제가 일시적으로 표시하는 안내다. 앱에서 이를 임의 제거할 수 없으며 표시가 사라진 뒤 하단 조작 가능 여부를 실제 기기에서 확인한다.

새 최종 아트·사운드를 제작한 작업으로 계산하지 않는다. 시그널 워치와의 미술적 완성도 동등성, Phase D 최종 시각 품질 Lock은 Director 판정 사항이다. GitHub 소스 반영과 실제 서비스 배포 확인을 구분하며 운영 URL의 최신 배포는 별도 확인이 필요하다.
