# 상세 기획 구현 · 공유 표시/음향 1차

## 이번 실제 적용

- WATCH의 `loadDirectionalActor`, `drawDirectionalBody`, `SpriteMotionTracker`를 직접 가져오는 순수 표시 어댑터를 추가했다. 정지 후보 이미지 대신 실제 기존 주인공의 방향 원화·이동 거리 기반 보행·회전·발 접지 렌더러가 준비되면 표시한다. 브레이커의 위치/생명/시뮬레이션 시각만 입력으로 받으며 WATCH 게임 상태는 만들지 않는다.
- 플레이 시작 시 선택된 기본 주인공만 준비한다. 전체 캐릭터 자산을 초기 로딩하지 않는다. 현재 캐릭터 선택 UI와 다른 인물 연결은 미구현이다.
- 어댑터 번들 96,979바이트(gzip 21.66kB). 빌드 명령은 `node scripts/build-breaker-shared-actor.mjs`이다. 자산 복사를 끄고 브레이커 표시 부분 21모듈만 묶는다. 본편 빌드가 이 어댑터를 자동 재생성하지 않으므로 공유 소스 변경 시 이 명령을 먼저 실행한다.
- 금속 타격·포획에 기존 녹음 `hit_metal_light_01.mp3`, `harbor_cargo_lock.mp3`를 연결했다. 첫 로딩 동안 기존 합성음을 유지하고, 디코딩 완료 후 다음 이벤트부터 녹음음을 사용한다. 로딩 완료 후 지난 이벤트를 지연 재생하지 않는다.
- 공통 오디오 캐시에 URL별 Promise/디코딩 결과를 AudioContext별로 보관한다. 재생 노드는 세션별로 생성하고 동시 발음 상한 24개를 유지한다.
- `after-the-shift-v01.mp3`를 전용 저음량 배경음으로 연결했다. 작전 시작 때만 스트리밍하고 정지/탭 전환/음소거/완료 시 중단한다. 같은 음악 객체를 재개하며 여러 곡을 일괄 디코딩하지 않는다.
- SB-02~04의 컨베이어를 실제 운반 구간에 표시했다. 벨트 방향/이동 위상은 기존 물리의 +65 운반 방향과 시뮬레이션 시각을 사용한다. 정지하면 화면도 멈춘다. 이번에는 컨베이어 물리 공식이나 새로운 장치를 추가하지 않았다.

## 검증/한계

독립 검사 11개(오디오 중복 요청/디코딩 방지 포함)와 타입 검사, Vite 빌드 통과. 본편 기준선은 2037 통과/1 제외다. 실제 Chrome에서 기존 주인공 준비 완료, 우측 이동·발사·정지/재개, 배경음 요청과 JS/HTTP 오류 없음을 확인했다. 화면은 저장소 루트 `docs/qa/signal-breaker-20261010/shared-actor-audio.png`에 보관했다.

움직임 공유는 기본 주인공에서 먼저 연결했다. 모든 캐릭터/브레이커 장비의 손 앵커 보정 완료를 의미하지 않는다. 현재 무기 표시에는 기존 브레이커 장비 오버레이를 사용하며 전용 장착 디테일은 후속 작업이다. 사용한 WATCH 표시 소스는 이 분리 작업 폴더의 기반 버전이며, 다른 작업 폴더의 미커밋 보정과 차이를 검토해 후속 이관해야 한다.

실제 음질/음악의 장면 적합성, 물리 모바일 GPU·발열, 전체 캐릭터 로딩 메모리, HTTPS 오프라인 캐시의 공통 원화/음원 연결은 아직 미검증이다. 공유 기반을 연결했다고 전체 게임 최적화 완료로 표시하지 않는다.

다음 순서는 장비별 손/총구 앵커 정합 → 캐릭터 선택/해제 정책 → 방호판/컨베이어/전자석 상태와 녹음 루프 연결 → 연속 충돌 및 장치 상호작용 고도화다. 메인 허브 연결과 배포는 수행하지 않았다.
