## 0. Codex가 가장 먼저 읽을 지시

**목표:** 기존 《시그널 워치》와 동등한 상업 게임 지향 그래픽/타격감/조작 품질을 갖추되, **반사·분열·장비 조합·연쇄 회수**가 핵심인 새로운 독립 모드 《시그널 브레이커》를 계속 개발한다. 기존 게임은 보존한다.

1. 저장소 `TELLOWSS/psi-zero-day`를 열고 **`feature/signal-breaker-foundation-20261010` 브랜치**를 기준으로 작업한다. `main`에 바로 수정·병합·배포하지 않는다.
2. **이 파일 → `public/signal-breaker-dev/docs/GDD_V2.md` → `docs/LOCAL_WEB_WORKFLOW.md` → `docs/QA_STATUS.md` → 실제 코드/테스트** 순서로 확인한다.
3. 기존 v0.4 실행 파일을 먼저 재현한다. 명령: `node public/signal-breaker-dev/dev-preview.mjs` → 같은 PC의 브라우저에서 `http://127.0.0.1:5199/` 확인.
4. `cd public/signal-breaker-dev && node --test tests/*.cjs`로 출발점 테스트를 수행한다. **2026-10-10 작성 환경에서는 4개 테스트 파일 모두 통과**했지만, 새로운 환경에서 재실행하여 확인한다.
5. 우선 **첫 스테이지(SB-01)를 실제 원화 기반 고품질 플레이 화면으로 고도화**한다. 기존 물리·분열·반사·포획 판정은 유지하며, 애니메이션·충돌 감각·화면 판독성·멀티디바이스 UX를 개선한다.
6. 매 작업 후 **변경 파일, 재현 가능한 테스트 결과, 미검증 항목, 스크린샷/동영상(가능하면), 다음 작업**을 남긴다. 실제로 검사하지 않은 내용을 PASS라고 쓰지 않는다.
7. **Vercel 호출/수동 배포/`main` 병합은 지시받기 전까지 하지 않는다.** 개발 브랜치에 커밋하면서 로컬 브라우저에서 반복 검수한다.

## 1. 확정된 디렉터 의사결정 — 변경 금지 기준

### 1.1 제품 안에서의 위치

- 《시그널 브레이커》는 단순 보너스 스테이지가 **아니라**, 《시그널 워치 (SIGNAL WATCH)》와 동등한 **독립 게임 모드**다.
- 다만 독립 앱을 즉시 출시는 것이 아니라, **《오늘도 무사히》 메인 게임 안의 별도 모드**로 성장시킨다.
- 기존 《시그널 워치》의 생존·성장 슈팅과 별개의 장르로 만든다. 《시그널 워치》 안에 존재하는 **기존 핀볼 보너스 게임은 그대로 유지**한다.
- 디펜스/스토리 모드의 기존 **준비중 표시를 승인 없이 변경하지 않는다.** 현재 `GameHub.tsx`에도 브레이커를 아직 연결하지 않았다.
- 사용자가 원하는 방향은 **기획 → 스케치 → 개발 → 로컬 웹 시연 → 실제 조작·성능 검증 → 품질 상향 → 명시적 승인 뒤 통합/배포**다.

### 1.2 재미의 네 축

1. **터뜨리는 쾌감:** 한 발 충격에서 재질별 균열/파편/분열/대량 회수가 이어지는 즉각적 피드백.
2. **무기 메커니즘:** 단순 대미지 차이 대신 밀기·궤도 굴절·포획·안정화·고정·스캔이라는 서로 다른 물리 역할.
3. **장애물/핀볼적 반응:** 각도를 바꾸는 방호판, 범퍼, 철골, 전자석, 컨베이어, 집진 게이트 등을 의도적으로 활용하여 리코셰/연쇄 공격을 구성.
4. **기믹형 보스:** HP를 깎기만 하는 보스가 아니라 현장 시설/취약 노드/차폐 단계/타이밍을 읽고 피니시를 만드는 보스.

**한 줄 핵심:** “한 발을 제대로 설계했더니 건설현장의 시설물과 위험 신호가 연쇄 반응하여 통쾌하게 안정된다.”

### 1.3 세계관/윤리/차별화

- PSI = **Proactive Safety Intelligence** = “사고 전 신호를 모아 다음 위험을 먼저 읽는 안전지능.”
- 허구의 신호 코어는 **위험의 시각적 은유**다. 작업자나 사고 피해자를 공격·파괴 대상으로 표현하지 않는다.
- 현장 반응은 **분리 → 유도 → 통제/안정화 → 회수**이며, 실제 안전조치를 단순 폭파로 대체한다는 뜻이 아니다.
- 기존 Pang/핀볼에서 참고한 것은 **쾌감·물리 규칙 수준의 아이디어**다. 원작 그래픽·인물·사운드·스테이지 배열·전반적 표현을 복제하지 않는다. 최종 출시 시 별도 권리/상표/등급분류 검토 필요.
- 원본 《오늘도 무사히》의 인간관계/현장사건/PSI 서사를 존중하지만, 브레이커의 플레이 기록을 본편 사건의 **증거·실제 안전 평가 결과로 자동 반영하지 않는다.** 실제 산업안전 관리용 PSI 제품/데이터와 게임 플레이 성적을 혼합하지 않는다.

| 실제 웹 공개 URL | **미연결**. 현재 localhost 개발 서버가 배포 서비스인 것은 아님 |

### 특히 혼동하지 말 것

- 사용자가 제시한 `127.0.0.1:5199` 화면은 **“로컬 웹에서 작업하고 그때그때 확인하자”는 개발 방식의 예시**다. 그 스크린샷 자체가 시그널 브레이커의 구현/성능 검증 증거는 아니다.
- `127.0.0.1`은 **각 기기 자기 자신**을 뜻한다. PC의 로컬 서버를 휴대폰에서 직접 같은 주소로 열 수 없다. 모바일 실기기 테스트에는 별도의 안전한 LAN 또는 HTTPS 테스트 경로를 설정해야 하며, 외부 공개/방화벽 변경은 명시적 승인을 따른다.
- GitHub 개발 브랜치로 커밋하는 것과 Vercel 배포는 다르다. 현재 설정은 `main`만 허용하지만, 설정이 바뀌거나 Deploy Hook/수동 배포가 사용되면 별도 빌드가 일어날 수 있으므로 수정 전에 확인한다.
- **주의(통합 전 검증):** 현재 개발 게임은 Vite 프로젝트의 `public/` 아래 있다. 나중에 그대로 `main`에 병합하면 메뉴 카드가 없어도 정적 에셋이 빌드 출력에 포함될 수 있으므로, 출시 여부에 맞는 폴더 배치/빌드 포함 정책을 검토해야 한다.

### 실제 코드에 존재하는 기능

- 브라우저에서 직접 조작 가능한 **SB-01~SB-04**, 이 중 **SB-01~03 일반 시험 구간, SB-04 기믹형 보스 시험**. 이는 20스테이지 완성이 아니다.
- 무기 **PULSE(에어 펄스)**, **NET(포획망)** 2종; 이동·직접 조준·발사, 3단계 방호판 각도, 전자석 ON/OFF.
- 코어 종류 `metal`, `dust`, `power`, `load`에 대한 기초 데이터/거동과 접촉 반응. **모든 속성별 최종 공략 메커니즘이 완성된 것은 아님.**
- 발사체/코어 충돌, 분열, 범퍼와 레일 반사, 자력장 유도, 회수 게이트, 연쇄 점수/피드백.
- 보스 원형: **3개 노드 타격 → 실드 해제 → 핵심 코어 타격**. 원화의 거대 ZERO CASCADE는 아직 게임 속 리깅/애니메이션으로 제작되지 않음.
- 최고점 및 클리어 기록 `localStorage` 저장. 그래픽 `high/balanced/low`, 동작 감소, 집중 보기, 기초 오디오 피드백.
- 개발용 PWA manifest/service worker 파일. **로컬 HTTP에서는 캐시가 개발 변경을 숨기지 않도록 SW 자동 등록을 끈 상태**, HTTPS 운영은 별도 검증 필요.

### 미구현·미검증 — 반드시 명확히 표시

- 6무기 전체, 무기별 3단계 성장, 기믹을 구분한 20스테이지/4보스, 독립 LAB/CHALLENGE/BOSS RUSH 정식 모드.
- 원화 3종을 게임 내 **완성 스프라이트/애니메이션/보스 리그**로 변환하고 장착·발사·명중·소멸까지 연결하는 Production Art.
- 실제 모바일·태블릿·PC 기기별 프레임 수/발열/입력 지연을 측정한 **실기기 QA**.
- 메인 `GameHub.tsx` 독립 선택 카드, 본편 통합 저장/결제·경제 연동, 출시 권리 검토 및 상업 배포.

> **선행 문서 정합성:** `docs/GDD_V2.md`는 코드 생성 **이전**의 기획서라 마지막에 “미구현”이라고 적혀 있다. 그 문구는 문서 작성 시점의 기록이며 **현재의 v0.4 프로토타입 존재를 부정하지 않는다**. 소스 코드와 후속 QA가 최신 구현 상태의 근거다. 또한 `docs/README.md`의 `localhost:8765`는 예전 단순 정적서버 실행 예시이며, **최신 기본 개발 루프는 `docs/LOCAL_WEB_WORKFLOW.md`에 적힌 `127.0.0.1:5199`**다.

**기술 메모:** 현재 프로토타입은 논리 좌표 **1100×620**, 엔진 고정 논리 스텝 `1/120초`, 활성 코어/발사체/파편의 상한을 사용한다. 고품질 연출을 넣더라도 공격 판정, 약점 가시성 및 반사 궤적 읽기 기능이 화질 프로필에 따라 바뀌면 안 된다.

**저장 분리:** 현재 로컬 키는 `psi.signal-breaker.offline.v1`, 그래픽 키는 `psi.signal-breaker.graphics.v1`. 기존 시그널 워치·핀볼·통합 지갑 키를 재사용하지 않는다. 향후 보상은 중복 정산 방지/버전 마이그레이션을 먼저 설계해야 한다.

## 7. 모바일 + 태블릿 + PC 동시 최적화 품질 계약

**단일 물리 규칙 / 디바이스별 입력·화면만 적응**. 개발 단계부터 동시에 확인한다.

| 환경 | 검증 대상 기준 해상도 | 검증 내용 |
|---|---|---|
| 모바일 세로 | 390×844 | 작동은 가능, 안내/핵심 HUD/버튼이 가려지지 않음 |
| 모바일 가로 | 844×390 | 우선 플레이 레이아웃, 손가락이 위험/궤적을 가리지 않음 |
| 태블릿 | 1024×768, 1280×800 | 확장 시야, 터치 버튼 크기, 보조 패널 배치 |
| PC | 1366×768, 1920×1080 | 마우스 정밀 조준, 키보드 이동, 정보 표시 균형 |

- Desktop 입력(현재): `A/D` 또는 방향키 이동, 마우스 조준·클릭 발사, `1/2` 무기, `Q` 방호판, `E` 자력장, `Space/F` 발사, `P` 일시정지.
- Touch 입력(현재): 화면 터치 조준/발사, 좌우 이동·무기·방호판·자력장 버튼. 정확한 기기별 조작 지연과 터치 가림은 실기기 검증 전이다.
- 모바일 low/balanced, PC high를 강요하지 말고 이용자가 전환 가능하게 한다. 낮은 품질에서는 파티클·광원·반사 장식의 비용만 낮추고 판정·경고·조준/회수 궤적을 유지한다.
- **성능 목표(미검증):** 적절한 기기에서 부드러운 60fps를 지향하되, 저사양에서는 안정적인 30fps 폴백도 비교한다. 초당 프레임 실측 없이 달성했다고 말하지 않는다. 장시간 플레이 시 GC 스파이크·발열·음원 중첩도 관찰한다.
- PC 개발자 도구의 기기 에뮬레이션은 1차 반응형 확인일 뿐 실제 GPU/터치 검증이 아니다.

## 8. Codex 실행/검증 명령 — 배포 없음


### 코드 검사

```bash
cd public/signal-breaker-dev
node --version
node --test tests/*.cjs
```

### 로컬 웹 시연

```bash
# 저장소 루트에서 실행하거나 해당 폴더에서 node dev-preview.mjs
node public/signal-breaker-dev/dev-preview.mjs
# 같은 컴퓨터 Edge/Chrome → http://127.0.0.1:5199/
```

Windows: `public/signal-breaker-dev/START_WEB_PREVIEW.cmd` 사용 가능. 현재 포트가 이미 사용 중이면 다른 포트에서 직접 실행하고 브라우저 주소를 일치시킨다. 예: PowerShell에서 `$env:SIGNAL_BREAKER_PORT='5200'; node public/signal-breaker-dev/dev-preview.mjs`.

로컬 서버는 **Node.js 기본 모듈만** 사용한다. 브라우저에 노출된 페이지는 수정시 라이브 리로드를 시도하며, 서버 종료 시 주소도 사라진다. 작업에 따라 프로젝트 루트 `npm run typecheck` / `npm test` / `npm run build`를 사용할 수 있지만 기존 전체 게임의 빌드/테스트 파이프라인이 크므로 실행·소요·실패 원인을 별도로 보고한다.

### 기준선 검증 기록(2026-10-10 실행 환경)

- `node --test tests/*.cjs` → **4개 테스트 파일 통과, 실패 0**. 엔진 측 내부 검사는 20개를 출력한다. “4개 파일”과 “엔진 단위 점검 수”를 합산해 표현하지 않는다.
- 로컬 HTTP 서버 실행 → `/`, `/src/engine.js`, `/src/style.css`, `/art/responsive-platform-concept.webp`, `/manifest.webmanifest` 응답 **200 확인**.
- 화면 렌더링을 실제 브라우저로 캡처하는 검사는 환경 제한 때문에 아직 수행하지 못했다. **실기기 QA / FPS 목표 미검증**.

## 9. 우선 개발 백로그 (권장 승인 단위)

### P0 — 시각 품질을 1개 스테이지에 먼저 고정

- [ ] **SB-01**의 캐릭터/발사 장비/코어/현장 배경을 원화 기준으로 레이어 분리하여 가독성 있는 일관된 시야 완성.
- [ ] PULSE 및 NET 각각 **대기 → 발사/반동 → 비행/궤적 → 재질별 명중 → 분열/포획 → 소멸/회수** 상태를 애니메이션으로 연결.
- [ ] 금속/분진/전원/장력별 외형·동작·사운드·피격 반응 차이를 **게임 규칙과 일치**시킴.
- [ ] 리코셰 순간 방향이 읽히도록 반사점·각도 표시·피격 프레임·상태 신호 강화; 장식 이펙트로 판정 가리지 않기.
- [ ] PC 1920×1080/1366×768, 태블릿 1024×768/1280×800, 모바일 844×390/390×844 스크린샷 및 조작 동선 확보.
- [ ] 확대된 자산으로 30/60fps/메모리 부담이 달라지면 low/balanced/high 프로필로 **가시적 결과와 성능** 검증.
