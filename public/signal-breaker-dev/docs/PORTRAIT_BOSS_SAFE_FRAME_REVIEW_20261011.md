# SIGNAL BREAKER — 모바일 세로 보스전 Safe Frame 교정
2026-10-11 | 기준 main: PR #185 / CH03 필터 4단계

## 근거와 결함
CH03 GitHub QA 모바일 세로 390px 실렌더 캡처에서 보스 제어부가 우측 화면 밖에 잘려, 플레이어가 약점과 안전 개입 지점을 파악할 수 없었다. 기존 카메라는 세계관 세로 배경 높이를 화면에 무조건 채우는 scale 제약(Math.max)과 플레이어 근접 구도로 인해 x가 크게 떨어진 보스를 표시하지 못했다. 코드 성공이나 통합 플레이 클리어는 모바일 비주얼 품질 기준 통과를 의미하지 않는다.

## 구현
- 독립 `src/boss-camera.js`의 순수 `frame()`은 CH01~05 보스 배치 시 플레이어(±39 세계 px), 보스 몸체(±149), **현재 깨진 노드 포함** 릴레이 3개의 ±30 범위를 모두 화면 x방향 약 16px 여유 안에 포함한다. 파괴/재등장 순간 범위가 변하지 않아 급격한 카메라 줌 점프를 줄인다.
- 배율은 max가 아니라 min(적정 수평 구도 배율, 세로 배경 커버 배율)로 계산한다. 배경 이미지가 세로 화면 전체를 덮지 못하는 예외는 보스가 화면 밖으로 잘리는 것보다 우선순위가 낮으며, 추후 비주얼 QA의 재질/하단 밴드 검토 대상이다.
- 지면은 화면 하단 조작영역 위에 유지하고, 플레이어가 작업공간 좌우 끝으로 움직일 때도 최소 여유를 확보한다.
- 가로 화면, 보스 이외 웨이브는 기존 카메라, 보스 물리·좌표·충돌·조준·사격·저장·다른 게임 모드는 변경하지 않는다. 별도 스크립트 및 service-worker 캐시 배포에 포함한다.

## 검증
- Node 단위 테스트 5개: 보스 5종 × 플레이어 좌표 이동, 320/360/390/412/600/768 폭·세로 대응, 노드 파괴/재생성 구도 안정성, 높이·배경 유효영역, 순수 함수 및 보스 완료 후 비적용.
- GitHub 브라우저 시나리오: CH01/02/03/04/05 보스 실제 렌더링 중 세로 화면 플레이어/보스 ±149/노드 3개가 모두 화면 안에 있는지 확인하고 `operation-portrait-safe-CHxx-390.png`, 태블릿 대응 캡처 생성. 기존 자동 입력 45회, UI/제어 흐름, EP01 전체 회귀 통과 필요.
- 실제 Android 사용자가 보스 전투 중 조작부·약점·파티클 충돌 없이 읽을 수 있는지는 별도 기기 확인이 필요하다.
