## 기준선 검토

인계서와 GDD, 로컬 실행 지침, QA 현황, 실제 엔진·UI를 대조했다. 원격 개발 브랜치의 현재 기준은 `16a96e388271b6da559a3948bf713b30e59e7e25`이며, 인계서에 기재된 `fa47d12a` 이후 인계 문서 추가 커밋을 포함한다. 기존 WATCH 작업 폴더의 미커밋 변경을 보존하기 위해 별도 Git worktree와 `codex/signal-breaker-polish-20261010` 파생 브랜치에서 작업했다.

- 실제 기반: SB-01~04, PULSE/NET, 고정 물리, 분열, 방호판 반사, 자력 유도, 회수, 3노드 보스.
- 계획: 시즌 20판, 6무기/3단계 성장, LAB/CHALLENGE/BOSS RUSH, 본편 메뉴 및 경제 연계.
- GDD의 “신규 코드 미구현” 문구는 기반 코드와 불일치한다. 위 구분을 현재 기준으로 사용한다.
- 출발점 검사: 4개 파일 중 2개 실패. 루트 ESM 설정 아래에서 UMD 엔진을 CommonJS로 읽던 문제를 독립 폴더의 `package.json`으로 해결했다. 브라우저 실행 규칙은 동일하다.
- `vercel.json`의 개발 브랜치 자동 배포 차단 유지. 메뉴 연결·main 병합·원격 push·Vercel 배포를 수행하지 않았다.

## 보강한 플레이 기획

핵심 감정은 **내가 설계한 한 발이 현장을 연쇄 작동시킨다**이다. 자동 발사나 자동 포획으로 대신하지 않는다.

| 보강 | 이번 구현 | 다음 품질 기준 |
|---|---|---|
| 조준의 의미 | 실제 탄환의 방호판/외벽 규칙으로 경로와 반사 접점 표시 | 움직이는 코어의 미래 위치는 보장하지 않음. 자력은 코어에 작용하며 탄환 곡선처럼 표시하지 않음 |
| 포획의 발견 | NET의 실제 102px 범위를 현재 예측 표적에 표시 | 큰 불안정 코어는 먼저 안정화한다는 후속 안내 보강 |
| 첫 체험 | 분리→반사→포획의 이벤트 기반 안내, 초기 조준 방향 보정 | 15초 체험은 목표. 일반 사용자 대상 성공률 측정 필요 |
| 손맛 | 발사 반동, 순간 재질 반응, 회수 게이트로 이동하는 시각 잔상 | 잔상은 판정 없는 연출. 새 위험물이나 추가 보상으로 오인시키지 않음 |
| 재질 정체성 | 금속/분진/전원/장력의 다른 원화, 회전·흔들림과 합성 타격음 | 각 속성의 최종 장비 대응은 캠페인 규칙 확정 후 구현 |
| 모바일 | 드래그 조준→손을 떼면 발사, 취소 시 발사 없음 | 물리 기기에서 엄지 가림·다중 터치·지연 측정 |
| 몰입 | 작전 개시 시 집중 화면, 경기장과 버튼을 뷰포트 안에 배치 | OS 전체화면 API가 아닌 앱 내 집중 화면 |
| 판독성 | 진행 안내를 경기장 밖에 배치, 화질과 판정을 분리 | 위험 경고·조준·회수 표시를 저화질에서도 유지 |

추가 성장안은 공격력 수치 반복보다 **경로 숙련**을 중심으로 한다. 기본 회수만으로 클리어할 수 있고, 반사 횟수·장비 조합·회수 연결은 선택적인 고득점 과제가 된다. 반사 성공 장면을 결과 화면에서 짧게 되짚는 ‘경로 기록’과, 해금한 조합을 부담 없이 시험하는 보상 없는 LAB를 다음 제작 대상으로 제안한다. 아직 기록/해금 보상을 구현한 것은 아니다.

연쇄 피니시는 성공 위치의 짧은 충격→금속/분진/전원/장력의 고유 반응→포획 수축→게이트 흡수→점수 확정 순서를 따른다. 긴 중앙 자막·전면 백색 섬광·화면을 덮는 배너는 피한다. 기존 합성 음향은 재질별 음색을 구분하고 동시 발음 24개를 제한했다. 상용 음원 마스터링이나 장비별 녹음 완료로 계산하지 않는다.

## 실제 원화 사용

내장 image_gen으로 제작하고 원본을 보존했다. 정확한 프롬프트는 `PRODUCTION_ART_PROMPTS_20261010.md`에 기록했다. 외부 게임의 스프라이트·배치를 복제하지 않았다.

| 자산 | 실제 크기/형식 | 런타임 적용 |
|---|---|---|
| `art/sb01-delivery-bay-v1.png` | 1672×941 RGB | SB-01 실제 배경. 원화의 바닥 경계 81.7%를 엔진 지면 536px에 맞춰 위/아래 두 구역으로 배치 |

| `art/operator-idle-v1.png` | 1024×1536 RGBA | 플레이어 정지 원화, 발 기준 미세 호흡, 조준에 따른 좌우 방향과 별도 장비 반동 |

요청한 출력 크기와 실제 생성 크기는 다르다. 위 표가 실제 파일 기준이다. 코어·캐릭터의 투명 알파를 검사했다. 원화를 코드에서 단순 확대해 보행 원화라고 계산하지 않는다. 캐릭터 보행/회전/양장비 착용 원화, 시설물 전용 원화, 재질 타격 아틀라스, 보스 다단계 원화는 미완료다. 이번 이미지는 런타임 적용한 최종 후보이며 시그널 워치급 최종 품질 확정은 사용자 플레이 검수 후 판단한다.

## 검증 기록

- 독립 Node 검사: 6개 파일, Node 보고 8개 테스트 통과. 기존 엔진 파일 내부 20개 검사는 이 결과에 포함되어 별도로 더하지 않는다.
- 새 검사: 예측의 무변경성, PULSE/NET과 3개 방호판 각도의 실제 반사 접점 일치, 포획 범위, 합성 음향 동시 발음 제한과 해제.
- 본편 기준선: `npm test -- --run` — 2037 통과, 1 제외; `npm run typecheck` 통과; `npm run build` 통과. 이는 분리 작업 폴더의 원격 기반 본편 검사이며, 다른 작업 폴더의 최신 미커밋 WATCH 변경을 재검사했다는 뜻은 아니다.
- 실제 Chrome 브라우저: 1920×1080, 1366×768, 1024×768, 1280×800, 844×390, 390×844. 가로 넘침 없음, 경기장과 발사 버튼 화면 안 배치, 이동 버튼 40px 이상, 장비/방호판/자력/정지/재개 검사. 터치 뷰포트는 CDP 터치 입력으로 드래그 중 미발사와 손을 뗀 뒤 발사를 확인했다.
- 실제 UI 입력 플레이: 첫 PULSE 명중으로 2개 코어→3개 코어, 이어 NET 사용으로 6/6 회수, 1577점, 최대 4 CHAIN, 생명 5, 8발 중 4발 명중으로 승리. 단일 자동화 재현 결과이며 일반 사용자 평균 성공률은 아니다.
- 참고 성능: Chrome 154.0.8037.98 헤드리스, PC 1366×768/high, 초기 코어 2개, RAF 간격 179표본: 중앙 16.7ms, P95 16.8ms, 최대 50ms. 스트레스 장면/GPU 프레임 시간/물리 모바일 발열 검증이 아니다.
- 재현 가능한 UI 검사: `scripts/verify-browser.cjs`. Playwright 런타임 및 Chrome 경로는 `SIGNAL_BREAKER_PLAYWRIGHT_ROOT`, `SIGNAL_BREAKER_CHROME` 환경 변수로 지정한다. 출력 경로는 `SIGNAL_BREAKER_QA_OUTPUT`으로 설정한다.
- HTTPS PWA 업데이트·오프라인 전환, iOS 주소창·안전영역, 장시간 최대 개체 스트레스, 실제 기기 오디오 믹싱은 미검증이다.

## 다음 제작 순서

**후속 방향 변경:** 사용자의 공유 자산 활용 지시에 따라 캐릭터 움직임·사운드·VFX는 WATCH의 최신 구현 공유를 우선한다. 아래 최초 계획보다 [공유 기반·맵·무기·UX 기획서](SHARED_PRESENTATION_MAP_WEAPONS_UX_PLAN_20261010.md)의 제작 순서가 우선한다. 새 원화는 장치 부품이나 장비 장착 등 공유 자산으로 충족되지 않는 부분에 한정한다.

1. **P0 마무리:** 캐릭터 보행/회전과 PULSE/NET 장착 전용 원화, 시설 원화, 재질별 타격 아틀라스. 사용자 첫 15초 체험을 보고 발사/포획 안내를 조정한다.
2. **P1:** SB-02의 분진 안정화 순서, SB-03의 회수 통로 조작을 고유 공략으로 강화. SB-04는 시험 보스 지위를 유지하며 예고→노드→방호 해제→연쇄 피니시를 보강한다. 시즌 1의 5판 보스와 혼동하지 않는다.
3. **P1 검증:** 저/고화질 스트레스, 저장 실패 안내, 터치 동시 조작, 실제 기기 성능과 사운드 검수.
4. **P2 통합 설계:** 순수 TypeScript domain/engine으로 이관하고 React UI는 표시만 소유. 독립 저장 스키마와 중복 정산 방지 계약을 먼저 검증한다. 이번에는 승인된 JS 시험 기반을 유지했다.
5. **첫 챕터:** 5개 고유 스테이지를 검수한 뒤 6무기와 20판으로 확장. 색상만 바꾼 스테이지 증식은 하지 않는다.
6. **허브/배포:** 인계서의 통합 검수 단계에 맞춰 별도 승인 후 연결한다. 통합 크레딧·본편 사건 증거·PSI 안전 평가를 브레이커 점수로 자동 생성하지 않는다.

## 로컬 시연

실제 화면 증거는 저장소 루트 `docs/qa/signal-breaker-20261010/`에 여섯 해상도 스크린샷과 `viewports.json`으로 보관했다. 브라우저 검사는 원화 로딩 이후 실제 시작/발사/장비/정지 버튼을 사용한다.

기존 본편은 5199를 사용한다. 브레이커는 작업 폴더에서 `$env:SIGNAL_BREAKER_PORT='5200'`을 지정하고 `node public/signal-breaker-dev/dev-preview.mjs`로 실행한다. 시연 주소는 `http://127.0.0.1:5200/`이며 같은 PC에서만 접근한다. 게임 실행 중에는 경기장 밖 안내와 1/2 장비 전환, Q 방호판 변경, E 자력 전환을 함께 확인한다.
