# SIGNAL BREAKER · 공유 자산과 현장 물리 중심 제작 기획 v1

## 1. 제작 방향과 현재 상태

시그널 워치에서 개발한 캐릭터 움직임·음향·특수효과를 공통 품질 기반으로 활용한다. 브레이커의 제작 집중점은 **장치가 실제 작동하는 현장, 설계 가능한 반사 경로, 역할이 다른 무기, 읽기 쉬운 조작**이다. 한 발이 방호판을 거쳐 코어를 분리하고, 컨베이어와 자력으로 모은 신호를 포획할 때 내 선택이 현장을 움직였다는 감각을 준다.

이 문서는 후속 구현 명세다. 이번 작업에서 공유 자산 연결이나 물리 기능을 새로 구현했다는 뜻은 아니다. 현재 브레이커는 SB-01~04 시험판, PULSE/NET, 방호판/범퍼/금속 코어 자력/회수 게이트를 제공한다. 여섯 무기·20판 캠페인은 계획이다. 앞선 검토서의 ‘캐릭터 원화 재제작 우선’ 순서를 **워치의 최신 자산·동작 공유 우선**으로 수정한다.

## 2. 확인한 공유 기반과 연결 계약

검토 기준은 최신 로컬 WATCH 작업 폴더 `psi-zero-day-animation-20261007`이다. 최신 미커밋 보정도 있으므로 원격 개발 브랜치의 파일만 복사하면 과거 움직임이나 EMP 연출이 들어갈 수 있다. 연결 전에 실제 파일 버전·해시·의존성·품질 검사를 목록으로 고정한다.

| 공유 대상 | 확인한 소스 | 브레이커 적용 방식 |
|---|---|---|
| 캐릭터 정체성과 방향 원화 | `survivors-character-art.ts`, `survivors-directional-art.ts`, `graphics-v1/actors/` | 기존 인물/별칭 유지. 좌우 이동에는 동/서 원화를 우선 사용하고 현재 새 정지 캐릭터 후보는 대체 |
| 자연스러운 움직임 | `survivors-sprite-motion.ts`, `survivors-animation-rig.ts`, `survivors-foot-lock.ts`, `survivors-contact-mesh.ts` | 이동 거리 기반 보행 주기, 발 고정, 정지/회전 보정 재사용. 다리 길이 보정과 손·장비 보호 영역도 함께 가져옴 |
| 장비 장착 | `survivors-worn-equipment-plan.ts` 및 캐릭터별 보정 | 손·어깨 앵커 계약 공유. 새 장비의 형상/손 위치만 추가 보정 |
| 발사/타격 효과 | `survivors-cinematic-vfx.ts`, `survivors-authored-electrical.ts` | 기존 아틀라스·잔광·강도 곡선 활용. 브레이커의 무기 단계와 이벤트를 별도 변환 |
| 녹음 타격음 | `survivors-sfx-assets.ts`, `survivors-equipment-sound.ts` | 금속/콘크리트/피니시 등의 실제 음원을 이벤트별로 매핑 |
| 현장 장치 소리 | `survivors-pinball-audio-assets.ts` | 모터 시작/루프/정지, 컨베이어 충격, 고무/금속 접촉을 장치 상태에 연결 |
| 음악·믹싱 | `survivors-audio-manifest.ts`, `survivors-session-audio.ts` | 음악 버스, 효과/대사 덕킹, 음소거·세션 해제 구조 활용. 곡은 브레이커 장면별 큐 목록으로 지정 |

공유하는 것은 자산과 표시·음향 기능이다. WATCH 엔진, 피해 공식, 장비 성장, 보상, 저장 키, 전투 진행 상태를 공유하지 않는다. WATCH 이벤트를 위조해서 기존 효과를 호출하지 않고 `BreakerPresentationEvent`를 중립 표시 계약으로 변환한다.

예시 이벤트 필드: `type, sourceId, position, normal, outgoingVelocity, material, intensity, weaponStage, chainId, simulationTime`. 반사 방향/강도는 물리 엔진이 확정하며 렌더러가 난수로 바꾸지 않는다. 오디오·이미지 캐시는 공통으로 둘 수 있지만 발 접지 추적기, 효과 인스턴스와 재생 세션은 모드별로 분리한다. 종료·재시작 시 잔상, 발 고정 상태, 모터 루프, 음악을 해제한다.

워치는 주로 상부 시점이고 브레이커는 현장 단면이다. 방향 원화 사용 가능 여부를 먼저 화면에서 검수하고, 맞지 않는 손 각도나 장치만 보완한다. 화면상의 캐릭터 발 기준은 브레이커 지면으로 변환하되 원본 신체 비율을 바꾸지 않는다. 이동과 조준을 분리해 뒤를 조준한다고 다리가 늘어나거나 캐릭터 전체가 기울지 않게 한다.

## 3. 맵은 ‘작동하는 기계’로 만든다

모든 장치는 **대기→조작/예고→작동→접촉→정착/복귀** 상태를 갖는다. 색상 외에 형상·움직임·소리를 함께 사용한다. 배경 속 같은 형태의 장식물은 조작 윤곽이나 입력 표시를 붙이지 않는다.

| 장치 | 플레이 역할 | 실제 물리/조작 | 그래픽·사운드 피드백 |
|---|---|---|---|
| 접이식 방호판 | 다음 반사 경로 설계 | 제한된 각도 선택, 회전 중 충돌 형상도 일치 | 힌지 회전→잠금음→실제 접점의 방향성 스파크 |
| 고무 완충 범퍼 | 속도 완화·정밀 회수 | 반발계수와 감속 규칙, 접촉 연속 중복 방지 | 접촉 부위 압축/복귀, 저음 고무 타격 |
| 컨베이어 | 분열체 집결과 타이밍 | 정/역/정지, 접촉 구간에서만 운반력 적용 | 벨트·롤러 방향과 속도 일치, 모터 루프 |
| 전자석 | 금속 경로 굴절 | 범위/극성/출력 제한. 비금속에 동일 효과 금지 | 케이블 전원→코일 맥동→코어까지 연결된 힘의 흐름 |
| 집진·회수 게이트 | 연쇄 마무리 | 허용 재질/안정 상태/진입 방향을 명시 | 흡입 방향, 문 개폐, 회수 수와 동기화한 완료음 |
| 양중 장력선 | 가변 반사와 노출 창 | 매달린 길이·각도·주기, 이동 충돌선 동기화 | 로프 끝과 화물 연결, 모터·고정장치·장력 반응 |
| 센서 릴레이 | 회로 순서 퍼즐 | 접촉/스캔→연결 경로→상태 변경 | 노드에서 케이블을 따라 전원 전달, 목적 장치가 응답 |

장치 변화 중 피할 수 없는 즉사나 예고 없는 경로 변경은 만들지 않는다. 기본 클리어 경로를 확보하고, 더 긴 반사/위험한 각도는 선택적 고득점 경로로 둔다. 인접한 장치를 작동시킬 때 조준 입력이 가로채지지 않게 입력 우선순위를 고정한다.

### 배경 디테일의 세 층

1. **원경:** 공정별 구조물, 크레인, 도시 실루엣, 구름. 저대비와 느린 움직임으로 공간 깊이를 준다.
2. **현장층:** 실제 장치, 전원 케이블, 표시등, 벨트, 바닥 재질. 상태와 인과관계를 가장 선명하게 보여준다.
3. **전경:** 작업 발판, 접지 그림자, 국소 분진/수증기. 경고·코어·조준선을 가리지 않는다.

원화의 크레인/등을 움직이려면 베이스와 이동 부품을 레이어로 분리해야 한다. 정지 배경 전체를 흔들거나 확대해서 크레인이 작동한다고 표현하지 않는다. 먼저 반복 가능한 모터·벨트·팬·광원부터 구현하고, 움직이는 하중은 로프 앵커/추 길이/그림자를 함께 보정한다. 낮은 화질은 원경·입자·반사광만 줄인다. 장치 작동, 경고, 조준 경로는 유지한다.

## 4. 물리 고도화 명세

- 논리와 표시를 분리하고 고정 스텝을 유지한다. 프레임 사이 표시 보간은 충돌 판정을 바꾸지 않는다.
- 빠른 탄환은 이동 구간을 검사해 얇은 방호판·코어를 관통하는 터널링을 방지한다. 초기에는 탄환의 연속 충돌 검사를 우선 적용한다.
- 반사는 법선 방향과 진입 속도로 계산한다. 이동 장치는 장치와 코어의 상대 속도를 사용한다. 반발계수/마찰/회전 반응은 재질 데이터로 관리한다.
- 같은 접촉 상태의 매 프레임 타격음·점수·파편 생성 금지. 접촉 진입과 충분한 재접촉 조건을 정의한다.
- 분열은 질량/회수 단위 보존, 생성 위치 겹침 해소, 속도 상한을 유지한다. 개체 상한으로 빠진 분열체는 점수나 남은 목표를 소실시키지 않는다.
- 자력은 범위 밖에서 작용하지 않고 힘/속도 상한을 둔다. 무한 가속, 벽 고착, 끝없는 공전에는 회수 가능성을 유지하는 탈출 규칙을 둔다.
- 예측선과 실제 탄환은 같은 충돌 함수를 사용한다. 이동 표적/변경 중 장치는 불확실한 구간을 표시하고 보장 명중처럼 안내하지 않는다.
- 충격 정지는 장면별 짧은 선택적 연출로 검토한다. 구현 시 입력을 버리지 않고 엔진/보간/음향 시계를 일관되게 정지한다. 이번에 구현된 기능은 아니다.

## 5. 무기 6종: 공격력보다 물리 동사

| 장비 | 기본 조작/역할 | 장치와의 조합 | 한계와 판독성 |
|---|---|---|---|
| PULSE | 충격·밀기·분리 | 방호판 반사→코어 분리→컨베이어 집결 | 혼자 모든 재질을 즉시 해소하지 않음. 탄두·방향성 충격·금속 파편 |
| NET | 범위 포획/큰 코어 안정화 | 완충/자력으로 모은 분열체 회수 | 큰 불안정 코어는 첫 접촉에 안정화. 망 전개→조임→흡수 |
| MAGNET | 금속 궤도 굴절/극성 전환 | 전자석과 방호판으로 회수 방향 설계 | 대상·범위·지속 제한. 전기 공격으로 오인하지 않는 곡선 유도 표시 |
| MIST | 분진·열 상태 안정화 | 집진 게이트 허용 상태로 전환 | 안정화에 체류 시간 필요. 효과 영역 밖에는 영향 없음 |
| ANCHOR | 장력/이동 경로 고정·해제 | 흔들리는 장력선의 노출 창 확보 | 앵커 수·연결 길이 제한. 연결점과 선을 선명하게 유지 |
| SCAN | 약점·회로·노출 타이밍 읽기 | 센서 릴레이와 보스 공략 지원 | 자동 승리/자동 조준 아님. 스캔 결과와 실제 공격 기회를 구분 |

처음에는 2슬롯만 운영한다. 장비 선택 화면에 ‘무엇을 하는가 / 어느 코어·장치와 맞는가 / 무엇은 못 하는가’를 한 줄씩 표시한다. 성장 1단계는 명확한 기본 동사, 2단계는 범위/지속/분기 중 선택, 3단계는 장치 연계 피니시로 설계한다. 첫 단계부터 최대 화려함을 적용하지 않고 강도를 구분한다. 유료 외형이나 캐릭터가 필수 공략 장비를 독점하지 않는다.

### 효과의 시간 순서

손/장비 준비→총구 발사→비행→접촉점 반응→재질 변화→장치 반응→회수로 이어진다. 같은 프레임에 전부 번쩍이면 인과가 읽히지 않는다. 기존 워치 아틀라스의 준비/비행/타격 셀을 활용하고, 전기는 방출 방향·표면 방전·잔광을 단계적으로 보여준다. NET·MIST·ANCHOR의 고유 상태 표현만 필요한 부분을 제작한다.

## 6. 캐릭터·음향 연출 운영

캐릭터 선택은 기존 이름·별칭·성격·장비 장착 보정을 유지한다. 초기에는 외형/무전/동작 개성부터 공유하고 캐릭터별 신규 능력치 차이는 별도 밸런스 검증 후 추가한다. 정지→가속→걷기→감속→정지, 이동 중 조준/발사, 방향 전환, 충격 반응을 한 캐릭터에서 검수한 뒤 전체 인물로 확장한다.

음향 우선순위는 **위험 예고/접촉 확인→장비/회수→장치→음악→배경 환경음**으로 한다. 소리가 위험 위치를 돕되 청각 정보만으로 필수 공략을 전달하지 않는다.

| 상황 | 음악/환경 | 효과음 운영 |
|---|---|---|
| 작전 준비 | 기존 곡의 낮은 밀도 구간 | 장비 확인·짧은 무전 |
| 정상 플레이 | 일정한 리듬, 현장 앰비언스 | 소재 접촉 변주, 같은 음원의 연속 반복 제한 |
| 연쇄 상승 | 가용 스템이 있으면 층 추가, 없으면 검증한 전환 큐 | 반사→분리→포획 순서를 음 높이/질감으로 구분 |
| 보스 노출 | 긴장 큐→노출 순간 짧은 강조 | 경고가 음악에 묻히지 않게 덕킹 |
| 회수 피니시 | 짧은 성공 큐→환경 안정 | 점수 확정과 동시에 보상음, 연습에서는 보상 지급 없음 |
| 정지/탭 전환 | 정지 정책에 따라 음악·루프 제어 | 효과 꼬리 정리, 재개 때 모터 루프 중복 금지 |

보유 음악이 단일 믹스라면 악기 스템 분리가 되어 있다고 가정하지 않는다. 원곡을 확인하고 루프 경계·크로스페이드·덕킹으로 활용한다. 현장 모터 루프는 실제 장치 가동 동안만 재생하며 별도 오디오 세션에서 발음 상한과 정리 규칙을 적용한다.

## 7. UI·UX 명세

**준비 화면:** 캐릭터, 장비 2슬롯, 스테이지의 핵심 장치와 목표, 자유 실험/작전 시작을 명확히 배치한다. 미구현 기능은 작동 버튼처럼 노출하지 않는다. 장비 미리보기는 실제 장착 위치와 게임 효과를 연결한다.

**전투 화면:** 상단은 목표/회수/생명/정지, 경기장은 플레이만, 하단은 이동·장비·시설·발사. 진행 안내는 경기장 밖에 둔다. 중요 이벤트 때문에 조준·경고·접촉점을 중앙 팝업으로 가리지 않는다. 설명/장비 교체/결과 화면을 열면 진행을 정지하고 명시적으로 재개한다.

**PC:** A/D 이동, 마우스 조준, 클릭/Space 발사, 1/2 장비, Q/E 시설. 키 변경과 도움말은 준비/정지 화면에서 같은 설정 계약을 사용한다. 현재 시험판은 키 변경 기능 미구현이다.

**모바일:** 드래그 후 손을 떼어 발사하는 현재 조작을 기본으로 유지한다. 이동 손과 조준 손의 포인터를 분리하고 취소/탭 전환은 미발사 처리한다. 시설 버튼은 큰 터치 대상으로 제공하며 장치 자체의 작은 부분을 정밀 탭하도록 강요하지 않는다. 가로형을 기본으로 두고 세로형에서도 전체 아레나를 보존한다. 드래그 발사/별도 발사 버튼 선택지는 조작 실험 후 결정한다.

**초보자 학습:** 팝업 읽기보다 첫 펄스 분리→반사판 변화→포획 회수의 직접 체험. 실패 시 ‘큰 코어라 안정화 먼저’, ‘게이트 진입 조건 미충족’, ‘방호판에 궤도 변경’처럼 원인만 짧게 안내한다. 무기·코어·시설의 상태를 동일한 용어와 아이콘으로 연결한다.

**설정:** 준비와 정지에서 동일 화면. ‘선명하게 / 균형(추천) / 부드럽게’에 효과 차이를 짧게 설명한다. 음악/효과/무전 볼륨, 화면 흔들림 감소, 조준 도움을 분리한다. 자동 품질 조절을 넣으면 실제 성능 지표를 사용하고 ‘추천’만으로 측정 완료처럼 표현하지 않는다.

**결과:** 클리어 보상과 선택적 연쇄 성과를 구분한다. 회수량, 장비 조합, 대표 반사 경로, 다음 현장 장치를 보여주고 재도전/다음 작전을 같은 위치에 둔다. 경로 리플레이는 메타 보상과 분리한다. LAB에는 크레딧 수익이 없음을 진입 전에 안내한다.

## 8. 첫 챕터의 장치 차별화

| 정식 스테이지 제안 | 핵심 장치/공략 | 다음 판을 기대하게 하는 변화 |
|---|---|---|
| 01 첫 반사 | 고정 방호판·완충 범퍼, PULSE→NET | 직접 반사 경로를 만들었다는 경험 |
| 02 이동 반입 | 컨베이어 정/역/정지, 분열체를 같은 구간에 집결 | 타격만이 아니라 운반 흐름 설계 |
| 03 집진 통로 | 분진 안정화와 회수 게이트 허용 조건 | 장비의 사용 순서가 공략이 됨 |
| 04 장력 릴레이 | 흔들리는 선, 고정 창, 전원 전달 | 경로와 타이밍의 결합 |
| 05 보스: 반입동선 혼선 | 방호판·벨트·게이트 순차 제어 | 시설 전체가 반응하는 연쇄 피니시 |

현재 SB-04 시험 보스와 위 정식 04/05를 같은 콘텐츠로 표시하지 않는다. 정식 전환 때 스테이지 ID와 저장 이관 규칙을 먼저 정한다. 원화 색만 바꾸는 확장 대신 장치 역할과 실패/회복 방법이 달라져야 한다.

## 9. 구현 순서와 완료 판정

1. **공유 기반 고정:** 최신 로컬 자산 목록/버전, 캐릭터·VFX·오디오 의존성 분리, TypeScript 표시 계약과 브레이커 엔진 분리. 본편 수정사항을 덮어쓰지 않음.
2. **SB-01 통합:** 기존 캐릭터 한 명의 좌우 보행/정지/조준/발사, 기존 녹음 타격음과 음악, 방호판·완충대 원화 상태 연결. 새로운 전신 원화부터 다시 제작하지 않음.
3. **장치 물리:** 연속 충돌 검사, 소재 반사, 컨베이어/전자석 상태, 이벤트 중복 방지. 각 장치 단독 검사 뒤 조합 검사.
4. **UI·UX:** 준비·정지 공통 설정, 장비 역할/시너지 안내, 모바일 동시 조작, 실패 원인 피드백과 결과 흐름.
5. **첫 챕터:** 5개 고유 공략과 보스. 신규 무기/장치는 필요한 판과 함께 단계적으로 추가.
6. **확장/통합:** 실제 플레이와 성능을 검수한 뒤 캠페인 확대, 별도 저장 계약, 허브 연결과 배포 검수.

완료 기준: 캐릭터별 발 접지/회전/장비 앵커 일치, 빠른 탄환 누락 없음, 같은 접촉의 중복 보상 없음, 맵 장치의 시각·물리·음향 상태 일치, 저화질에서도 필수 정보 보존, 정지/재개/탭 전환 시 루프 중복 없음, PC·태블릿·모바일 여섯 뷰포트 조작 검증, 실제 모바일 기기 성능·발열 확인. 첫 15초 성공률과 스테이지별 플레이 시간은 사용자 플레이로 측정하며 목표를 완료 수치로 적지 않는다.

이번 문서는 기존 WATCH 품질 자산을 공유한다는 사용자의 방향을 반영한 후속 제작 기준이다. 실제 공유 적용과 장치 고도화는 다음 구현 작업으로 진행한다.
