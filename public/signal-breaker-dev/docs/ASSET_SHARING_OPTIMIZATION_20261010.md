# 공통 자산 공유와 로딩 최적화

## 적용한 구조

- 공통 원본은 `public/assets/`에 한 벌만 둔다. 브레이커 폴더에 WATCH 효과 아틀라스를 복사하지 않는다.
- 로컬 시험 서버가 `/assets/`를 같은 저장소의 공통 자산 폴더로 연결한다. 저장소 밖 경로 접근은 차단한다.
- `public/assets/shared/presentation-cache-v1.js`는 URL을 정규화해 같은 이미지 객체를 반환한다. 브레이커의 기존 이미지 3종도 이 캐시를 사용한다. 자산 오류 시 캐시 항목을 제거해 다음 요청으로 재시도할 수 있다.
- WATCH의 `cinematic-vfx-v3.png`를 실제 브레이커 타격/분리/포획 효과에 연결했다. 첫 효과가 발생할 때만 요청하고 새 인스턴스/이벤트에서도 같은 객체를 사용한다.
- 캐릭터 전체, 모든 음악, 모든 스테이지 원화를 시작 화면에서 한꺼번에 불러오지 않는다. 현재 실제 연결은 이미지 캐시와 공통 VFX이며, 캐릭터 동작/녹음 음향의 공통 어댑터 연결은 후속 구현이다.

## 전체 공유 구현 기준

공유는 ‘모든 파일을 미리 로딩’한다는 뜻이 아니다. 선택 캐릭터+현재 장비 2종+현재 맵+현재 음악만 먼저 준비하고 다음 스테이지는 여유 시간에 제한적으로 준비한다. 모드 코드도 진입 시 로딩한다. 공통 원본과 자산 해시를 기준으로 배포 파일 중복을 검사한다.

이미지 원본 공유와 GPU/디코딩 메모리 공유를 구분한다. 이번 이미지 캐시는 같은 페이지 안에서 적용된다. 별도 브라우저 탭은 각자의 디코딩 메모리를 사용한다. 최종 허브 안에서 공통 캐시를 연결해야 모드 전환에서도 객체 공유가 유지된다. WATCH의 기존 로더는 아직 이 새 캐시로 이관하지 않았다.

오디오는 URL별 로딩 Promise/디코딩 결과를 공유하되, 재생 노드와 모터 루프·음악 세션은 모드별로 관리한다. 전환 시 사용하지 않는 루프/효과를 정리하고 오디오 컨텍스트별 디코딩 계약을 확인한다. 모든 곡을 동시에 디코딩하지 않는다.

사용 종료 시 캐릭터/배경/VFX 소유 참조를 해제하고, 메모리 예산에 따라 사용하지 않는 항목을 제거한다. 현재 `evict()`는 캐시 참조 제거이며, 다른 렌더러가 보유한 이미지까지 강제로 해제하는 기능은 아니다. 자동 LRU/메모리 측정은 후속 구현이다.

장치 물리·경고·조준·포획 판정은 화질과 무관하게 유지한다. 최적화 대상은 배경 장식, 입자 수, 잔광/광원, 반복 할당, 오디오 중복 발음이다. 캐릭터와 효과는 매 프레임 새 이미지/캔버스를 만들지 않는 구조로 연결한다.

## 검증과 수치 해석

독립 검사 10개, 타입 검사, Vite 빌드 통과. 공통 경로 접근/탈출 차단, 동일 URL 중복 생성 방지, 실패 후 재요청을 검사했다. 실제 Chrome에서 준비 화면의 공통 효과 아틀라스 요청 0회→첫 PULSE 타격 후 1회, 캐시 4개 이미지와 실제 명중을 확인했다.

공통 아틀라스는 2,033,237바이트이며 브레이커 전용 복사본을 추가하지 않았다. 기존 시험판에 없던 고품질 효과가 추가되어 첫 타격 이후 다운로드는 늘어난다. 총 용량이나 FPS가 이미 감소했다고 주장하지 않는다. 오프라인 캐시의 공통 경로를 허용했지만 HTTPS/실제 오프라인 전환은 별도 검증이 필요하다.

완료 판정은 초기 요청 바이트, 모드별 추가 요청 바이트, 디코딩 메모리, 반복 진입 뒤 잔존 객체/오디오 루프, 물리 프레임 비용을 전후 비교하는 것이다. 실제 모바일 장시간 테스트와 전체 자산 로더 통합이 끝나기 전에는 전체 최적화 완료로 표시하지 않는다.
